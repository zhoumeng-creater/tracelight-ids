# 第十一轮零拟合诊断：成本与检测收益复核

复算脚本与原始工件位于本地工作目录 `UNSW零拟合诊断分析_20261106`；本目录保存报告和复算数值。

日期：2026-11-06。本报告只重算已回传的原始时长、RSS 和历史 R/C 检测工件；没有新增计时、模型查询或拟合。复算脚本为 `analyze_costs.py`，完整数值为 `cost_reanalysis.json`。

## 判断

本轮成本部分完整，冻结输入与执行顺序正确，重算结果和回传摘要一致。H40 的速度和模型包优势确实存在；**当前 Python/PyTorch 运行方式下，它没有完整进程内存优势**。

用户没有体积、内存或时延硬上限，因此不能只因 H40 包更小就继续以压缩为默认主线。HGB 相对 H40 在已开发 C 上多检出 488 条、少 2 条误报，单条 p95 多 0.815 ms，现有进程 RSS 反而更低；这是值得优先保留的实际方案。H40 的速度优势为继续研究轻量学生提供了一项真实依据，但不能单凭成本结果决定新增训练，更不能宣称本轮 KD 已成功。

## 1. 原始记录与预算

独立读取 `timings.jsonl`、`warmup.jsonl`、三个 RSS JSON、RSS 输入 parquet，逐条复算并核验：

| 项目 | 原始记录 | 输入行数 |
|---|---:|---:|
| 正式计时 | 450 | 57,825 |
| 预热 | 30 | 3,855 |
| 独立 RSS 探针 | 3 个独立 PID，各 1 次前向 | 768 |
| 合计 | **483 次调用** | **62,448** |

全部计时和预热记录为 complete。三个 RSS 子进程的 stderr 均为空。每种 batch 尺寸均为 75 组输入，每组恰有 H40/HGB/CatBoost_reference 三个模型，组号、块号、块内重复号和执行位置一致。

输入 ID 与第十轮 `summary.cost.timing.batches` 逐组完全相同。执行顺序按冻结的 NumPy `SeedSequence([20261105, 3])` 逐组重建，与全部 150 组原始记录一致。预热恰为每模型每尺寸 5 次，使用该尺寸的第一组输入；三个 RSS 探针也使用同一份第一组 256 行输入。

对所有 pooled 与三块 p50、p95、均值和吞吐逐项重算，最大绝对差为 **0**。本次未追加、删除或挑选计时块。

## 2. 同口径速度

设备：Windows 10，Intel64 Family 6 Model 183 Stepping 1，24 物理 / 32 逻辑核心，固定 4 线程。三种流程均包含内存中已有字段、预处理或原生类型转换、CPU 模型和冻结阈值判定；不含磁盘 CSV 读取、抓包或原始流字段提取。

| 模型 | 单条 p50 ms | 单条 p95 ms | 单条均值 ms | batch256 p95 ms | batch256 吞吐 行/秒 |
|---|---:|---:|---:|---:|---:|
| H40 | 2.23310 | **2.39274** | 2.249159 | **3.08600** | **91,758** |
| HGB | 3.04340 | 3.20741 | 3.066740 | 4.88469 | 57,948 |
| CatBoost-reference | 5.04130 | 5.32301 | 5.076244 | 5.80732 | 45,882 |

H40 相对 HGB 的单条 p95 低 **25.40%**，batch256 p95 低 **36.82%**，批吞吐高 **58.34%**。这不是单个有利样本造成：两个尺寸各 75 组配对中，H40 都比 HGB 更快，HGB 都比 CatBoost 更快。

| 模型 | 单条三块 p95 ms | batch256 三块 p95 ms |
|---|---|---|
| H40 | 2.36514 / 2.50306 / 2.31706 | 3.04466 / 2.99518 / 3.08850 |
| HGB | 3.19618 / 3.19312 / 3.20370 | 4.57702 / 5.08490 / 4.77510 |
| CatBoost-reference | 5.24138 / 5.38406 / 5.16880 | 5.81152 / 5.99156 / 5.77604 |

HGB−H40 的配对时长差中位数为单条 **0.8132 ms**、batch256 **1.6136 ms**；pooled p95 之差分别为 0.81467 / 1.79869 ms。配对差的中位数与两个模型 p95 之差是不同统计量，不能混用。

完整结果同时保留三种执行位置的统计与六种顺序的计数。三块均支持相同的速度次序，没有依据删去 HGB 的第二块较高 batch256 p95。以上是冻结 C 输入、固定实验流程的时长分布，不是线上请求、并发队列或原始抓包系统的 p95。

本轮跨函数类比较没有 1.25 倍硬门槛。HGB/H40 单条 p95 比为 1.3405，不能套用原 K/H 的旧 1.25 条件判 HGB 不合格；本轮也没有重测 K，因此不能改写第十轮 K 的成本失败。

## 3. 模型包与实际内存不能等同

| 模型 | 完整模型包 B | 导入后 RSS MiB | 输入加载后 MiB | 模型加载后 MiB | 一次256行前向后 MiB |
|---|---:|---:|---:|---:|---:|
| H40 | **34,549** | 502.230 | 514.887 | 516.000 | **518.992** |
| HGB | 1,509,420 | 139.660 | 149.965 | 152.246 | **153.629** |
| CatBoost-reference | 312,279 | 146.742 | 157.113 | 159.418 | **161.520** |

HGB 模型包为 H40 的 43.69 倍，但在本轮独立 Python 进程中，H40 前向后的 RSS 约为 HGB 的 3.38 倍。H40 的大部分差异在导入阶段已经出现；实验室使用的是 PyTorch 2.6.0+cu126，即使本次前向在 CPU 上执行，仍有这套后端的导入与运行时成本。

扣除输入加载后的基线，模型加载加一次前向的 RSS 增量分别为 H40 **4.105 MiB**、HGB **3.664 MiB**、CatBoost **4.406 MiB**。单看模型加载增量，H40 为 1.113 MiB，低于 HGB 的 2.281 MiB；这不能抵消当前完整进程的较高开销。

这些记录是三个独立进程的驻留内存快照，不是峰值 RSS、长期服务稳态或优化后的推理引擎结果。没有测量 ONNX、纯 CPU torch wheel 或共用运行时，不能把这些潜在替代当成已获得的内存收益。加载时间分别为 2.297 / 11.9265 / 3.0275 ms，每模型只测一次，不对启动时延稳定性作推断。

## 4. 把成本与已有检测结果放在一起

下表检测值来自已封存的第八/十轮 R/C 缓存统一复核，本轮没有新增性能评估或阈值选择。R/C 已用于开发，不是新的独立测试集。

| 模型 | C TP / FP | C 标准化 pAUC | R TP / FP | R 标准化 pAUC |
|---|---:|---:|---:|---:|
| H40 | 13,960 / 78 | 0.889540 | 7,032 / 39 | 0.887778 |
| HGB | **14,448 / 76** | **0.911837** | 7,245 / **28** | **0.914522** |
| CatBoost-reference | 14,439 / **75** | 0.908642 | **7,285** / 39 | 0.913401 |

HGB 相对 H40：C 净增 488 TP，TPR 提高 2.92093 个百分点，FN 从 2,747 降至 2,259，减少 **17.76%**，同时 FP 少 2。R 净增 213 TP、FP 少 11。这份检测收益伴随约 0.815 ms 单条 p95 增量和约 1.799 ms 的 batch256 p95 增量；没有硬性资源上限时，它是合理的优先实际参照。

必须保留错误交换：HGB 的 C 检出变化包含救回 733 条、反向漏掉 245 条；R Analysis 从 H40 的 116 TP 降为 112 TP，即净少 4。C Analysis 为 230 vs 229，净增 1。HGB 不是对 H40 的逐样本或逐族无损替换。

CatBoost 相对 H40 的 C 净增 479 TP，FP 少 3；R 净增 253 TP。其 R/C Analysis 分别少 3 / 4 TP。相对 HGB，CatBoost 的包体积约小 79.31%，R 多检出 40 条、C 少 1 FP；HGB 则 C 多检出 9 条、R 少 11 FP，两种尺寸推理更快且当前 RSS 更低。二者各有取舍，不能仅凭 C 净 TP 宣布全维度支配。

## 5. 是否值得继续训练学生

成本结果满足了“学生可能具有实际价值”中的速度证据：其较小包和稳定速度优势真实存在。但当前无硬性部署预算，完整进程内存也不占优，尚不能证明为这种优势继续牺牲 488 条 C 检出是值得的。继续研究学生应回答如何缩小检测差距，而不能再以 35 KB 本身作为成功标准。

如果 F 诊断另行支持训练目标未充分承接，冻结的 **H/K 两臂 mini-batch 优化方案对照**有机制研究依据；本成本报告不授权、不启动该分支。其作用是区分优化方案与 KD 的交互，不能仅靠两臂训练判断容量上限或证明新的实例知识机制。

后续实际方案比较以 HGB 和 CatBoost 为强参照，保留 H40 的速度与逐族比较。旧四臂失败不改判，也不依据本次某块计时重新定义成功门槛。
