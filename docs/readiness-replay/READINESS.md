# 本地阈值就绪修复

第二十五轮 DEDALE 各日首小时只有 1 或 2 条记录。旧实现将“一小时已过且前缀非空”视为就绪，但有限样本序位超出前缀长度时返回 `null`，判决器解释为永不告警。本模块修复就绪状态；保留旧记录、时钟、模型分数与预算定义。

`repair_decisions(features, scores, old_decisions, old_registration)` 为纯函数，返回新判决 DataFrame 和登记字典。输入使用旧 R25 的逐行特征、三视图连续分数、18 种封存判决及每组阈值报告；不读取真值，不加载模型，不修改输入对象。三个表均要求 `row_id=1..n`；特征和判决时钟必须为相同的非递减整数毫秒，分数有限。

## 统一就绪条件

每个来源块保留原起点和一小时边界。所有七类本地组合共用一次切换与一个参考前缀，满足：

1. 从该块首条记录起至少经过一小时。
2. 严格早于切换时钟的已观测记录至少 399 条。

原首小时若已有至少 399 条，且已经观察到一小时边界以后的记录，直接保留旧的 `first + 3600000` 边界；即使没有记录恰好落在这个毫秒，也不将边界挪到下一条记录。这样已有足够参考的来源保持旧相位和阈值。

原首小时不足时，寻找第一个有至少 399 条严格先前记录的逻辑时钟组；整组同钟行都不进入参考。若第 399 条与后续多条同钟，必须等到下一时钟组。到文件结束仍不满足时，状态为 `not_ready`，`cutoff_ms=null`，全块使用预先登记的旧正常 C 分量规则，所有行保持 `startup`。

最少条数由固定预算推导，不从标签或检出效果选取。使用原序位 $\lceil(n+1)(1-\alpha)\rceil$，预算为 1%、0.5%、1/300、0.25% 的分量，有限阈值分别至少需要 99、199、299、399 条。七类组合最多四个分量，因此统一最低值为 399。预算分摊沿用 `Fraction`，告警仍为严格 `>`，并列分数不可拆。

399 只使最细预算的序位落在已观察样本内，不证明前缀有代表性，也不保证后续正常误报低于 1%。前缀全并列但得到有限阈值时仍为就绪；其后零告警是判决结果，不能再解释为样本不足。

## 保留和重算的列

输出保留旧的 18 个策略列及原列顺序。四个冻结模型告警、四个旧计数／组合告警、扫描代理逐位复制。七个 `*_local` 在就绪前使用旧报告中的 `registration[name].old`，就绪后使用共同前缀登记的新规则；两个 `frozen_plus_*` 按复制的 `add_quality_old` 与修复后的计数告警重新取并集。`phase` 改为修复后的 `startup/after`。

就绪报告保留旧的一小时边界、共同切换边界、实际参考条数、首小时内启动行、首小时后等待就绪行、同钟阻塞组大小及每项阈值状态。未就绪时 `prefix_rows=0` 表示没有冻结本地前缀，并非没观察到流量；`rows`、`first_hour_rows` 与 `rows_strictly_before_last_clock` 分别保存相应数量。旧后备阈值如有 `null`，明确记录为 `insufficient_reference_rows`，不会因此触发本地切换。

修复回放使用已打开的 R25 数据，属于开发证据。后续评价应分别保留全日、修复启动期和切换后结果；启动期误报和漏检不会因等待延长而删除。

## 验证范围

合成检查覆盖首小时 1/2 条的退化、398/399 边界、整组同钟排除、未来分数不改变参考阈值、整块未就绪后备、原首小时足够时逐位复现，以及全并列有限阈值。旧 R25 `decide` 直接生成比较工件；这里没有真实模型拟合或推理。
