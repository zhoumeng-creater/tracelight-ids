# IoT-23 39-1 独立确认资格决定

核查日期：2026-11-18。仅检查作者元数据、公开标签表、标注源码及项目现有分配；未下载 PCAP 或完整流日志，未调用模型。

**决定：39-1 不进入当前路线的核心独立确认批次。它可保留为未评分历史采集上的标签迁移辅助案例，不能承担“在可比正常业务中识别恶意控制”的独立效果证明。本轮不切换其他来源，也不为此安排模型评分。**

## 标签已核清，主要障碍不是缺少模型运行

作者主页链接的公开标签表中，`CTU-IoT-Malware-Capture-39-1 Labels` 是 `gid=0`。本轮通过 Google Sheets 连接器读取 `A1:H15`，有效数据为表头及以下五行条件：

| 目标标签 | 作者规则 |
|---|---|
| C&C | `id.resp_p == 6667`，独立条件 |
| PartOfAHorizontalPortScan | `conn_state == S0` 与 `id.resp_p == 22` 联合成立 |
| Attack | `conn_state == SF` 与 `id.resp_p == 22` 联合成立 |

C&C 规则不含字节量、已执行命令或恶意负载条件。按该规则，目的端口为 6667 的流都会被标为 C&C；因此原生标签不能提供这一目的端口上的正常反例。这是从规则推出的结论，尚未声称已逐行验证最终日志。即使模型移除端口输入，流量形态仍可能体现服务差异；移除端口不能使标签自动变成独立的恶意性证据。[作者标签表](https://docs.google.com/spreadsheets/d/1HRqgKJp0XoSUIfW3rCQKoD_LnSCJ1k-k61PndJXWq_o/edit#gid=0)

作者 `Flaber` 源码逐字段执行 `eq/gt/lt` 条件及连接规则；未匹配流的内部标签设为 `-`。当前归档仓库的 `main` 提交为 `d856ba86b3e0fd7293c04a9bafd701222b2d7e61`，`flaber.py` blob 为 `cb5636f81b04f324fad3a9714b9ec5c03369ecf7`。该快照晚于数据集首发，支持解释当前公开规则的执行语义，不能代替当年最终标注工件与运行收据。[作者标注代码](https://github.com/stratosphereips/flaber/blob/d856ba86b3e0fd7293c04a9bafd701222b2d7e61/flaber.py)

作者公布的39-1标签计数为：正常7,337、C&C 1,530、Attack 677、扫描73,559,437；没有下载标签。正常总数足以提供一个全采集经验FPR分母，但不能证明有正常IRC、远程管理或与C&C相似的长连接业务。1,530条控制流也不等于1,530个独立攻击事件。[作者来源与标签计数](https://www.stratosphereips.org/datasets-iot23)

## 需要什么原件才可能改变本决定

1. **决定性缺口：** 与6667/IRC控制有业务可比性的正常流及独立正常证据，以及不单靠端口规则判定的恶意控制证据。可包括作者的逐连接负载分析或控制动作对应。只取得更多原生规则标签不会补上这一项。
2. **输入与分母原件：** 最终 `conn.log.labeled` 的表头、完整正常行和控制行、标签生成版本/收据，以及相应字段单位、方向、缺失与导出时刻说明。当前未逐行验证7,337条正常分母，未确认与本项目完整流输入的一致性。
3. **独立性原件：** 作者事件/恶意二进制清单与训练材料的对应、原始流身份和真实时间范围。它们决定能主张跨采集、跨实现还是时间前向；不能由连接数或采集编号代替。
