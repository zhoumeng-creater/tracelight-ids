## 提取障碍怎样解决

下载载荷没有恢复。三条 russell 下载在另一捕获点也保存着相同的缺失区间，继续寻找该捕获的完整 payload 已没有依据。但这次八字段使用包头统计，并不要求恢复文件内容。

已验证并应用 `declared-ip-truncation-v1`：对完整有效 IPv4 头、无分片且支持的传输头完整的记录，仅把派生 PCAP 的 `orig_len` 提高到声明 IP 长度所需值；时间、`caplen` 和所有捕获字节不变。五份完整捕获均按相同规则处理，再由固定 Zeek 8.0.11 `-C` 提取。共 5,698,480 条包记录，184,412 条改变长度元数据，得到 109,512 条连接。数值含义是捕获记录数和声明 IP 数据报字节，不是重新测得的物理链路包数或载荷完整性。[提取合同](ait_extracted/EXTRACTION_CONTRACT.md) · [原始三条下载的验证](ait_recovery/README.md)

原始 PCAP、旧统一表和旧失败判定保留。当前消费表使用一套有效连接身份；C 的旧/新 UID 有显式别名，不把两个版本重复计作样本。
