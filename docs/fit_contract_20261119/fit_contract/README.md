## 新测量合同：声明 IP 长度的截断记录

采用 `declared-ip-truncation-v1`。通用规则检查完整且 checksum 有效的 IPv4 头、无 IP 分片，以及完整的 TCP、UDP 或受支持 ICMP 头；当 `orig_len < L2偏移 + IPv4 total_length` 时，只提高派生 PCAP 记录的 orig_len。时间、caplen 和捕获字节不变。全部捕获记录均执行相同检查，不读取标签或动作筛选记录，不逐流要求 TCP 序列号或 ACK 证明。

此前针对 russellmitchell 3 个下载 TCP 的独立验证具有序列号、ACK/FIN 证据，并改变了 28,115 条下载包记录的 orig_len。3 个下载 TCP 的捕获记录数和声明 IP 字节累计全部进入 Zeek；32 个控制候选及 38 个 cloud 候选的 raw8 不变。原 PCAP 与旧完整 raw8 表保留。[实际验证](<E:/OneDrive - Coventry University/中传/毕业论文/工作/拟合来源与划分落实_20261119/ait_recovery/declared_length_representation/validation.json>)。

包数表示捕获记录数，IP 字节表示这些记录的 IPv4 声明长度累计；聚合/卸载可能改变它们与物理线上包数、字节的对应。缺失 payload 未恢复，不声称完整文件或完整线上传输。通用规范化已覆盖五件完整捕获：santos intranet/cloud 为 14,538/17,562 条连接，fox 为 21,514/33,973 条，russellmitchell cloud 为 21,925 条，共 109,512 条连接。上述 3 个下载的序列证据属于专项验证，不能推广为全背景逐流均有此证明。详细判断见 `observed_flow_admission.md`。

raw8 固定顺序：`ip_protocol, orig_port, resp_port, duration_seconds, orig_pkts, resp_pkts, orig_ip_bytes, resp_ip_bytes`。数值统一 `log1p`，真实缺失保留为 NaN，交给 HGB 原生缺失处理；不以文件大小、主机动作或成功回执补特征。

## 流标签与动作评价

普通 HGB 只拟合有确定二分类标签的网络记录。正例须关联确定的恶意控制/攻击下载活动；一流同时含正常事务不自动取消“含恶意活动”标签。正常 B 级可以包含多个正常对象，前提是完整连接内所有可能业务均有正常依据。一个正常对象不能使未知的其余事务自动变正常。

同一物理流的多个命令、文件对象、代理两腿和传感器副本不重复计作独立训练流。未标注背景仍进入上下文，不能把它填为正常。F/V 各自保留同场正常浏览和正常下载，避免一个来源全攻击、另一来源全正常；记录体量和捕获质量与类别的关系，不把提取瑕疵解释成可迁移行为。

模型按网络侧固定流与时钟评分后，才连接到动作真值。主机动作窗口不裁剪模型输入。若一个动作只有一个真实连接，候选集合完整而身份未知，确定/可能检出为 `[min(alert), max(alert)]`；候选覆盖未经证实则记未解析。确实跨多个已证连接的动作按告警并集计一次。正常 FPR 只用合格正常模型记录，动作受影响率另报。

当前任务需要 F 中有控制与下载两类真实监督。没有下载正例可以训练控制检测器，但不能作为本次代表性监督后的控制/下载比较。动作有多义性时，不把所有候选都造为正例。

## 25 条 C 的核阅与固定工作点

校准脚本使用每个物理 TCP 的完整首末包时间包络，边界向整秒扩展，保留所有代理请求候选；backend/proxy 按方法、解码路径、查询、HTTP 版本及状态核对。全包络只要出现其他或 VPN actor 就排除，因此 38 个候选中保留 25，13 个排除。其余业务均来自已证正常内部员工。独立核阅记录见 `calibration_review.md`。

其中 TCP17775 有 86 条代理请求、85 条后台请求，多出的一个是已知正常员工的 `GET /`、302。这里证明的是请求身份候选覆盖及所有 actor 正常，不是逐事务一一配对。该差异不改变 B 级正常判断。

**C 的 1% 预算取整为 0 个误报。每臂阈值固定为该已冻结模型的 25 个 C 正常分数最大值，告警规则为 `score > threshold`，相等判正常。** 这只是经验校准规则，没有 95% 人口误报保证；C 是有关联且经过业务资格筛选的 ownCloud 子集。不能用 C 选模型或调容量，也不能把此子集写成全网正常分母。

## 唯一时钟合同

AIT 主比较使用完整背景 Zeek 导出时记录的 `replay_export_time`，即离线回放的导出 network_time。它比用流末时刻代替导出时刻更直接，但仍不是实际检测器接收时间；EOF/shutdown 标记保留，不倒填更早可用时刻。两臂共用这一时钟。

OpTC 外源只有 `offline_flow_end_replay`，明确保留不同模式，不据此声称在线早检，也不为了列名一致丢弃 AIT 已记录的导出时间。不另开时间窗或时钟矩阵。

santos 攻击早于 fox，保持拟合→开发验证的日期顺序。C 在 01-21/24，晚于 V，故用 C 阈值回算 fox 是开发回测。AIT2022 到 OpTC2019 仅作跨源历史开发回测。真正校准后新时段的结论，需要日期晚于 C、阈值已经冻结的材料支持。
