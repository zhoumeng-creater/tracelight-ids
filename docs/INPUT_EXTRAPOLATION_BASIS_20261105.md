# 输入范围外推：修改依据与可推翻的解释

2026-11-05。状态：冻结工件机制分析、零拟合诊断原型。不是新的KD方法，不构成独立效果确认。

## 1. 已定位的问题

CIC24 hard MLP的2,293条C漏报中，2,272条共享同一完整特征模式。其Fwd Packets/s为2,000,000，超过整个F的最大值1,090,909，标准化后约50.51。Flow Duration为1，前向包数2、后向包数0、SYN数2、前向头长48、载荷长度为0。F中存在16条攻击短流，在选中的其他19个字段上与目标一致，持续时间13–190、速率约1.05万–15.38万；它们被已有模型识别。

HGB24和MLP24的imputer/scaler参数逐项相同，F中没有与目标相同的24维原始输入或float32输入。因此该模式的失败不是两类模型使用不同预处理，也没有证据归因于该模式被float32碰撞抹掉。冻结MLP沿前向速率方向外推时分数下降；树沿已有轴向阈值分区，在训练极值之外保持末端叶输出。

不训练、保持旧阈值，统一将所有24个数值字段夹到各自在F中的最小/最大值：hard24恢复2,272个TP，增加74个FP；wide24恢复同样TP，C FP不变。目标输入实际只有Fwd Packets/s被此规则改变。HGB24在R/C的决策不变。该干预支持“已学边界在F范围外的外推方式导致这个模式漏报”，但hard额外误报说明不能把裁剪立即当作无代价部署修复。

完整原始字段、来源核验、冻结模型响应与短流模板记录保存在工作目录`机制重设计_20261105/cic`。本地parquet字节与实验室文件不同，机制分析另核F/R/C身份和F完整字段值绑定；新实验室工具仍要求原封存manifest精确匹配，不放宽历史恢复条件。

## 2. 最近邻与采用范围

- [scikit-learn固定1.5文档](https://scikit-learn.org/1.5/modules/generated/sklearn.preprocessing.MinMaxScaler.html)已有训练范围clip选项。本文保留既有StandardScaler、类别编码和网络，仅夹住数值编码的F极值；这是普通范围限制的诊断适配，没有新颖性主张。
- [TabM作者项目](https://github.com/yandex-research/tabm)及2025/2026数值表示成果支持检查标量表示与分段表示，而非只增加网络宽度。具体原文/源码核对见[学生表示审查](research_alignment_20261105/student_representation_review.md)。这些文献不保证范围裁剪在IDS有效。
- [TabReD](https://openreview.net/pdf?id=L14sqcrUC3)与[BeyondArena](https://arxiv.org/html/2606.30410v1)要求保留时间/分组评价边界；当前C发现后的修正只能先算开发证据，不能再把C当新独立测试。

## 3. 最小干预

令既有预处理输出的数值列为$z_j$，F的每列边界为$a_j=\min_{x\in F}z_j(x)$、$b_j=\max_{x\in F}z_j(x)$。唯一候选为

$$
z'_j=\min(b_j,\max(a_j,z_j)).
$$

类别one-hot列保持原样。范围仅由F输入估计，不读F标签来定边界，不使用C分位点、不搜索百分位、不加目标hash例外。F的编码逐元素保持不变，网络权重不变，所以没有理由为这个探针重新训练。极值限制可能抹去有用的范围外异常，这是必须在全部R/C正常和各攻击族上检查的代价。

每个已封存MLP均报告两个口径：旧阈值固定用于隔离分数干预；随后按既有max(R正常阈值,C正常阈值)规则重新登记开发阈值。后者不能掩盖前者增加的误报，也不作为独立误报达标证明。两口径都保存，工具不选择赢家、不改旧包。

## 4. 可推翻解释的结果

1. F编码发生改变：实现不再是冻结模型的纯外推探针，停止并修复。
2. 大量F范围内记录的分数改变：违反干预定义，先查实现与推理精度。
3. 目标模式在范围限制后仍无法检出：范围外推不足以解释该失败，不能再宣传已定位此机制。
4. 恢复攻击同时产生不可接受的正常误报或其他族漏报：机制可能成立，部署候选仍可能不成立。
5. 只有C目标模式改善、其他环境/独立来源不保持：收缩到局部开发诊断，不扩展为通用提升。
