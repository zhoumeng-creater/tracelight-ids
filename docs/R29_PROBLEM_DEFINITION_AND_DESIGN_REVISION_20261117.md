# R29之后的问题定义与设计修订

2026-11-17。用户要求先明确问题、设计清楚并改正后再推进。本次只审阅已有结果、源码、数据合同与作者实现；没有训练、模型前向、阈值搜索、新数据下载或新实验登记。R29的历史协议与回传保持原样。

**当前决定：关闭R29固定神经模型分支；先修正问题归因和研究设计。下一版模型机制尚未定案，不发布新的训练批次。** “设计文档完成”与“新方法已具备开跑依据”分开记录。

## 1. 已经明确什么，尚未明确什么

| 判断 | 证据状态 | 对设计的影响 |
|---|---|---|
| R29整套候选没有满足既定采用条件 | 已证实；全部六个TabM和新HGB均不通过，机器检测报告经独立复算无差异 | 保留负结果，不改判据挽救本轮 |
| 训练/选轮实现坏了，或只学正常 | 没有得到支持；14次拟合、预处理、选轮及P重训均核对通过，正负训练样本均充分拟合 | 不把长训、加轮数作为默认修复 |
| F/V不覆盖TCP控制，V不能检验所要求的TCP迁移 | 已证实；P180条控制和V90条控制均UDP，D1964条控制均TCP；V很早达到pAUC=1 | 修正开发验证与目标能力的对应关系 |
| 缺TCP控制就是低召回的唯一根因 | 不成立为当前归因；R26 MLP29在同一P支持上仍检出D1773/1964，PLE也恢复大量TCP检出 | 不自动把D移入训练，不宣称加TCP样本必然修复 |
| TabM架构本身劣于旧MLP | 尚未隔离；跨轮同时改变输入、目标权重、优化与选轮 | 只能比较已实现流程，不能归因纯架构 |
| 自然权重、协议类别编码或缺失填补造成退步 | 尚未隔离；训练正类损失低不代表这些选择对迁移无影响 | 这些是候选影响因素，既不能判错，也不能当作已证优选 |
| PLE在本流程下影响了D检测 | 已证实；同种子新增1607/1560/1657条D检出，对应无PLE旧检出无丢失 | 保留正向消融；其自身不全合规，不能作为部署采用结论 |
| 所有模型都无法同时达到低误报和检出 | 未证明；现有有限流程的失败不是不可行性上界 | 删除普遍不可能性的主张 |
| HGB模型本体单条推理慢7～8倍 | 未隔离；当前调用每次进入线程限制上下文，预处理单测仅0.38ms | 成本只描述当前封装，暂停模型本体和部署场景外推 |

这里必须同时保留两个事实：当前支持没有覆盖目标迁移条件；不同流程在相同支持下仍表现出很大差异。不能把失败全部排除到模型之外，也不能把一项数据缺口当作唯一原因。

## 2. R26与R29到底改了什么

R26 `target-ports_zero8-mlp29`和R29最终P使用相同的10502条正常及180条控制，C也使用相同5511条正常身份。但训练系统并不相同。

| 变量 | R26 target/端口置零MLP29 | R29 |
|---|---|---|
| 模型 | 8→128→64→1，GELU，9473参数 | TabM 2×512、k32、dropout0.1；无/有PLE为371904/416704参数 |
| 类别目标质量 | 正常/控制各50%；单行权重约0.50857/29.67222 | 每行1；P中控制占约1.685% |
| 数值预处理 | 全八字段signed log1p，P均值/标准差 | 连续缺失填补后非负log1p，F/P各自拟合统计 |
| 协议输入 | signed log1p后的连续量 | 固定语义类别，不进入PLE |
| duration的−1 | 保留负哨兵再变换 | 中位数填补并保留独立缺失标记 |
| 端口 | 两个恒零输入槽 | 不进入学习器 |
| AdamW | lr0.001，wd0.01 | lr0.002，wd0.0003 |
| 批大小与裁剪 | 512，无梯度裁剪 | 256，梯度范数裁剪1 |
| 模型选择 | P固定80轮末轮，1680次更新 | F/V选轮，P从头重训27～194轮，1134～8148次更新 |
| 校准 | 固定C，每模型共同阈值，严格大于 | 同身份和规则，但分数与阈值随模型不同 |

旧权重公式相当于分别平均两类BCE再各占一半；R29按实际样本比例平均BCE。两者都是普通训练目标，目标质量不同不是实现错误，也不是新损失。

**设计修订：以后必须先声明比较的是模型结构，还是整个训练流程。** 结构比较要保持可比的输入、训练目标、选择规则和评价；流程比较可以改变这些项，但结果只能归于完整流程。若要解释某项改动，先给出明确作用假设与应保持的变量，不能先跑一串组合再替结果寻找原因。本轮不追加这些组合。

## 3. 任务合同先于模型清单

当前修订围绕R29的控制检测子任务；扫描和下载的已有正负证据继续保留，不能把它们悄悄视为已解决。

| 合同项 | 当前可固定的定义 | 不能默认加入的内容 |
|---|---|---|
| 观察对象 | 完整Zeek流记录形成后的网络特征 | 提前使用未来累计字节、最终持续时间或攻击者日志 |
| 预测任务 | 在明确历史标签范围内识别控制相关流 | 将控制动作、下载、普通长连接合成一个未经核实的语义 |
| 能力层次 | 同支持历史监督、未见传输迁移、未见攻击实现迁移分别报告 | 以同传输V满分代替另外两种能力证据 |
| 正常对照 | 与目标行为有业务可比性的正常流，并给出分母与未决状态 | 只因同端口就认为业务充分匹配，或将未标记背景自动当正常 |
| 分配单位 | 按来源、完整采集、事件/攻击链及时间分组 | 把同一链的请求、日期或传感器当多个独立攻击实现 |
| 标签用途 | 评价真值允许事后核实；训练、校准或更新标签须在使用前可得 | 将作者攻击日志等事后真值当作在线反馈 |
| 误报指标 | 按预先确定的评价单元报告正常数、FP及整数预算 | 用pooled FPR抵消单元超标 |
| 方法贡献 | 需要具体机制、直接近邻及可区分解释的对照 | 把换开源模型、普通混合训练、标准校准或增加数据本身称为创新 |

**目前不默认把问题改成多传输混合监督。** 若未来决定允许TCP控制标签参与训练或开发，就必须明确这是信息条件的变化，重新登记数据角色；不能沿用R29的“未见传输”解释。跨传输目标仍可保留，但它需要独立的开发证据，不能从UDP验证满分推断成功。

| 材料 | 目前可支持 | 尚缺什么 |
|---|---|---|

| DEDALE | 一条APT链内的控制/下载与正常业务混淆案例 | 按天拆分不产生新独立攻击实现 |
| SFC | 已开扫描事件与现有冻结策略结果 | 多传感器不能替代事件独立性 |
| AIT/R27 | WebShell控制、受害机下载与同站正常网页动作的外部历史案例 | 纯流/混合用途/未决标签，完整正常分母，正常下载对照，兼容Zeek字段和时刻合同 |

“整个项目只有Merlin正例”不正确。R27也没有取证失败：已有32条WebShell请求与33个候选连接、口令表下载的明确对应、68次正常动作与294个候选连接。仍不能把这些候选直接当成充分的正常校准池或新的独立低误报确认集。其轻量统计不是Zeek原八字段；68条正常反馈可用时刻均未知。JPEG前缀回显产生的响应体积差还可能形成来源特征，需在主张中保留。

当前没有已核就绪、同时满足未开独立控制/下载实现、匹配正常业务及兼容输入的确认包。这不禁止有明确问题的已开开发研究，但禁止把已有材料重新包装成盲测。此次不重新下载、拼接或评分这些数据。

## 5. 校准、评价与两类参照的修订

R29的共同C阈值只确定了该正常校准池上的工作点；它没有给每个未来单元1%的保证。逐单元1%是本轮预设的实测采用条件，保持不变。后续若要提出更强保证，必须先写清相应假设与部署前可取得的正常信息，不能通过在已开D上改阈值实现。

两类参照都保留，但分开解释：

1. **同信息流程比较**：新HGB与候选使用相同P/C、标签预算和允许特征。这用于判断固定训练系统在相同条件下的表现，不是纯架构的所有因素控制。
2. **既有能力替代**：旧HGB及端口规则拥有不同历史支持和信息，用于判断是否丢失已有能力；不能据此作公平架构排名，也不能因为不对称就删去它。

B72与D全单元合规及旧TP保持是新方案的联合要求，目前没有现成模型已经同时达到。旧强参照B66，不能称全面赢家；三个种子全过也只说明固定数据上的初始化稳定性，不代表三个独立部署确认。

## 6. 模型与训练现在如何处理

| 对象 | 决定 | 理由 |
|---|---|---|
| 官方TabM实现、成员级损失及集成评分 | 保留已审查实现和负结果；不再追加当前分支 | 没有发现实现错接，固定候选已经按预算完成 |
| PLE | 保留其正向检出消融；不称已采用 | 在本流程中确有影响，但仍不满足逐单元合规及旧强参照能力 |
| 原MLP、HGB、规则 | 保留真实强弱结果及允许信息说明 | R26结果对单因解释提供反例，不能被更规范但较弱的新流程抹去 |
| 自然行权重、语义协议编码、缺失标记 | 保留为明确的已测设计，不宣布为业务最优 | 规范性与迁移收益是不同结论；对D的独立影响未识别 |
| 长训、去协议、加入TCP、恢复混合来源、换骨干 | 均不自动实施 | 目前没有足以指定其中某一项为修复的因果证据 |
| HGB逐次线程管理 | 已识别为成本实现上的不对称，写入待修正项 | 需要把资源管理与预测计时边界统一；它不解释检测失败，当前不为此补跑实验 |

本轮没有依据选定下一种新骨干，也没有依据宣称新训练目标已设计完成。更清楚的设计应先说明具体混淆和拟议机制，不能把“用更成熟模型”当作机制本身。

## 8. 设计完成应交付什么

下一份可实施设计需要同时给出以下内容，而不是先发一个训练入口：

1. **一个明确问题**：具体是哪类正常—攻击混淆、在哪个允许信息条件下，已有方法哪里失败；反例和证据强度一并写出。
2. **明确的数据角色**：训练/开发/正常校准/评价各自允许使用哪些来源与事件；哪些已经打开，哪些能支持独立主张；不能只有行数和比例。
3. **一个有依据的机制改动**：具体改变输入表示、模型结构或目标函数的哪一处，依据哪个作者公式/实现；为何可能影响已识别混淆。
4. **可归因的比较设计**：哪些条件固定，哪一个因素改变；同条件学习器和旧强能力参照分别回答什么，成功/失败都怎样解释。
5. **判定与停止条件**：误报单位、检出保留、逐条增失、成本口径事先写定；失败后结束哪一个假设，不自动增加种子、阈值或模型清单。

这是研究设计的完成标准，不是追加用户审批流程。能够用现有源码、日志和已保存证据澄清的事项继续完成；没有被证据支持的新方法不会被写成已经修好的方案。

本次已完成问题分级、跨轮变量对照、数据用途盘点、比较与主张修订。**新机制及其可归因设计仍未建立，所以当前没有下一轮实验安排。**
