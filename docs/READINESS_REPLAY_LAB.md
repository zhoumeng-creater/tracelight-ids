```powershell

Set-Location ..\tracelight-readiness-r25
.\scripts\RUN_READINESS_REPLAY.ps1
```

默认旧结果目录来自本次回传索引：`D:\zhoumeng\Graduate\tracelight-behavior-transfer\local\behavior-transfer-r25`；解释器沿用 `D:\zhoumeng\Graduate\venvs\tracelight-route-core\Scripts\python.exe`。路径不同时明确传入：

```powershell
.\scripts\RUN_READINESS_REPLAY.ps1 `
  -PreviousRoot 'D:\你的旧工作树\local\behavior-transfer-r25' `
  -Python 'D:\你的环境\Scripts\python.exe'
```

旧结果目录必须包含 `protocol.json`、`receipts`、`evidence`，以及 `local` 下的完整特征、真值、连续分数和旧判决。11 MB 回传摘要包不能代替这些输入。模型权重和原始下载缓存不参与本批计算。旧目录可以整体移动：入口按固定相对路径和回执摘要定位，不追随索引内旧电脑的绝对路径。

`-PlanOnly` 显示固定任务；`-CheckOnly` 运行合成检查；`-PreflightOnly` 核验输入，不运行补算。三个开关单独使用。正式入口包含检查和预检，通常直接运行即可。缺少缓存时会一次列出缺项，不自动下载或重新评分。

新输出默认在新工作树 `local\readiness-replay-r25`。输入和输出必须是两个互不包含的目录树。原实验输出只读。同一命令续跑时，已完成的组先校验并跳过，再决定是否创建工作进程；单个来源或学习器失败后继续其余独立任务。补算开始后旧缓存路径也被绑定；此后搬动缓存、改变输入清单或运行设置，需要新输出目录。

## 修复条件

所有本地策略共用一个参考前缀。满足以下两个条件后才登记阈值：

1. 距第一条观测已满一小时。
2. 切换逻辑时刻**之前**至少有 399 条记录；同一时刻的全部记录都不能进入该前缀。

若原首小时已有足够样本，保留原截止时刻和判决。否则等待首个满足条件的后续时刻；整块都不满足时继续使用登记的旧正常 C 规则，状态为 `not_ready`，全部记录属于启动期。399 由最细四分量预算 `0.01/4` 的有限序位下限推导，未按效果搜索。它只使阈值可计算，不能保证前缀具有代表性或未来误报不超过 1%。有限阈值遇到全并列分数，也可能没有告警，这与样本不足须分别记录。

七种本地判决及两种并集随上述条件重算；旧八字段、contact、quality、追加质量、旧计数规则及无回包代理的原判决直接保留。输入标签、事件身份和未来分数不进入就绪选择。[规则与检查](readiness-replay/READINESS.md)

## 一次输出什么

| 输出 | 用途 |
|---|---|
| `evidence/readiness/<source>/<group>.json` | 就绪／未就绪、首小时样本数、实际参考数、切换时刻、同钟排除与各分量阈值 |
| `budget.csv.gz` | original/repaired 逐日正常分母、误报、整数预算和未决告警；原统计须精确复现 |
| `paired.csv.gz` | 修复判决分别对原同策略、旧八字段、旧追加质量，逐原生类列原检出、新检出、新增、丢失 |
| `events.csv.gz`、`services.csv.gz` | 原生动作、首次可见告警、同服务正常背景；事件起点不随 phase 重置 |
| `rare_rows.parquet` | 全部控制、下载 UID 的输入、三视图分数、旧／新判决及证据等级 |
| `ranking_thresholds.csv.gz`、`ranking_families.csv.gz` | 各单分数在同日正常预算下的共同阈值上界及各类检出 |
| `ranking_targets.csv.gz` | 每条稀有目标的全局及同服务正常排名、同分数量、检出它至少需要的正常误报数、超过预算多少 |
| `normal_service_fp.csv.gz`、案例表 | 纯正常服务误报、扫描及其他类别的有界新增／丢失／持续漏检案例 |

评价同时保留五种范围：`all` 是完整 UTC 日；`startup/after` 按修复后的未就绪／已就绪切分；`original_startup/original_after` 保留原一小时切分。各范围重叠，不相加。启动期原规则超标不会因延后校准而消失，也不能在报告中删掉。SFC 的已开、未开、混合身份和 DEDALE 的作者动作证据等级均保留。[评价口径](readiness-replay/EVALUATION.md)

排序上界分别使用 `score_raw`、`score_contact`、`score_quality`、目的端口计数和目的地址计数。在正常数为 $n$ 的范围，额度为 $\lfloor n/100\rfloor$，使用最宽松的可行共同上阈值，严格 `score > threshold`，不拆并列分数；无正常对照时标为无支持。该计算使用评价期正常标签，只用于诊断分数排序，不能作为上线策略。不同分数的上界不能逐目标择优合成一个模型成绩。同服务排名提供局部背景，不改变全日预算。[排序字段与数学定义](readiness-replay/RANKING.md)

## 多核安排

评价按来源多进程并行，每个工作进程一次读入该来源特征、真值并准备分组，复用到该来源尚未完成的五组学习器。采用一个持续进程池，按大来源优先调度。并发数同时受物理核数、当前可用内存及最大来源估计内存限制；最多八个进程，各进程分配 Arrow／本地数学库线程，总配额不超过所选线程数。

默认使用物理核数和可用内存的 60%。需要限制资源时使用 `-Threads 24 -Workers 6 -MemoryGiB 24`，它们是资源限制，不改变方法。资源设置改变后使用新输出目录；普通中断恢复沿用同一设置。

保存进程树实际核占用、内存、每源读取／共享分组时间，以及每组修复、评价和排序耗时。此批没有模型前向，GPU 分数直接复用；设备采样中的 GPU 活动可能来自其他进程。合成性能记录只验证实现路径，实验室真实吞吐和内存以本次日志为准。

## 如何据结果决定下一步

先核对旧预算统计是否逐项复现、就绪状态是否正确，再看各日误报和各类配对。任一天超标都保留，不用平均值或最佳种子替代。

- **仍未就绪或有限阈值静默：**先区分样本不足、同分与正常业务覆盖不足，不能当模型容量结论。
- **修复后达标且补回稀有目标：**记录哪些原动作恢复、哪些原告警丢失；这是已开数据的修复收益，之后才登记独立验证。
- **因果阈值漏检而同分数上界可检：**优先研究参考资料与时间漂移，并保留启动期的实际代价。
- **单分数上界也检不出：**该固定分数的共同上阈值已不足以解决这些目标。结合逐流输入和同服务正常对照，判断下一步需要改变学习依据还是观测信息；这不等于证明所有模型或融合方法都不可能。

保留简单端口规则作为扫描强基线。扫描增检不能抵消控制、下载或其他攻击丢失；作者跨日动作步骤不重复计作独立攻击。任何新教师、损失或特征设计，都应针对上述诊断暴露的具体缺口，而不是由再一次总体失败触发。
