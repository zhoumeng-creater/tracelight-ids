# 正常校准迁移：设计完善与固定比较

2026-11-22。当前主线仍是正常组成变化下的校准迁移学习。此次完善把训练参照改为完整来源正常、把目标改为既有正常业务组，并用同信息的简单分组目标取代随机时段对照。三臂、三个种子，共九次拟合；没有新增训练矩阵。

## 要解决的真实问题

R30 的三个已保存模型在各自完整 F 上，最小攻击分数减最大正常分数分别为 2.5374、3.5587、8.9514，均大于单位间隔 1；正常业务预算却只通过 8/15、5/15、4/15。任何正常组的预算顺位都不高于最大正常分数，因此单纯要求这些组与攻击分开，不能保证另一个正常参照产生的阈值可用。

这是已有真实失败的数学解释。R30 的输入和训练集合与本次不同，不能据此写成本次 G 已经失败。详细出处及近期方法核验见 [recent_methods.md](recent_methods.md)。

## 本次具体修正

旧包 `normal-tail-transfer-v1` 的训练目标使用同来源自然日前后片段，最终却用整个 russell 正常来源校准，二者参照角色不一致；随机身份置换还拆开了 73 个已知正常动作中的 46 个，不能排除简单业务分组就足够的解释。旧包完整保留，不再作为当前待运行设计。

新包使用两个 F 来源全部正常连接作参照，九个既有正常业务组作被检验对象。组身份只用于训练目标，推理不增加来源、时间、正常参照或历史信息。所有臂共用输入、模型、初始化和 BCE 抽样。

| 臂 | 训练目标 | 回答的问题 |
|---|---|---|
| A_BCE | 普通类别均衡 BCE | 成熟模型是否已经足够 |
| G_group_tail | BCE＋最不利正常组边界与攻击的分离项 | 简单业务分组约束能否解决问题 |
| R_reference_envelope | BCE＋参照阈值对业务组的覆盖项＋攻击间隔项 | 明确训练校准规则是否比 G 有额外价值 |

固定经验边界为升序第 $n-\lfloor0.01n\rfloor$ 个分数，严格大于边界才告警。令两个参照边界为 $q_j$、业务边界为 $e_u$，$a=\min s(\text{attack})-1$，则：

$$
L_G=[\max(\max_jq_j,\max_ue_u)-a]_+,
$$

$$
L_R=[\max_ue_u-\min_jq_j]_+ + [\max_jq_j-a]_+.
$$

$L_G\le L_R$。G 为零表示存在共同分离阈值；R 为零还要求每个已登记参照的实际边界都能满足每个已登记业务组的整数预算，并保持训练攻击间隔。两端边界都反传。证明、反例、梯度和约束限制见 [mechanism.md](mechanism.md)。

新贡献只能落在“参照校准约束相对简单分组约束的实际增量”上。顺位、max、hinge 和校准反传均不是本项目的新发明。当前分组是完整来源与业务的包含关系，R 为零实际上要求参照边界与最高业务边界一致；不再宣称独有时间先后机制。近期方法与作者代码比较见 [recent_methods.md](recent_methods.md)。

## 已有材料是否支撑

| F 材料 | 数量／状态 | 对设计的作用 |
|---|---:|---|
| 正常 | 12,747 条 | 两个完整来源参照与九个业务组覆盖相同正常集合 |
| 控制／下载 | 504／1 条 | 攻击池独立于正常组；下载覆盖仍只有一个训练实例 |
| santos 正常 | 439 条，cloud 314、intranet 125 | 两个实际业务组 |
| Unraveled 正常 | 12,308 条，七个既定协议／业务组 | 正常组间组成差异；不新增由分数挑选的组 |
| 已知 AIT 正常动作 | 73 个 | 每个完整保留在一个业务组内 |
| 原始及实际编码正负冲突 | 均为 0 | 排除这批 F 上“同输入异标签”的一种确定性不可能；不证明模型能拟合或迁移 |

全部正常连接只在一个业务组中出现；参照与业务组的重叠用于训练约束，不作为独立验证样本。Unraveled 没有已确认的动作级划分，不把其协议组称为动作。冻结输入与核验结果见 [inputs_receipt.json](inputs_receipt.json)。

整数取整带来实质限制：Unraveled 整体 1% 预算为 123，七个业务预算之和为 119。若其参照阈值使所有本来源业务达标，阈值处至少要有五个完全相等的分数。F 编码中存在三组重复数不少于五的正常输入，但没有证据说明它们会落在阈值处。两个来源也没有完全相同的编码正常输入。不能把数学上可写出的零损失当作已知可优化的状态。

因此不要求训练损失必须等于零才评价模型，也不以接近零代替达标。每臂末轮输出两个目标的损失、18 个参照—业务配对的实际 FP／预算、边界并列数、攻击间隔与检出、正常分数是否全部相同。禁止用 epsilon、拆分并列、修改整数预算解决这一差异。

## 一次比较后的固定出口

| 结果 | 判断与下一步 |
|---|---|
| A 已满足所需正常预算和攻击能力 | 使用成熟基线推进系统及论文，不保留无必要的额外约束 |
| G 与 R 均优于 A，R 对 G 没有稳定额外判决收益 | 简单分组解释已足够；本版本不主张参照约束创新 |
| R 对 A、G 在三个种子均降低至少一个正常单元超额，其余不增，且不丢失原已检出攻击／事件边界 | 结合实际训练与推理成本冻结候选，按既定独立前向确认要求检验；不追加寻优矩阵 |
| R 仅降低 F 分数差或损失，开发误报与攻击判决没有改善 | 没有证明检测收益，结束本版本，不改阈值或尺度补救 |
| 正常改善伴随控制／下载丢失，或收益只出现在部分种子／来源 | 完整登记取舍和不稳定性；不挑最好种子，不用总 TP 抵消下载损失，不事后制定采用门槛 |
| F 约束未满足 | 结合真实整数判决、并列分数及优化记录解释未达到的约束；仍报告固定开发结果，不直接推断算法家族无效 |
| F 约束满足而跨 run 开发失败，或三臂均没有实质收益 | 关闭这项固定候选，保留结论和既有项目成果；不自动补来源、加种子、改窗口或重启阈值搜索 |

“三种子无丢失”的标记用于识别清楚的优选候选，不把逐 TP 零损失变成所有后续研究的永久要求。项目尚无数值化的控制／下载采用门槛，报告逐类事实，不根据结果反推门槛。
