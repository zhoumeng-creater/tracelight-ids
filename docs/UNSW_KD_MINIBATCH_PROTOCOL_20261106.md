# UNSW H/K mini-batch 最小受控验证：冻结执行协议

本轮实现[最小机制验证规格第 4 节](research_alignment_20261105/kd_failure_research/最小机制验证规格_20261105.md)中的唯一条件训练分支。用户已授权交付实验室入口并由实验室运行；本机只做代码、合成检查和缓存复核。执行方法见[实验室指南](UNSW_KD_MINIBATCH_LAB.md)，机器规格见[JSON 配置](../configs/unsw-kd-minibatch-minimal-20261106.json)。

## 1. 研究问题与进入依据

第十一轮[零拟合诊断](UNSW_DIAGNOSTIC_RESULTS_20261106.md)的有效性通过：原 anchor 的 hard/teacher 梯度整体冲突未获支持；K40 的混合 BCE 仍为 0.124516711，而现成教师函数在同一目标下为 0.062642725。现有证据尚未分离优化不足与表示限制。原续训每遍 F 只更新一次，而 warmup 每遍更新 84 次，为受控检查优化方案提供了具体依据。

本轮只回答：保持教师、目标、学生和起点不变，将全批续训改为 mini-batch 后，KD 相对同预算 hard 对照的收益是否达到事前门槛？两臂均从原 warmup 开始，不能从 H40/K40 继续训练。

资格依据绑定已核验的 `analysis_integrity.json`，语义 SHA256 为 `545072afb20c2752c7fd3d94720b4fbc557b9e4dffc76c696b62d703aac0d311`。实验室无需另行寻找第十一轮目录。该绑定记录进入这两次训练的依据，不预设结果成功。

## 2. 保持不变的对象

| 对象 | 冻结内容 |
|---|---|
| 数据 | 原 UNSW-NB15 train 的 F/R/C：85,916 / 12,274 / 24,547 行；身份及原始文件 SHA 不变 |
| 字段与预处理 | 42 个原字段、189 个编码特征；复用原预处理，无重新拟合或裁剪 |
| 学生 | 原 `all-small-s17` warmup；隐藏层 32/16，6,625 参数，同一个初始 state |
| 教师 | 原 full-F `all-s17` HGB；只读已保存的 F 概率 q，零新增教师查询 |
| H | 原全 F 类平衡 hard BCE |
| K | 原普通 KD，T=1、lambda=0.3，目标 `r=(y+0.3q)/1.3` |
| 优化器 | 各臂重新创建 AdamW；lr=0.001、weight_decay=0.0001、betas=(0.9,0.999)、eps=1e-8、amsgrad/foreach/fused=False |
| 精度 | 网络 float32；logit、目标与权重进入 float64 损失；禁 AMP/TF32，确定性计算，4 线程 |
| 梯度 | 每批计算、反向、范数裁剪 10、更新各一次；全 F 固定权重乘 N/实际批行数 |

F 的类别权重分别为 `0.5/N_normal` 和 `0.5/N_attack`。每批不能按本批类别人数重新归一化。最后一批 924 行，缩放分母必须是 924，不能沿用 1024。

原 H40/K40 的分数、阈值、模型和历史日志仍按原 SHA 绑定。预检直接从原分数和阈值复算 full 的 C 差值：H=13,960 TP，K=13,965 TP，K−H=5；不重新推理或重登记原阈值。

## 3. 唯一改变与预算

每臂固定 40 遍 F，batch=1024；每遍完整访问所有 F 行一次，每遍 84 次更新。H/K 使用相同的 40 份排列。

排列在实验前通过 NumPy 1.26.4 的 `Generator(PCG64(SeedSequence([17,20261106,12])))` 连续生成；没有排列搜索。形状为 `[40,85916]`，SHA 对按行连续的 little-endian int64 字节计算，总 SHA 为 `c9f2ea0a786c77a2321a245e6037152c24f1bc43f3618f0c3e10bc276223cbed`。配置保存总 SHA 和逐遍 SHA，预检重生成核验，运行包保存完整排列。该随机流只用于共同排序，不是新的独立 seed 重复。

| 工作 | 每臂 | 总计 |
|---|---:|---:|
| 学生续训 | 1 | 2 |
| 带梯度 F 前向行 | 3,436,640 | 6,873,280 |
| 训练前向 / 反向 / 优化器更新 | 3,360 | 6,720 |
| 终点 R/C 评分行 | 36,821 | 73,642 |
| CPU 终点评分前向调用，chunk=2048 | 18 | 36 |
| 新教师拟合 / 查询、warmup 拟合 | 0 | 0 |
| 额外 F 评估、中间 R/C 评分 | 0 | 0 |
| CPU 成本计时、RSS 探针 | 0 | 0 |
| validation / calibration / test 评分 | 0 | 0 |

只取第 40 遍终点，不设早停或 checkpoint 选择。每遍日志复用训练时的前向结果；同一遍内参数持续变化，日志不是固定终点模型的 F 目标值，不能与第十一轮固定模型 F 损失直接当作同口径比较。

更新次数、随机批梯度、梯度裁剪频次、Adam 状态演化和累计 weight decay 同时变化。与原 full H/K 组成的 2×2 对照检验整个优化方案的交互，不能单独归因于更新次数或批噪声。

## 4. 预先冻结的验收

执行有效性先检查输入、共同起点、共同排列、目标、优化器、模型结构、终点、实际预算与运行前后源码。有效性失败不能被较高指标抵消。

各新终点使用原保守有限样本登记方法：分别从 R-normal 和 C-normal 取阈值，再取两者较大者；float64 原始 logit 与阈值比较，`score >= threshold` 判攻击。该规则保证的是当前开发池约束，C 已参与阈值登记。

质量门槛必须全部满足：

1. C 上 Kmini−Hmini 净 TP ≥34，标准化 pAUC@0.01 不降。
2. R 上 Kmini−Hmini 净 TP、标准化 pAUC@0.01 均不降。
3. H/K 各自在 R/C 的 FP ≤39/78；K 相对 H 的 R/C 净 FP 均不增加。
4. R/C 每个有支持的攻击族，K 相对 H 的净 TP 均不下降。
5. 删除 C 上净正收益最大的完整 `feature_hash` 组后，剩余净 TP 仍大于 0；删除后不重新登记阈值。

pAUC 比较容差沿用 1e-12。没有新增成本硬门槛，也不借用旧成本结论宣布新模型的延迟或 RSS 通过。

若要支持“优化方案达到预设的 KD 实际交互增量”，还须满足：

$$
I=(TP_{Kmini}-TP_{Hmini})-(TP_{Kfull}-TP_{Hfull})\ge34.
$$

原 full 差值为 5，因此 mini 差值至少为 39，同时满足全部质量门槛。34 是事前实际增量标准，不是显著性检验。

结果分别保存 `validity_passed`、`quality_acceptance_passed` 和 `acceptance_passed`；最后一项表示执行有效、质量门槛及交互门槛全部通过。`unsw_kd_minibatch_complete` 只表示输出完整。

## 5. 输出与停止规则

输出含两臂终点模型、原始 R/C 分数、逐遍训练日志、阈值、错误交换、逐攻击族及模式集中度、原 full 的冻结指标，以及 Hmini−Hfull、Kmini−Kfull 的 TP/FP/pAUC 差值。输出还保存源码快照、输入绑定、资格证据、完整排列、预算和逐文件 SHA。

质量或交互门槛失败仍完整封包；技术失败保留已完成的模型、逐遍日志和错误堆栈，禁止自动重试或续跑。本轮不增加 S/M、seed、遍数、教师、架构、温度或权重组合。

两臂都改善而 KD 差值不足，只支持优化方案的一般作用。通过也只是已开发 F/R/C 上的机制结果；新优化方案没有对应 S/M，不能借旧控制成绩证明实例知识机制。无硬部署上限时，项目的实际候选仍需与现成 HGB 比较；本轮门槛不替代该比较。
