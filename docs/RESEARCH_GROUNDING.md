## 1. 每个研究改动必须有可审查的依据

开始新增算法模块前，填写或更新以下记录，不能以文献数量替代：

每次重新设计先做广度检索：至少覆盖当前失败相关的方法、强简单基线、数据／评价协议和可复现项目；可并行分配方向。随后对直接近邻深读原文机制和固定版本作者实现，形成“问题—近邻—差异—对照—验收／退出”的对应记录。逐项说明为何采用、暂缓或放弃，不设置凑论文数量的配额，也不把只看标题／摘要列为深入研究。本轮示例见[2026-11-05审查](research_alignment_20261105/README.md)。

| 项目 | 记录内容 |
|---|---|
| 实际问题 | 本项目哪份结果暴露了什么失败；仅有推测时明确写假设 |
| 最近邻 | 2025—2026 年内最接近的方法、正式身份／年份、原文位置与一手 URL；不以旧方法最近更新替代年份核实 |
| 原机制 | 目标函数、输入、监督、分母／采样／阈值、优化步骤和适用条件 |
| 作者实现 | 可查仓库的 commit／blob、相关函数与实际默认配置；读取不等于运行 |
| 代数与梯度检查 | 是否只是换符号、权重、mask、尺度、采样或等价变形；是否有不可微或二分类退化 |
| 具体差异 | 与最近邻逐项对照，分“已有”“适配”“待验证”；不以多组件恰好没同名证明原创 |
| 关键对照 | 同标签／数据／初始化／学生／预算的简单控制及直接近邻；至少有一项可以击穿我们的解释 |
| 成本与证据 | 训练／教师查询／部署分别记账；设支持与退出条件，结果不符时下调或撤销主张 |

找不到全文或代码时，记录取得失败和证据层级；不补造机制、不把未检索到当不存在。可以做明确标注的独立原型和工程检查，但不能借用未核保证、宣称作者复现或直接进入完整新方法成功主张。

## 2. 文献、项目与快速更新模型分别核实

1. 论文先查正式会议／期刊、作者全文与方法／实验；主会、workshop、期刊、预印本分列。
2. 项目先查作者／维护方、输入 schema、实际版本、依赖与许可、代码默认配置及数据划分。公开链接不等于完整开源，README 不代替实现。
3. 模型分别锁软件包、checkpoint revision／文件 SHA、上下文、预训练来源和资源条件；新包版本不自动等于新模型。
4. 商业成果用于需求／输入／调查流程比较；厂商宣传的检测率和吞吐不进入本项目算法排行。
5. 不将 PCAP、流／主机图、统计 CSV 的成绩混排行；同名字段先核方向、单位、时间范围与提取器。
6. 沿用前一轮证据时检查是否已过时；新发现应直接更新当前主张，不保护旧提案的措辞。

## 3. 算法创新的最低证据边界

- 恒等式、标准 hinge／ramp／KL、门控、对偶更新及其重命名不单独算原创。
- 若两个表达数学等价，用等价性检查验证；不为同一目标重复训练并声称“优于等价基线”。
- 作者代码与论文不一致时，原文语义适配与固定源码行为分别记录，不直接由源码问题否定论文结果。
- 工程正确、数学界成立、代理优化可行、真实效果提升和新颖性成立，是五种不同结论。
- 本科工作量由研究问题、对照、机制解释和可复现成果支撑；不以测试数、拟合数或漂亮界面替代。

## 4. 实验与报告

真实训练／近期方法对照／正式资源测量在实验室 RTX4090D。本机只做单元、合成和读取分析。实验前冻结研究数据角色、近邻适配、超参预算、seed、主比较、退出规则和成本口径。

所有对照共享可用标签与信息；若新方法新增约束池标签，简单基线也获得相同监督预算。区分重复组、会话关联、攻击族和环境；不将 hash 自动当独立统计单位。

旧 test 只能用于已封存 v1 工件的解释，不给新模型排名、调阈值或独立确认。新主张需真正未使用来源；校准集经验预算不等于测试／部署总体保证。

每次进展标明“调研／设计／原型／合成／实验室运行／独立确认”。保留失败、不可取得工件和不利结果；近期方法未实测就写未实测，不将引用变成复现。
