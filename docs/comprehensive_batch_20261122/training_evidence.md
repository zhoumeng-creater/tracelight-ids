## 一次运行固定覆盖什么

72 条 TabM 轨迹均运行到 31,200 步，保存 3,900、7,800、15,600、31,200 步模型，共 288 个评价检查点。同一轨迹的四个预算共享前缀，不是四次独立拟合。每条轨迹另存 step0 初始诊断；它不计入 288 个评价检查点，不参与部署评价。

主比较预先固定为学习率 0.002、辅助权重 1、15,600 步、seed17/29/43。另一学习率 0.0005，以及 G/R/S 的权重 0.25/4，用于报告敏感性；不依据 C 或 V 重新选择最佳设置。A/H/D 只用权重 1。全部设置及解释规则见 [机制与对照设计](mechanism.md) 和 [运行说明](index.md)。

模型、预处理和每步 128 正常＋128 攻击的采样继承 v2。15,600 步共抽取 1,996,800 次攻击，505 条独立攻击各被抽约 3,954–3,955 次；31,200 步将重复次数加倍，独立攻击数仍为 505。逐行曝光向量保存在各检查点 `F_scores.npz`，来源×目标类别汇总保存在诊断和最终 summary 中。

训练每 100 步记录成员 BCE、辅助损失、裁剪前梯度范数、裁剪次数、抽样链、dropout 状态和累计成本；四个预算更新记录实际参数位移范数。step0 和四个预算还保存：

- 全 F 部署分数、行身份、按来源/目标类别及二者组合的 ensemble BCE 和分数范围。
- 同一组分数下全部六种目标的值、各来源/业务边界、预算违反项、攻击间隔与正常分数并列。
- 同一参数下的全 F 类别平衡成员 BCE 梯度、当前加权辅助梯度的范数、点积、夹角和合并范数。
- 同一参数下未加权 D、H、G 分量的梯度范数、各自与 BCE 的夹角，以及 D–H、D–G 的夹角；不能用分别训练后的 D/H 模型梯度推断 R 内部的冲突。

梯度探针使用 eval 模式关闭 dropout，恢复原有梯度、训练模式和 CPU/CUDA 随机状态，不更新参数。它衡量固定参数处的确定性方向；训练仍使用原有随机小批成员 BCE。分量探针与训练回放的前向/反向行数分开计费。

## 中断后如何继续

`recovery.pt` 在第 0 步、每 100 步及每个固定预算原子保存，包含模型、AdamW、CPU/CUDA RNG、采样队列/游标/PCG 状态、抽样哈希、历史和成本计数。恢复只继续同一注册任务，不改变种子、学习率、批量、权重或步数。Python 的 SHA-256 运行状态不能直接序列化，因此恢复时仅在 CPU 重放已完成的采样调用，核对队列、随机状态和完整 draw hash；这一步不执行模型前向或优化。

第 0 步恢复点先于初始诊断保存。更早的初始化中断仅允许恢复仍只有 job/preprocessing/groups 元数据及其临时文件、或首次恢复写入遗留的 `recovery.pt.part` 的目录，并逐项核对元数据；此时没有执行优化器更新。出现 history、snapshots 等训练工件却缺少正式恢复文件时，禁止自动重训。任何完成的预算模型都保持原字节；恢复若与现存模型状态不一致，任务报错。

每个完整预算写入 `snapshots.json`，模型、F 分数和诊断均附 SHA-256。后续步骤出现数值失败时，已完成的预算仍能进入统一报告，失败轨迹也保留失败状态。作业之间由外层运行器隔离；资源中断暂停批次并按原任务恢复，不自动缩小批量或改学习率。C 开启后的运行只能继续固定模型的评分和报告，不重新训练。

计时分别记录训练 BCE、辅助分数发现/回放、优化器，以及诊断和快照物化开销。每次报告和完整快照都更新轻量 `cost.json`；每个预算目录保留独立成本文件，`snapshots.json` 同时保存该预算累计成本及文件哈希。预算成本包含该次已完成诊断，history 的累计成本也同步更新。最终任务失败时，已有预算成本和最后报告成本仍能回传，不依赖优化器恢复文件。测量时间不写入模型工件或模型状态哈希。

heartbeat 用已完成优化时间估计剩余优化时间，诊断、其他落盘和其他作业耗时另计。恢复保留已提交更新的计数；中断后重放的实际额外时间由外层批次墙钟记录，不能用旧纯推理吞吐估算新目标的整批时间。

## 本地已经验证的内容

仅使用生成数组：六个目标的缩短轨迹验证连续训练与中断恢复的模型状态、逐行分数、抽样和 RNG 一致；初始诊断失败可从第 0 步恢复。官方 TabM+PLE 在 CPU 与 CUDA 上分别验证 R/S 的 4 步连续训练与 2＋2 步恢复，模型和评分逐位一致。这里验证的是执行与恢复实现；真实批次的任务结果由上述固定实验产生。
