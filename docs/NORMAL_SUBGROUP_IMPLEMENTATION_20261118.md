# R31 实施核验与实验室边界

本轮把v2设计接成独立的六轨迹运行、工件冻结、评价和成本流程。本机没有进行真实数据拟合，没有计算新的C/E分数或阈值。下一阶段是实验室固定六轨迹，运行说明见[实验室指南](NORMAL_SUBGROUP_LAB_20261118.md)。

## 保留的设计和作者实现

保留R30的协议盲TabM、k32、PLE、原权重、原预处理和数值分箱。网络构建、独立成员BCE、稳定平均概率log-odds、四组采样器均复用已有核验实现。作者版本及采用依据沿用[固定源码对照](normal_subgroup_design_20261118/alignment_proposal.md)，本轮没有替换架构或引入新的作者方法。

正常目标、固定尺度、两个辅助系数、学习率、三种子、每轨迹2224步、139步验证间隔及原C校准程序不变。两个比较方案均从同一种子的原R30权重出发；只改变正常目标表，正例软锚和其他训练条件相同。

## 从设计到执行的位置

| 位置 | 已落实的行为 | 核验标准 |
|---|---|---|
| `training.py` | 固定旧权重与预处理，四组批采样，双反传一次更新，固定16次CPU选择 | 无预处理重拟合、无P重训，2224次更新，不因结果提前停止 |
| `training.py`的CPU镜像 | GPU网络和优化器留原设备，用独立CPU网络选择 | step0逐位复现参照，评分前后CPU/CUDA随机流不变 |
| `protocol.py` | 源码、规格、输入SHA、实际评分主机及完整预检绑定 | 相同输入参照一致；三个step0自身通过全部F/V保护；跨主机重新预检 |
| `runner.py` | 六轨迹串行、全事件配对核验、完成阶段收据复用、全局冻结 | 全部16事件的采样/dropout相同；未完成或失败拟合不自动重训 |
| `evaluation.py` | 冻结后一次C校准，完整B/D与历史身份比较 | B72/D1964及全部原TP身份保持、15单元分别合规、三seed预设增量 |
| `costs.py` | 独立CPU成本进程，单条/批量口径、GPU吞吐另列 | 全E批256冷重放逐位一致；固定64行单条判决漂移不得被忽略 |
| 独立注册和PowerShell入口 | 固定软件环境、RTX4090D、输入与源码快照、结果/失败打包 | 不安装包、不下载数据、不调用旧训练入口；离线核验不加载模型 |

原F/V选择保护、来源内尾部保护和step0回退保持不变。回退工件直接复制原模型字节，选中新模型则保留兼容R30的模型格式与全部预处理哈希。

## 本机真实零更新核验

实际使用原三份blind权重，CPU单线程、内部批256。每个种子独立加载两次、分别评分完整F19904和V21450；两次同路径输出逐位一致，原权重SHA未变。同模型输入的参照冲突为0；正式训练读取器、身份顺序、目标表与32组映射全部核验通过。

正式CPU基线的完整F正常压过或并列正例次数均为0；三个V选择器自身检查均通过。V的H分别为0.637350506、0.708647654、0.662666667，作为未来各自的step0基准，不与理想F目标指标混称同一个结果。

本轮曾将组编号序列化误判为对象数组。逐文件检查确认原输出已经是`<U6`字符串，训练读取器可在`allow_pickle=False`下读取全部字段；冗余转换已撤回。为核查此问题重复执行了一次零更新预检，两次全部15个载荷及输出清单SHA完全相同。总计12次真实工件加载、24次完整F/V评分调用、496248条评分记录，0次优化更新；不将重复预检计为新的方法实验。

本机CPU参照用于实现核验；实验室将在自己的CPU重新生成正式参照，不能假定跨CPU数值逐位一致。

## 合成核验及未完成的效果验证

测试使用手算数组、微型官方TabM+PLE和桩后端。覆盖精确目标、采样校正、FP64锚点、实际成员梯度、CPU/GPU双路径、完整预算、选轮/回退、失败计数、六工件冻结前拒绝C/E、唯一校准、全部TP身份及误报预算、成本评分一致性。CPU与CUDA微型配对训练实际执行；没有把合成输入结果当作真实检出改善。

通过实际PowerShell入口运行的111项测试全部通过，0跳过，Ruff通过；包含本机CUDA双臂微型更新。运行命令、实际CPU载荷与207份源码/配置绑定见[核验记录](normal_subgroup_lab_20261118/verification.json)。本轮没有新架构、系数网格、种子选择、真实短训试探或阈值搜索。

剩余的实验命题是：同预算运输目标能否比保持目标更好，并且存在通过所有保护的checkpoint；该改善是否能传到已开B/D开发数据，达到全部15单元预算而不丢失任何原TP。真实CPU参照、合成梯度和可运行代码均不能预先回答这个问题。

## 实验结果如何处置

| 结果 | 处置 |
|---|---|
| 没有通过保护且改善H的checkpoint | 回退原工件，判该候选没有安全改善；不追加训练步数 |
| 运输目标没有优于同预算保持目标 | 不宣称新增目标有必要；保留对照结果 |
| V通过，但B/D丢TP或任一单元超预算 | 采用失败，不调阈值补救 |
| 三seed全部通过机制、效果及部署合同 | 记为已开开发材料上的修复结果，不称新盲测确认 |
| 实现、环境或工件合同失败 | 保存执行失败证据，先修故障，不当作算法负结果 |

正式训练和成本沿用实验室RTX4090D，保持既有测量口径。本机4050具备合成CUDA核验能力，不将硬件差异说成绝对无法训练；下一次实验只执行已登记的六轨迹，不新增另一套本机真实试训。
