# 正例保护：必要性、实现及可行性判断

2026-11-18。已实现 v2 选择器与合成核验，真实训练、真实模型加载、真实前向和新真实分数均为 0。原 `ce6b953` 的 v1 设计保留原值。v2 有两项保护口径修订：F 正例硬门槛从“绝对分数不下降”改为“每条正例被正常压过或并列的数量不增加”；V 正常尾部除 pooled Hq 外，增加 A/B 各自正常分母下三个 Hq 分别不退化的保护。原单侧分数软锚、其系数、目标、优化器、V 正例与并列保护、pooled H 唯一选轮主指标、B/D 身份及 15 单元预算均不变。原始 F 正例分数下降仍逐身份记录。

## 1. 为什么修订原 F 硬门槛

绝对分数不下降不是保留检出的必要条件。考虑全部分数作严格递增变换 $g(s)=s-7$：按同一 C 序位程序重新标定后，阈值也减 7，所有严格 `>` 判决、正负排序、H 和逐身份检出均不变，v1 却会拒绝所有分数下降的正例。

可复核数组使用原 C 规模 5511、原一基序位 5457。C 分数为 0 至 5510，旧阈值 5456；变换后阈值 5449。评价分数 `[0,5456,5457,6000]` 与整体减 7 后的分数，判决都为 `[false,false,true,true]`。这是对原硬门槛必要性的反例，不是新标定方法。

v2 只保留任务相关的 F 排序保护：每条正例的 `sum(normal_score >= positive_score)` 不增加。R30 完整 F 原计数均为 0，因而新工件仍须保持完整 F 严格分离；并列也拒绝。实现没有保留两个保护模式，不形成新实验分支。

## 2. 单侧平方软锚为什么不保证硬保护

在参照点 $s=s^0$，$[s^0-s]_+^2$ 的函数值与梯度都为 0。第一步方向由 BCE、正常目标和优化器共同决定。共享参数可以在降低正常损失时同时降低正例分数；有限权重的惩罚只在下降之后产生回拉梯度。

第一个合成例子只有一个共享参数：正常分数为 theta，正例为 theta+2，初值为 0，正常目标为 -1，尺度为 1。保留平衡 BCE、正常 MSE 与系数为 1 的正例平方锚。初始总梯度为 2.19039853899，正例锚梯度为 0。取一个 0.01 的示例梯度步，theta 变成 -0.0219039853899，总损失下降，正例分数从 2 下降到 1.97809601461。这里的 0.01 仅用于数学反例，不替换注册学习率。

第二个例子直接使用注册 AdamW 首步公式，说明软锚也不自动保证 v2 的排序条件。两个正常分数是 theta-0.5、theta，正常目标分别为 -1.5、-1；正例分数是 2*theta+0.0001，初值 theta=0，初始严格分离。平衡 BCE 与正常项的总初始梯度为 1.71941016720，正例锚梯度仍为 0。经全局 norm=1 裁剪，采用 lr=0.0002、eps=1e-8 的首次偏差修正 AdamW 更新，theta=-0.000199999998。正常最大分数变为 -0.000199999998，正例变为 -0.000299999996，逆序计数由 0 变为 1，须被选择器拒绝。theta 初值为 0，因此该步 weight decay 项为 0。

这两个例子证明损失形式没有硬约束保证，没有使用 R30 的实际梯度或把合成小间隔当作真实间隔。是否能出现满足所有保护且 H 改善的非 step0 工件，仍未得到验证。

## 3. v2 也不能代替最终检出验收

F 排序保持不是 C 阈值下检出的充分条件：正常分数为 0，正例由 1 降为 0.1，两次仍严格分离；若 C 阈值为 0.5，原正例检出、新正例不检出。因此 v2 应称 F 排序保护，不能称 C/E 检出保证。

V 逐正例逆序保护、两面板严格分离与 pAUC、正常并列保护、pooled 三个 Hq 不退化和 H 改善均保留。原 C 仅含 B 正常，因此新增 source_tails：A、B 分别以自身正常为分母、以自身冻结子群计算同样三个 Hq，逐 profile、逐 q 不高于 step0；机制比较还要求分别不差于配对控制。pooled H 仍是唯一选轮主指标，不按历史五种模式增加约束。

这项修订用完整合成分数验证，而不是直接改写指标字段。构造 A/B 各两个冻结组，每组 100 条正常，共 400 条；两 profile 的正例均高于所有正常。原 pooled H90/H95/H99 为 0.30/0.15/0.03，修改分数后为 0/0/0.01，三者都改善；B 自身正常分母下 H99 却由 0 升为 0.01。所有既有保护通过，新增 B 尾部保护单独拒绝该 checkpoint。这证明 pooled 改善不能替代 B 域尾部保护，没有使用真实记录或产生新候选效果。

最终仍须用冻结后的唯一 C 程序检验 B72、D1964、全部旧 TP 身份和每个单元的原预算。没有通过这些检查，不能因 F/V 安全而宣布修复成功。
