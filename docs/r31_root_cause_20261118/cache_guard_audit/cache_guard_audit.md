## 机制判断与下一版设计含义

已证实的错位是：训练中 F 正例分数软锚，并没有直接控制 V 全来源逐身份逆序；选轮却以每个身份一条逆序也不得增加为硬条件。该条件额外限制了固定工作点 TP 保留未必需要限制的排序变化，也不能单独保证 C/E 检出。原有冲突主要位于 B/UDP 攻击与 A/ICMP 等正常的跨域极端尾部。正常子群目标改善不能自动满足逐身份保护；4 次 B_UDP 面板退化也证明不能把全部拒绝解释为无关的跨域排序。

下一版首先要明确保护的业务端点，再为训练保护目标、验证保护和最终 C/E 判决建立对应关系。不能在看完 R31 后删掉失败条件重选，也不能把这里的旧阈值诊断当作新选轮规则。若保留逐身份排序保护，就需说明如何让训练作用于这些排序关系，并记录完整 F/V 检查点分数以复原越序来源；若改为工作点保护，必须在新注册中冻结开发校准角色与指标，而不是沿用已查看的 C/E 调规则。

## 缓存一致性与复现

R30 与 R31 的 V 数据帧逐列相同、身份顺序相同。R30 原训练缓存与 R31 CPU 参照有微小数值差异，不能写成逐位一致；三 seed 的逐正例逆序计数完全一致。原 R30 缓存也同样满足全部 2805 攻击高于旧 C 阈值。

- seed 17：21450 行中 3484 行逐位相同，最大绝对差 3.0517578125e-05；原缓存最小旧阈值间隔 10.733998。
- seed 29：21450 行中 384 行逐位相同，最大绝对差 2.26345670598e-05；原缓存最小旧阈值间隔 6.617882。
- seed 43：21450 行中 2006 行逐位相同，最大绝对差 1.52587890625e-05；原缓存最小旧阈值间隔 6.128051。
