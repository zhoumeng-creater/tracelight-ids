# 正常校准迁移：固定三臂实验室批次

本批次将[已确定的研究主线](normal_tail_mechanism_20261120/index.md)接成统一训练与评价程序。问题是：当正常业务组成改变时，训练中的真实时段对应能否比普通 BCE、同目标随机对应更有效地减少正常单元超额，同时保留控制／下载检出。研究依据、近期近邻和已关闭方案不重新展开。

固定版本为 `normal-tail-transfer-v1`。三臂各用种子 17、29、43，共九次拟合。固定末轮，不挑种子、不选开发集最优轮次、不重新拟合。现有 HGB 四臂保持原注册，未并入这九次重跑。

| 臂 | 训练目标 | 对照用途 |
|---|---|---|
| A_BCE | 类别均衡的成员 BCE | 同信息强简单模型是否已经足够 |
| B_permuted | BCE＋双边界迁移目标，同来源身份整体置换 | 校准参与训练本身的作用 |
| C_real | 同 B 的目标，保留真实自然日对应 | 真实时段／业务对应的额外作用 |

每个种子三臂具有相同初始化、BCE 抽样序列、输入和模型，末尾核对初始化与抽样哈希。B/C 每次更新都在同一参数状态下对完整 F 评分，计算精确顺位并反传；没有降低为间歇目标。三臂各 15,600 次更新，沿用既有训练上限作为固定比较预算，不宣称末轮已充分收敛。B/C 额外完整评分与反传有实际成本；报告实际行数、耗时及显存，不将相同更新次数写成相同耗时。

B/C 每份工件增加 206,731,200 行完整 F 发现评分，六份合计 1,240,387,200 行，另计活跃分块反传。C 对 B 才是对应结构的主要创新对照，两者有相同更新数和完整评分上限；A 用于判断普通模型是否已足够。实际训练成本必须与检测收益一起解释。

在实验室仓库目录执行：

```powershell
Set-Location '..\tracelight-normal-tail-v1'
.\scripts\RUN_CALIBRATION_TRANSFER.ps1 -Output 'D:\Research Work\results\normal-tail-transfer-v1'
```

入口默认使用项目已有解释器 `D:\zhoumeng\Graduate\venvs\tracelight-route-core\Scripts\python.exe`。若现有环境位置不同，通过 `-Python` 指定。环境检查要求 RTX4090D、PyTorch 2.6.0 CUDA 构建、TabM 0.0.3、rtdl_num_embeddings 0.0.12，以及项目固定的 NumPy／pandas／scikit-learn；脚本不自动改环境。依赖配置沿用[近期方法环境说明](RECENT_METHODS.md)。

输出必须为空目录。程序依次完成九次训练并保存全部模型、九次 C 校准并保存全部阈值、固定开发评价和 ZIP 打包；训练每 100 次更新输出进度。回传整个 ZIP。异常会保留已经完成的工件和错误，不自动重新训练。

可用同一入口加 `-InputsOnly` 做数据和代码检查，另设一个空输出目录。该模式只解析 F，绑定整份输入的哈希，不构造模型、不评分、不计算阈值。

## 已固定的实现

F 为 13,252 条：12,747 正常、504 控制、1 下载。123 条未知和 11 条其他攻击不进入拟合；未知不改成正常。所有完整流特征仍按离线导出时刻解释。

输入保留协议类别、五个连续字段和缺失标志；有限端口值丢弃，两个端口的缺失标志保留。连续字段只在 F 拟合中位数、log1p 标准化和 PLE 分箱。协议沿用固定类别 `1/6/17/58/132/UNKNOWN`。三臂推理均不接收来源、时间、历史、正常参照或片段身份。

模型复用作者 TabM＋PLE：2 层、宽 512、32 个成员、dropout 0.1；PLE 维度 16、最多 48 箱、version B、不加激活。优化器 AdamW，学习率 0.002、weight decay 0.0003、梯度范数裁剪 1；FP32 参数和成员 logits。每批 128 正常、128 攻击，分别按固定随机排列循环抽取；不按来源重加权，不再叠加类别权重。

部署分数是成员概率均值的稳定 FP64 对数几率，不是成员 logits 均值。迁移项使用关闭 dropout 的同一个部署分数：先按固定 1,024 行分块对 F 评分，在分数向量上求顺位目标导数，再对有非零导数的原始整块重放反传。重放使用相同参数、分块大小和次序，并核对分数逐位一致；最后与 BCE 梯度相加，执行一次参数更新。两端顺位都反传。margin 与迁移权重均为 1。

| 真实 E 时段 | Q 正常数 | E 正常数 | E 的 1% 整数预算 |
|---|---:|---:|---:|
| santos 2022-01-15 | 119 | 64 | 0 |
| santos 2022-01-16 | 183 | 113 | 1 |
| santos 2022-01-17 | 296 | 143 | 1 |

这些全部是训练内片段。B 的同来源身份置换保持片段大小及复用次数多重集；三个种子均将 73 个已知 AIT 正常动作组件中的 46 个分到多个伪时段，完整对应已保存。C−B 检验真实时间／业务对应的整体作用，不能单独归因于纯粹时间因果。

所有九个模型保存后才读取 russell 的 3,475 条 C 正常。阈值固定为升序第 `N-floor(0.01*N)` 个分数，严格大于才告警；九份阈值都保存后才读取完整 fox／OpTC 开发输入。harrison／Meterpreter 不在本批次输入。经验预算不等于总体误报保证。

## 回传后按什么作决定

报告同时给出逐连接分数与判决、每个正常单元的整数超额、控制／下载分别检出、事件候选命中上下界、所有新增与丢失、训练内真实／随机片段诊断及实际成本。每个种子单列，不把重叠单元和重复连接视为独立样本。

| 固定结果 | 下一步 |
|---|---|
| A 已满足正常业务预算且攻击能力满足应用要求 | 使用成熟基线推进论文和系统，不强行保留 C 的创新身份 |
| B/C 改善 A，C 相比 B 没有一致额外收益 | 保留校准训练适配结果，结束本版本时间／业务对应的创新主张 |
| C 相对 A、B 在三个种子均降低至少一个正常单元超额，其余不增，且无已检出攻击／事件边界丢失 | 结合实测成本冻结候选，进入独立时间前向确认；这项规则只形成开发候选，不自动宣布全项目成功 |
| gap/loss 降低，但开发误报判决和检出没有改善 | 判定未证明检测收益，不调整分数尺度或阈值挽救 |
| 正常误报下降伴随控制／下载丢失 | 按逐条与逐事件结果记录取舍，不用总 TP 抵消下载损失，也不事后制定采用门槛 |
| F 约束成立而跨 run 开发失败，或三个固定臂都没有解决问题 | 结束这项固定比较，不追加来源、种子、窗口、阈值或模型搜索 |

脚本中的“无攻击丢失”标记用于识别清楚的优选候选，不把零回退扩成所有后续研究的永久否决条件。尚未给定的最低控制／下载能力只作分项描述，不看完结果后补数字。
