# 早期至第十八轮：可保留的成果、被否定的方案与设计约束

整理日期：2026-11-19。依据实验归档的复核分析、KD 失效机制材料和当时的一手研究审查；本次只读既有材料，没有加载模型、评分、训练或重新选择阈值。表内数字沿用各轮实际划分、工作点和成本测量条件，不跨轮拼接成一个模型成绩。

**这段历程并非一直没有成果。** 已经做成的是可复算的强基线、几种有明确代价的轻量化方案、输入表示修复，以及对蒸馏目标和优化解释的实质排除。没有做成的是：证明一个新增算法机制能在强参照之上稳定改善目标检测。后者不能用工程检查通过数、模型体积下降或某一族局部增益替代。

旧 UNSW/CIC 工作主要是一般入侵二分类，输入为 42/82 等原始字段；R13—18 为 NF-ToN-IoT 的 48 字段。它们与当前 8 字段控制／下载识别不同。旧 R/C 中 C 曾用于约束和选择，不能与当前正常校准 C 混称。下表的保护条件、净增门槛和无新增错误条件均是**当时协议**，不恢复为当前所有新方法的永久硬门；当前仍应报告完整收益、损失、误报及成本取舍。

对当前算法设计最有约束力的过去结果

**首要是 R11＋R12：现成 HGB 的检测优势和真实成本已经成立，而普通 KD 的两种固定优化方案都没有交付足够增量。** 在当时 UNSW 条件下，HGB 比 H40 单条 p95 只多 0.81467ms，C 多 488 TP、少 2 FP；其完整 Python 进程 RSS 反而更低。mini-batch 补救没有缩小差距。用户没有强制约 35KB 的部署上限，因此不能再次把“必须得到极小学生”当作不证自明的需求，也不能把强教师存在当作蒸馏值得继续的理由。见[终点与成本测量][s12]、[优化补救结果][s13]。

这个约束不是“现在一律选 HGB”：旧 42 字段一般入侵结果不证明当前 raw8 控制／下载任务同样成功。它要求任何新增复杂性先证明相对强简单参照的目标收益或必要成本节约，而不是只超过某个已经较弱的学生。

第二个约束是 R14 与 R18 的组合：**修正输入确实带来过成功，但修完之后仍有具体的正常／攻击混淆。** 因而输入契约与判别机制应分别举证；“修好了字段”不等于“识别问题已经解决”，“多个模型都失败”也不等于“必须加历史／图”。当前若使用跨流信息，先要证明该信息在判决时已经可用，并能区分可比正常业务，再讨论结构。

应停止复活的具体分支包括：原 MI 稳定聚合的无增量主张、v4 全拒后的重复更新、固定 small 普通 KD 的温度／轮数续试、R15 端口映射变体、R16 扫描拆类种子，以及未证明完整教师任务价值就先压缩的新几何。应继续保留的是各阶段原始正负结果、强简单基线、真实质量—成本取舍和能改变前提的输入／标签证据。这里停止的是已被检验的具体配方，不是对整类方法作普遍判决。
