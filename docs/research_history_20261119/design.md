# 从实验经历修正研究设计

2026-11-19。当前要研究的是：在明确的网络观察和监督条件下，机器学习方法能否以可接受的误报与实际成本识别目标行为。控制和下载分别评价，低误报、算法贡献与展示要求保留。现有 raw8 四臂只检验这套单流 HGB 流程，不是整个课题永远只能使用八字段的规定。

## 先确定任务和信息，再确定模型

| 设计对象 | 当前确定的含义 | 会改变任务的做法 |
|---|---|---|
| 预测单位 | 已形成的网络连接观察；动作和完整链另作事件评价 | 把一个动作的多个连接当多个独立攻击，或把整台主机都标恶意 |
| 查询时刻 | AIT 使用已记录的离线导出时钟；OpTC 使用明确的流结束重放 | 把完整连接特征提前放到首包／命令发出时刻，或冒充真实在线接收 |
| 允许信息 | 冻结单流特征；若研究历史，只能使用当时已可得的观察 | 把攻击者日志、PID、URL 命令、未来包或未到达的完整流变成网络输入 |
| 真值与歧义 | actor／官方动作及请求、对象、UID 的证据链；多候选保留上下界 | 任挑一个候选记为确定命中；把未标记背景算正常 |
| 监督与评价 | 冻结采集／攻击链／正常活动组隔离；本四臂采用整 run／campaign；已开材料是开发 | 用训练内新来源的命中证明跨实现收益；把已开集重新称盲测；把本批整来源划分强加给所有未来任务 |
| 工作点与代价 | 固定 C 规则；逐正常单元 FP；逐类和逐事件得失；实际成本 | 池化均值抵消单元超额；将事后可行阈值、批吞吐当部署单条延迟 |

控制连接、恶意文件传输和普通业务的区别必须由相应证据支持。共同训练一个二分类分数可以比较，不能因此认为两类任务的机制相同。一个新方法可针对其中一个具体困难，但必须保留另一类的回归结果，不能删除退步后再宣布解决联合任务。

用户要求的新前向时段按数据时间定义；方法和选阈值规则须在确认前冻结，每次告警仅使用当时可得材料。当前异源开发资料不替代前向确认，也不要求重新采集今天之后的流量。

## 历史结果怎样约束下一项算法

**轻量化与蒸馏。** 早期小模型和字段压缩已经取得实际收益，普通 KD 也已经完成必要的正负对照。强教师存在，只说明有一个较强函数，不证明特定学生能承接其优势，更不证明必须压缩。下一项蒸馏设计若没有同结构 hard 学生、教师的目标能力和真实质量—成本收益，不立项。当前四臂没有教师／学生，因此不承担该判断。

**模型表示。** R26 代表性监督和 R29 PLE 改善了具体控制检出；R30 进一步做到全部 B/D 检出。这些证据否定“少字段一律没有信息”“换结构必然无用”等普遍解释。R30 误报又不能由缺训练样本一概解释。下一项表示设计应说明要改变哪一类实际排序和相应正常混淆，不能由总 FN 或共同错误直接推出新骨干。

**正常风险。** R31 的代理下降没有带来联合判决改善，解析反例还说明单侧下调分数不保证重新校准后的误报下降。共同工作点的正确组件已实现，但正常风险族的覆盖与必要性仍未成立。不能恢复该分支，再把分组粒度、损失权重或乘子试验当作根因修复。

**历史与关系。** AIT 真正 wget 控制流在下载查询时不可用；已完成的较早同链动作有时被最近槽覆盖。OpTC 有重复控制通信，但正常 ownCloud 同样重复端点。前者证明当前摘要不能承担所称因果机制，后者既不是“所有历史无用”，也不是“学习选择器必要”。同 PID、同主机、端点重复不足以生成控制导致下载的关系监督。更改为进行中的报文状态会改变采集和时钟条件，当前不能默认为已得到可学习信号。

## 算法机制的现行判断

| 具体方向 | 当前证据 | 处置 |
|---|---|---|
| 固定 19 维完整流历史识别控制—下载关系 | 可用时刻与所称触发关系冲突；正常端点重复反例明确 | 关闭，不登记替代窗口 |
| 端点重复／周期性识别 C2 | 本项目有局部正证据，成熟方法已有具体机制 | 可作相关工作和必要时的同信息参照；没有新增机制，当前不追加训练 |
| 正常分组风险训练恢复全部旧 TP | 旧目标和保护错位；修正组件未解决风险族依据 | 关闭默认推进，不以组件已完成恢复拟合 |
| 教师压缩／知识蒸馏 | 早期强教师与学生存在差距，但既定 KD 补救失败；当前批次不含教师学生 | 保留历史成果；没有新立项依据 |
| 扩充监督 × 端口处理的单流基线 | 输入和标签已具备，问题具体且尚待结果 | 保留四臂一次收尾，效果不能自动推出任何上述算法 |

这次没有为了形成一份“新方案”而选一个新模型名。原创要求继续保留，当前新增机制状态明确为未立项。原始实验已回答的问题不重新训练；可以直接转化为论文证据和真实展示。

## 四臂结束后如何继续，如何停止

四臂是一项描述性开发比较，不先假定“全部目标成功”或给未约定的召回填任意数字。结果同时按来源、控制／下载、正常业务和事件歧义解释：

| 结果事实 | 结论 | 固定处置 |
|---|---|---|
| 扩充后在未拟合来源有检出收益，且正常代价与任务取舍清楚 | 完整监督扩充对这套流程的实际作用 | 固定参照与收益边界，结束覆盖问题；不自动蒸馏 |
| 扩充无益或退步 | 本次扩充没有收益或出现负迁移 | 保留负结果，不重配来源比例、重抽子集或追加来源挽救 |
| 仅保留端口的流程表现好 | 端口处理改变了流程表现 | 不能称布局无关，也不能由此断言所有端口都是泄漏；不事后换主臂 |
| 控制收益与下载退步并存 | 任务存在取舍 | 联合目标未解决，下载覆盖未扩充；不能用控制 TP 抵消下载缺口 |
| 误报超额或四臂均不足 | 当前配方未交付所需能力 | 关闭这套配方的修补循环；不能推出所有单流模型失败或历史必需 |

新算法若要另行立项，必须给出一个具体改动及其证据：当前错在哪里、预测时多了或保留了什么信息、哪个成熟简单参照未解决、哪一个对照能够推翻拟议解释。比较应区分额外信息与学习机制的收益；模型、信息、监督同时改变时，只能评价完整流程。不能要求每次工程操作都重新做一轮文献审查。

当前剩余问题不能由四臂结果自动变成算法答案。研究可以获得负结果，但必须结束具体假设；不能把“继续寻找原因”永久转化为新实验指令。

## 近期成果对当前取舍的影响

本次按已有问题补查了[近期直接相关研究](method_sources.md)，没有添加新的模型矩阵。图方法的上下文与输出单位、流聚合的采集条件、KD 对 hard 学生的真实增量，都要先与本项目对应。相关论文的高 F1、AUC 或大吞吐不能替代当前逐业务低误报和控制／下载证据。
