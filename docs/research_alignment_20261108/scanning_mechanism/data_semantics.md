# Scanning 输入语义与支持覆盖审查

2026-11-08。本审查读取2025年官方ZIP内的字段表、2025原论文与2026修订，以及本项目登记的48字段。没有加载模型、拟合预处理或重新提取真实流量。

**四ID保真消除了身份合并，但没有验证数值邻近具有业务含义。现有工件也没有提供跨流扫描行为窗口。** 这两点应分开检验，不能由Scanning漏检直接认定必须换模型或必须增加时序模块。

## 字段能说明什么

字段定义优先来自官方原ZIP内 `data/NetFlow_v3_Features.csv`，共2935字节，SHA-256为 `abe3ce6e6ff731d72d76e029b512585c0dbcbd8e03ff6dbe2bd04b560723bd67`。同包 `bag-info.txt` 的Bagging-Date为2025-02-28。ZIP常驻位置为 `data/raw/nf-ton-iot-v3/NF-ToN-IoT-v3-official.zip`，未另行展开数据副本。[数据作者2025发布页](https://staff.itee.uq.edu.au/marius/NIDS_datasets/)

| 字段 | 官方定义支持的解释 | 本轮不能据此认定的内容 |
|---|---|---|
| L4_SRC_PORT／L4_DST_PORT | 流记录源／目的端口编号，须保留方向 | source必为发起客户端、destination必为服务端；目的443必为某个已验证应用 |
| PROTOCOL | IP协议标识字节 | 编号差值是协议相似度 |
| L7_PROTO | 数值形式的应用层协议ID | 91已被该发布版本确证为TLS或HTTPS；公开材料没有绑定提取器版本和ID名称表 |
| TCP_FLAGS／CLIENT_TCP_FLAGS／SERVER_TCP_FLAGS | 全流、客户端、服务端的累积TCP标志 | 它是连续强度或标志数量；已核到该发布版本每一bit的实现映射 |
| ICMP_TYPE | type×256+code的组合编码 | 编码差值可作连续行为距离 |
| DNS_QUERY_TYPE／FTP_COMMAND_RET_CODE | DNS查询类型／FTP返回码 | 数值大小具有统一的危险程度顺序 |
| 两向IAT统计、时长、包数、字节数 | 单条流内的包间隔和通信统计 | 同一主体在一个时间窗口内访问了多少主机或端口 |

官方字段表有说明错误：`DURATION_OUT`与`DURATION_IN`均写client→server；反向IAT的MAX／AVG／STDDEV也均误写为minimum。2025/2026论文表格正确区分了IAT统计名称，但仍重复DURATION方向说明。当前应保留列名和原数值，不据有歧义的文字自动交换方向。四个保护列之外的44列包含多种代码字段，因此“沿用数值链”不能改写成“44个连续物理量”。

论文将端口作为类别字段分析，并以时间和五元组匹配原始ground truth。Scanning是映射到流记录的攻击族标签，不意味着一条流已经包含整个扫描事件。原发布提供53特征；本项目删去两个IP、两个绝对时间和DNS事务ID后为48特征。保留的IAT是流内统计，不提供跨流计数。以上来自[2025原论文§4—5](https://arxiv.org/html/2503.04404v1)，其[2026修订](https://arxiv.org/html/2503.04404v3)未补充nProbe／nDPI构建版本或L7 ID映射。

## 支持覆盖应分四层记录

1. **单字段身份覆盖**：每个ID是否分别在P出现。它不能证明四ID组合或对应行为出现过。
2. **组合与方向覆盖**：固定有序的PROTOCOL／L7／目的端口等组合，分别报告P中的正常、攻击行数以及通信组数。不能把无序通信组键当作所有方向特征都可交换。
3. **行为覆盖**：在相同组合内比较其余字段的重复模式、范围及标签冲突，并区分多行重复与多个通信组。少量范围交叠不能证明不可分，完全不同的精确模式也不能证明可泛化学习。
4. **部署可用性**：查询真标签和attack_family只用于离线诊断，不进入查询端选择规则。任何支持重选必须登记可见的P信息、候选池、预算和额外标签使用；与原P不同的样本量或族标签监督不能悄悄合并为“覆盖改善”。

项目的communication_group由两端点无序对及IP协议生成，并且只用于划分。其哈希既不能恢复主机邻域，也不能重建时间窗口；组隔离不等于主机隔离或时间隔离。若后续检验跨流信号，需要回到原始IP／时间元数据，明确只使用决策时刻之前的信息与状态成本，不能直接向现有48字段插入日期或主机标识来提高开发集成绩。

## 原始元数据补核

本地官方ZIP可以按`sample_id`末尾的原CSV记录号回溯，所以本轮已完成原IP和起止时间核对。脚本[raw_metadata_audit.py](raw_metadata_audit.py)用`csv.reader`读取真实CSV记录，流式读完27,520,260条记录、5,302,886,266字节，没有展开CSV。CSV SHA-256为`53ec8f468a43ede9b1536fabc0390af2fa33ab4312b23ce4d864f186a4651f78`，与全部sample_id前缀一致；ZIP成员CRC在EOF验证通过。33,192条P/C/E记录的1,593,216个特征数值、二元标签和规范化攻击族全部对齐，未发现错行。原始`scanning`等族名按已有准备代码的strip＋casefold规则与`Scanning`等规范名核对。只保存约96KB的[聚合JSON](raw_metadata_audit.json)，没有保存逐行原始元数据副本。

E的20,000行中，19,966行源主机在P出现过，19,695行目的主机在P出现过，19,316行有向IP对在P出现过。IP和绝对时间没有作为模型输入，因此这些重合界定的是划分与泛化证据，不单独构成特征泄漏判断。

54条旧检出丢失行来自`192.168.1.30`、`.31`、`.32`三个源主机，分别10、20、24行；它们对应47个目的主机、51个有向IP对。三个源主机都已有P扫描支持；30／54行的目的主机、19／54行的有向IP对在P扫描中出现过。54行开始于UTC 2019-04-23 14:13:34.601至24日03:55:04.425，共21个活跃分钟，全部位于P扫描起止时间包络之内。这里的时间包络只表示最早至最晚之间，不表示事件或邻接窗口一致。

主47字段模式进一步显示：E的217条Scanning和33条正常流均来自同三个源主机；仅知道源主机不能区分该模式的标签。217条Scanning对应140个目的主机、179个有向IP对，开始时间落在25个活跃分钟；33条正常流对应31个目的主机、31个有向IP对，落在8个活跃分钟。扫描有100条在23日、117条在24日；正常有32条在23日、1条在24日。P同模式89条扫描的源主机全部覆盖E这217条的源主机，但仅37／217行的有向IP对在P同模式扫描中出现过。

这次回溯排除了“54条全部来自P未见源主机”这一解释，并确认目前没有独立主机或前向时间外推证据。目的覆盖和时间集中度值得保留为下一步机制线索；它们尚未验证因果可用的跨流特征。当前33,192条是抽样工件，不能把其窗口计数当作完整网络流量的扫描速率、扇出或在线状态。

## 最小机制对照的语义要求

先固定模型、P、C、E、输出维度及阈值登记规则，只干预被检验的输入关系。若要检验“端口数值距离”假设，必须保持ID之间的一一对应、已见／未见状态和查询可用性，不能重新引入词表外归并，同时又换支持集、类别先验或数值缩放而仍把效果归为单一因素。反向或随机重命名只能证明特定变换敏感性；任意重命名可能破坏端口分配的真实结构，不自动等于更正确的语义表示。

若检验支持覆盖，则先固定表示，明确改变的是候选选择、局部类别比例、重复频率还是总N。新增扫描样本同时减少正常样本会改变先验与上下文，这不是纯覆盖干预。两类机制应顺序检查；仅因一项阴性结果，不能立刻把缺失信息、输入几何和支持选择合并成一个大模块。
