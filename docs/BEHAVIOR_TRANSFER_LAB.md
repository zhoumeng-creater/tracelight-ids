# 第二十五轮实验室对照

本批次检验已观察到的两种失效。在同一批 SFC 扫描中，冻结 MLP29 的低误报排序远弱于一个已有输入中的端口计数；端口计数沿用外地正常校准阈值又会超出误报预算。用本地首小时无标签流量定阈值，在开发场景可以恢复大量扫描。实验将这一方案冻结到其他采集日，并同时测原告警的保留、丢失、正常误报及计算开销。现有全部五组学习器与权重均复用。[开发证据与研究取舍](behavior-transfer/DEVELOPMENT_EVIDENCE.md)

计划覆盖 IoT-SFC 单传感器的 14 个有记录日期块，以及 DEDALE 绿色传感器的 28 个原生日文件，共 42 个输入块。每块重放普通 HGB、家族加权 HGB 和 MLP 的 17、29、43 三个种子，每组预先登记 18 种判决。各模型只计算一次 raw/contact/quality 分数，其他对照复用这些分数。拟合次数为 0，策略、日期与随机种子不作为独立攻击事件计数。

在实验室仓库目录执行，使用新的工作树。

```powershell
git fetch origin tag behavior-transfer-lab-v1
git worktree add --detach ..\tracelight-behavior-r25 behavior-transfer-lab-v1
Set-Location ..\tracelight-behavior-r25
.\scripts\RUN_BEHAVIOR_TRANSFER.ps1
```

入口沿用第二十四轮的 route-core Python/CUDA 环境与随仓库提供的冻结权重。解释器默认路径为 `D:\zhoumeng\Graduate\venvs\tracelight-route-core\Scripts\python.exe`。路径不同时使用 `-Python '绝对路径\python.exe'`。可先用 `-CheckOnly` 运行合成检查，`-PlanOnly` 查看登记批次。正式运行自动完成检查、旧正常校准重放、GPU 批大小探针、数据下载/身份核对、多核历史构建、CPU/GPU 并行评分、阈值冻结、标签评价和结果打包。独立来源或日期失败后继续其余可运行任务，并生成未完成状态。

```powershell
.\scripts\RUN_BEHAVIOR_TRANSFER.ps1 -CacheDir 'D:\实验数据\behavior-transfer-20261114' -OutputRoot 'D:\实验输出\behavior-transfer-r25' -Threads 24
```

`-CacheDir` 下分别使用 `sfc`、`dedale` 子目录。默认原始数据缓存为仓库内 `data\raw\behavior-transfer-20261114`，实验结果为 `local\behavior-transfer-r25`。下载按公开来源及冻结 ZIP 成员位置续传，核对长度、摘要或 CRC。已下载的完整官方 ZIP 也可按各来源说明放入缓存作为离线输入。中断后在同一工作树与输出目录重跑同一命令，已通过文件摘要校验的阶段复用。[SFC 来源与身份](behavior-transfer/SFC_SOURCE.md) · [DEDALE 来源与原生事件](behavior-transfer/DEDALE_SOURCE.md)

**输入时段决定如何解释结果。** SFC 的 25 份原生备份有 5,839,132 行，排除 3,194,503 条字段完全相同的重复 UID 后有 2,644,629 行；其中 617,770 行属于已打开的两份快照。4 月 10 日完全已开，4 月 11 日与 14 日包含旧记录，4 月 12、13 日在登记时未评分。4 月 15–17 日为旧快照内容。早期日期覆盖稀疏，4 月 3 日只有 15 行、4 日只有 4 行，4 月 5、9 日没有该传感器记录；16 个作者扫描时窗中是否有可用样本，须看本轮事件覆盖表。原生日志时间与事件窗口重合只证明有流量，不能提前当成扫描样本覆盖。每行保留旧记录身份，按事件和来源分别报告。[冻结清单](../configs/behavior-transfer-20261114/sfc.json)

DEDALE 原生文件覆盖四周，D15 的开发样本已用于前一轮原因核查。D16–D28 是同一试验台的后续文件，D01–D14 提供较早正常业务漂移对照。使用原始 conn.log 的物理行序，用 UID 将作者按开始时间排序的标签 CSV 对齐，核对端点、协议和开始时间。作者类别 0 保留为正常、2 保留为未决/攻击相关，1 按具体动作映射为下载、外部控制或其他攻击。D15 的小 ZIP 下载保留独立主机和网络证据，其他事件的证据级别随行报告。IP 和 UID 用于历史关系或真值对齐，模型的固定输入仍只取已登记数值列。[冻结清单](../configs/behavior-transfer-20261114/dedale.json)

**每个原生日文件或日期块按一次冷启动处理。** 以物理记录顺序上的单调结束时钟代表日志可见时刻。它是离线重放代理，原始开始时间与结束时间仍在来源审计中保留。前 60 秒历史严格排除当前逻辑毫秒的全部记录。每块从首条记录起取整整一小时，只用这段全部观测流量登记本地阈值，随后冻结。首小时采用早期正常 C 的相应规则，照常计入所在 UTC 日结果。若文件不足一小时，整块采用旧 C。某个原生日文件跨 UTC 日时，沿用该块同一个首小时阈值，各 UTC 日分别报效果。结果中 `startup`、`after` 和 `all` 使用各自分母；`all` 表示该 UTC 日的全部记录。整块的误报数与正常分母可分别对各日 `all` 求和，不能平均日误报率。

| 判决组 | 要回答的问题 |
| --- | --- |
| `raw_old`、`contact_old`、`quality_old`、`add_quality_old` | 冻结模型和旧正常阈值在每个来源的原始表现 |
| `ports_old`、`targets_old`、`counts_old` | 过去 60 秒不同目的端口/地址计数的旧阈值能否迁移 |
| `ports_local`、`targets_local`、`counts_local` | 同一简单分数改用本地首小时阈值能否保持预算 |
| `raw_local`、`quality_local` | 固定学习分数只重定阈值能恢复多少 |
| `quality_counts_old`、`quality_counts_local` | 同一个质量分数加两个计数，用旧或本地参考资料时的区别 |
| `raw_quality_counts_local` | 同时保留两种模型分数的信息后，统一分配预算的得失 |
| `frozen_plus_ports_local`、`frozen_plus_counts_local` | 保留所有原告警并追加规则会增检多少、总误报是否超标 |
| `no_reply_scan_proxy` | 已观测无回应条件、按目标/服务分组的 5 分钟历史对照 |

主比较是 `quality_counts_local` 对同组 `add_quality_old` 和 `raw_old`；三个 MLP 和两个 HGB 全部报告。所有规则使用严格大于阈值，并列分数作同一判定，沿用仓库第 $\lceil(n+1)(1-\alpha)\rceil$ 个升序分数。两路组合各分 0.5%，三路各分 1/300，四路各分 0.25%；这里控制的是参考集合上的告警比例，后续正常误报通过真值实际计数。直接追加对照允许总误报超标并如实保留。主策略身份只确定比较顺序，任何跨来源效果和新方法价值都由真实结果判断。[策略、序位与时间口径](behavior-transfer/POLICY_AND_SCAN_PROXY.md)

原先引用的 Zeek `misc/scan.zeek` 在 v6 已被标注弃用。本批次的 `no_reply_scan_proxy` 是按已完成流记录构造的明确对照，15/25 个目标与端口、5 分钟仅保留为历史参考参数。原生连接拒绝、重置、反向事件及 notice 抑制不能由这一代理完整复现。两条 60 秒计数和已有学习器承担主要比较，代理成绩按其实际定义解释。[官方弃用记录与事件实现](https://raw.githubusercontent.com/zeek/zeek/v6.0.9/scripts/policy/misc/scan.zeek)

**回传结果应能直接回答新增和丢失。** 每组学习器按 UTC 日输出正常误报分子/分母、原生类别的原检出/新增/丢失、同服务正常支持、纯正常服务的误报分布、作者事件覆盖和首次可见告警时间。未决流量保留其告警数。控制与下载按实际原生动作及证据等级报告，摄像头攻击或暴力破解不替代它们。DEDALE 的事件编号按作者动作阶段生成，同一阶段的多条信标不能算多次独立任务。所有组均保留有界案例，包含行号、UID、原生类别、模型输入数值及原始分数，供本地解释失败。完整逐行特征、连续分数和判决保存在实验室输出的 `local`，回传包保留摘要和必要案例。

**资源安排。** 数据下载、解析/UID 对齐按独立文件并行；历史构建利用多核分块。两组 HGB 分用 CPU 线程，与单独的 CUDA 队列同时执行。三个 MLP 在 GPU 上依次批评分，按早期 C 的重复输入比较 4096、16384、65536 批大小，在连续分数容差及旧判决一致的候选中取最快者。选择过程不读取新日期的标签或模型效果。默认 CPU 配额取物理核数，限制为 4–64，可用 `-Threads` 指定。资源日志保存实际进程树核占用、内存、GPU 利用率及显存。

每个来源选无标签行数最多的日块，取最前 50,000 条，实测一次串行与一次并行历史构建并逐列比较。另用现有在线历史实现对同一前缀测两个计数的逐条维护与判决时间、状态规模和进程内存。GPU 探针、全批评分、历史构建和单线程在线计数各有独立计时范围，结果说明真实瓶颈，不用线程参数或 GPU 被调用代替加速证据。

完整结束后回传 `local\behavior-transfer-r25\behavior-results-*.zip` 和同名 `.sha256.json`。任一登记阶段失败时生成 `behavior-incomplete-*.zip`，`outcome.json` 给出未完成项；同命令重跑会复用已成功阶段。回传包不装原始数据、完整特征或每行分数。先保留实验室本地输出，分析后再按恢复记录精简。

**判读与停止条件。** 各日正常误报必须不超过 `floor(正常条数/100)`；正常分母为零时只报告警数。完整列出达标和超标日期，再在达标日期逐类报告新增与丢失。扫描新增不能抵消控制、下载或其他攻击的损失；“原检出全部保留”只有对应逐类丢失为零时成立。启动期和后续期都列出，不按最佳日期、种子或策略选择胜者。作者事件覆盖必须区分已开、未开与混合；只有至少两次未用于开发的独立扫描事件重复出现收益，才讨论跨事件复现。若实际只覆盖一次，就只报告一次。

若简单规则与本地阈值在未开时段稳定达标，它成为后续方法必须超过的强基线。若只有已开场景改善，或者新时段持续超标，本批候选停止作为主方法；不得在同一批结果上改窗口、改阈值再称前向验证。若组合达标但丢失特定类别，下一步只追踪这些丢失与同服务正常流的可用区别。只有教师具备学生当前缺失而可迁移的判别依据，才准备同容量硬标签/蒸馏对照。成本按实测吞吐、延迟与内存并列，不新增项目没有要求的硬限制。已有轻量化成果与负结果继续纳入毕设，本批次解决的是跨来源可用性和信息利用的实证问题。
