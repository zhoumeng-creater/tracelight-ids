1. 直接判断

目前“特征筛选＋树教师／小 MLP 蒸馏＋置信门控＋困难样本排序＋检测界面”的创新主张偏弱。现有证据不足以把它写成一套有显著优势的新算法。 本轮找到的直接近邻，比此前列出的通用 KD 与表格基础模型更接近当前设计，应据此调整论文定位和下一轮比较。

前五轮实验的价值是建立了可信基线、量化压缩代价，并暴露了可研究的失败现象。新的研究应解释并改善这些现象，同时回应最接近的已有方法。实验次数、最新模型名称、漂亮界面和多模块组合，都不能替代这个要求。

3. 最需要正面回应的已有成果

3.1 工作点感知蒸馏不是新的大概念

Evaluation-Oriented Knowledge Distillation for Deep Face Recognition，CVPR 2022 已经按 TPR／FPR 工作点识别关键关系，用排序迁移减小师生评价差距，并考虑小学生的表达能力。这直接削弱“围绕低 FPR 传递关键边界关系”的泛化新颖性。

人脸验证和二元 IDS 的样本单位、关系定义不同；可以研究任务适配与未解决机制，但更换应用不能自动构成新的学习方法。需要将其关键机制作为近邻对照，说明二分类适配究竟改变了什么，不能只比较普通 KD。

3.2 选择性轻量 IDS 与校准置信指导已有直接先例

DistillGuard，Computers & Security 2025 已有 Transformer 教师、轻学生、选择性知识传递与解释。其选择隐藏表示的机制与当前输出 gate 有差异，但“选择性 KD＋轻量 IDS”的大框架不能作为首创。

Adaptive Conformal Guidance for Learning under Uncertainty，ICLR 2026 利用校准预测集合表达不确定性、加权指导，并研究教师受噪声／变化影响的情况。因此“加一个校准不确定度门控”同样不足以获得新颖性。该方法的覆盖目标与本项目正常类误报率仍需区分。

3.3 基础模型蒸馏、OOF 与合成查询也已有近邻

Distillation of Tabular Foundation Models into Efficient Predictors，2026-10 预印本、结构化医疗表格蒸馏，ICML 2026 SD4H workshop 已直接研究 TFM 到高效模型的迁移。后者含 OOF、适应性温度与置信权重；前者在自己的设计中比较 full-context 和 OOF，不能只摘取支持某一协议的结果。

GEAR，2026-08 预印本 进一步使用合成协变量查询、真实数据与 OOF 锚定。换成 TFM 教师、增加合成数据、保留 OOF、部署时删除教师，都需要更具体的新问题和增量证据。

合法使用 train 标签的 full-context 软目标，不自动构成测试泄漏。当前研究坚持 OOF 的主要理由是要评估教师对未见训练行的错误、置信和门控选择；它是本研究问题对应的控制条件，不是所有蒸馏的唯一合法方案。

3.4 低误报迁移与安全级联也已有较近工作

Neyman-Pearson Classification under Both Null and Alternative Distributions Shift，ICLR 2026 同时处理正常与攻击两类条件分布的变化及负迁移。不能把“在漂移中保持误报预算”称为无人解决的问题。

近期 C-GUARD，Future Internet 2026 已涉及 OOF 救援模型、只翻转基线阴性、conformal gate 和显式新增 FP 预算，详见近邻报告。所以“按需升级到大模型并控制误报”的备线也需重新查明差异。对 SAFE-KD 等预印本，本轮还发现作者校准实现不足以直接推出所宣传的早退条件错误保证；有先例和保证成立同样需要分别审查。

6. 优先研究方向：把假设写到可被推翻的程度

A. 优先验证：压缩中的一侧错误迁移与正常组集中风险

具体问题：在同一预设校准 FPR 目标、相同小学生与推理成本下，普通 KD 的损失是否主要来自新增正常误报与丢失教师已检出的困难攻击？把这两类分歧分开建模，并限制少数关联组对训练尾部的支配，能否超过 EKD 适配、普通 KD＋pAUC 和无 KD 的同组权重训练？实际评价 FPR 分别报告，不假定相同校准目标产生相同测试风险。

它仍是待检验候选，不是本轮已经证明的新算法；EKD、AdaConG、pAUC／NP、group DRO 与类条件迁移理论都是必须回应的近邻。若具体机制与这些方法等价，应撤销相应原创主张。

将师生在各自冻结工作点的二元决策记为 T,S，P0,P1 分别表示同一评价总体的正常与攻击条件分布，在同一批样本上有直接计数恒等式：

FPRS=FPRT+P0(S=1,T=0)−P0(S=0,T=1), TPRS=TPRT−P1(S=0,T=1)+P1(S=1,T=0).

这只是分析工具，不称原创定理。它要求同时观察新增 FP、修复 FP、丢失 TP、挽救 TP，而不是仅看总体 KD loss 或置信均值。教师到学生的四格差异首先描述压缩，不自动说明 KD 的因果作用；须对 hard、matched-hard 和 KD 同时计算，并比较同初始化的配对差异。诊断必须使用实际 KD 教师；既有 RF→MLP 的差距不能代替 HGB 蒸馏的归因证据。若教师自身超预算，单纯压低学生新增 FP 也不能自动保证总 FPR。

待研究的改动应落实到以下三点，而不是先给算法起名：

  1. 信号对齐。 用合法训练范围内的教师工作点／边界余量定义迁移信息，比较概率软目标与关系／分歧信号；明确加权教师分数不等于部署后验。
  2. 集中度控制。 检查正常尾部由哪些重复／关联组主导，在相同更新与 pair 预算下比较逐行、组均衡、随机 pair 与标准 pAUC 训练。组均衡改变估计目标，须同时报告真实逐行 FPR，不能将两者混称。
  3. 困难攻击保护。 在 train 内定义有支持的攻击子集，检查教师正确检出的样本是否被压缩丢失；推理不能读取真实家族标签。与简单类／族重加权和同结构更好训练作对照。

特征重复组用于检查模式集中，会话关联组用于防泄漏与依赖分析，环境组用于迁移评价，三者不能互相替代。只有重复 hash 时，不主张会话独立或 mixture 稳健。组均衡也不同于最坏组约束或 group DRO。

建议的最小步骤：先筛教师→折内产生训练信号→固定学生与初始化／batch 顺序→比较已有方法和候选→独立正常校准→冻结阈值→新来源确认。需要教师工作点时，所用正常样本不得来自旧 test；训练内再划校准／交叉拟合的成本计入账本。分组 OOF 只能隔离已知关联；训练折彼此重叠，也不会使组内 flow 独立。独立统计单位及跨分区关联未经核验时，仅作经验结论。

最强击穿实验：候选与“hard＋pAUC＋同组权重”、EKD 关键机制适配采用相同学生与计算预算。如果优势消失，说明收益由已有目标或重加权解释，不能主张新的知识迁移机制。替换为同 gate 的真实标签目标仍同样有效时，也不能将收益归因于教师软信息。

B. 备选：语义字段族与派生捷径下的低误报压缩

具体问题：字段缩减造成的检测退化，是否与确定性派生字段、环境代理和罕见攻击所需信息有关？同字段数的简单 MI 为什么失败，条件信息选择或有约束的表示学习是否真正改善低 FPR 取舍？

最近邻为 FSNID、SAFE、表格遮盖预训练和 TabFSBench。先建立字段语义／派生关系字典，用固定其余字段的移除／恢复验证具体失效机制；再决定是否值得设计条件信息选择或语义整组遮盖。没有实际提取器时只测 CSV 编码／推理成本，不能用主观“昂贵字段”权重声称降低网络采集成本。

最强击穿实验：同字段数 MI、冗余控制、经审计可行的 FSNID、同架构随机遮盖、从头训练，使用相同数据与总预算。如果语义方案只改善重建 loss、不能保护低 FPR／困难家族，停止该路线。它在数据和工程上较可行，但目前的新颖性也需要进一步收窄。

C. 有数据条件的扩展：富输入教师到轻量流特征学生

4. 全文精读得到的关键区别

4.1 FSNID：不是另一种单变量 MI 排名，成本也不只是最终字段数

其核心比较去掉 Xi 前后的标签条件熵差，能够考虑其他字段已提供的信息，动机是冗余与协同；不能把普通 MI 或“多 seeds 取交集”称为等价方法。§5.3 的既有 split/80:20 和多类目标，与当前组隔离二分类的固定误报评价不同。Appendix C–E 给选择耗时及硬件：Table 1 的 UNSW vanilla/LSTM 为 748/71,501 秒，CIC-IDS17 为 13,565/508,093 秒；这是选择器开销，不是学生 CPU 延迟。近期对照准入时应先做 train-only 适配和选择预算核算，再保存选集及下游同协议分数。全文 §4/§5 与附录

4.2 Kitsune：低误报和廉价硬件本身早已是研究问题

Fig.9 已报告 TPR@FPR=0.001。§V/Table V/Fig.10 研究 Pi3B 与 i7-4790 单逻辑核的处理率；但该图用的是 KitNET 的基准输入，不可直接当原始抓包到告警的全链路性能。作者 Python README 也明确：要达到论文速度需 Cython/C++，普通 Python 版并非速度等价实现。对本项目的启示是，既要测小 MLP，也要测编码/转换/模型调用；仅参数减少、CSV 预测加速，不能宣称在线网络全链路加速。全文 §V、作者 Implementation Notes

4.3 CARAVAN：LLM 离线辅助有强先例，但不是无条件可信教师

§4.1 和 Appendix A 真正使用 GPT-4 对 UNSW 特征行标注，并生成可缓存规则；采用 few-shot 示例及字段解释。因此“LLM 不能读任何 CSV”不成立，“LLM 标注小模型”也非新概念。其作者同时承认公开数据可能进入 LLM 预训练；示例教师质量是先决条件。实验含人为窗口/新攻击到达的漂移设定、Taurus 硬件与 GPU 重训；不能转写为当前 UNSW 有真实时间流或冻结 1% 召回结论。本项目若用 LLM，应冻结版本、提示、示例来源、成本和标签错误审计，先比较规则/普通教师的增量价值。全文 §4.1/§5/Appendix A

§3.4 的协议问答和原始 header 输入，与当前统计字段差异根本；预训练含 UNSW 也是本项目不能忽略的重叠来源。论文通过按流划分及移除 IP/TCP 等字段揭示捷径，提示我们将同组重复、端点/时间代理、家族缺席作为检测对象，而不只换分类器。它的应用/网站识别、冻结/解冻 encoder 实验和浅层基线结果，不支持“某预训练模型在本项目不如 RF”的现成结论。全文、作者实现

6. 真正值得推进的研究问题与可执行边界

P1：二元蒸馏的低误报目标失配与可控纠正

问题：普通 KD 变化来自教师软信息，还是来自有效类别/样本权重变化？类平衡树教师的分数置信是否代表部署尾部的可靠性？哪些正常关联组贡献了误报？

可执行：保留现有同初始化/同 batch/同学生控制；普通 hard、精确 matched-hard、KD、gated-matched-hard、不同 gate 机制，逐损失记录。再按训练组检查 gate 错误 mass、teacher score 分布和 top-normal 集中度；已有 validation 只用于开发。若要改教师校准，应在训练组内部留出/交叉拟合，不能利用旧 test 反调。研究不要求新采集；确认性结论仍需未使用来源。不要把“score 离 0.5 很远”未经核验叫高置信概率。

贡献门槛：明确预测并检验一个失败机制；改善超过相同逐行权重控制，且低 FPR/家族/CPU 取舍有实际意义。若只有一组均值更高，没有机制和新确认，仍属于开发结果。

P2：按实际成本压缩字段，同时保护尾部和独立组

问题：最少字段与最少成本并不相同；某些便宜代理可能只记住采集环境，某些昂贵字段才保护稀有攻击。普通 MI/稳定性不能保证实用工作点。

可执行：先以字段字典区分直接字段、比率、时间/会话统计与派生字段族，明确当前只能测 CSV 预处理/推理成本，不能声称测到真实网络采集成本。在相同可见训练/选择分区，比较 MI、冗余控制和经审计可行的 FSNID；报告检测—编码维度—CPU p95—包大小的 Pareto。只有保留真实提取器并测量后，才能将目标升级为采集预算。若时序元数据不存在，先只评估 FSNID 非时序版本。

贡献门槛：证明哪种冗余/代理失效使简单策略不足，以固定其余因素的移除/恢复对照验证；不以“选到更稳定字段”单独作为检测收益。

P3：语义组自监督与蒸馏，先排除重建捷径

问题：字段间确定性派生关系可能使 MAE 只完成算术重建；随机遮盖学到的表示是否保护低 FPR 边界，而不只是重建误差更低？

可执行：现有 CSV 上 train-only 正常数据或明确定义的无标签 train；从头训练、相同预算随机遮盖、语义整组遮盖、去掉可直接回算的派生量，比较表示/下游/少标签效率。SAFE 是必须回应的直接先例，Lens/netFound 只提供语义设计动机，不能声称其复现。输入图化、预训练 epochs、额外数据、学生训练总成本均纳入控制。

贡献门槛：某个领域约束解决具体可复现问题，并在比简单 MLP/原始特征 novelty detector 更强的控制后仍有用；“把 CSV 变图片”本身不成立。

P4：包级富信息教师→仅 CSV 学生，条件具备后再做

问题：学生压缩能否利用额外包语义，而不把大模型带到部署？

可执行条件：有公共原始 PCAP、可靠标签及 packet/flow→CSV 一一映射；固定统一提取器和真实分组；只在 train 生成 OOF 富输入教师，比较相同学生下“CSV 教师 KD”与“包级教师 KD”。可以使用公开 PCAP，无需自行新抓包；但需要新数据处理、来源/预训练重叠审计，且当前 42/82 CSV 单独不能完成。netFound-small/v2 相比旧640M更值得先审小规模适配，但预训练 Arrow sampler 本身不提供本项目攻击 ground truth。

贡献门槛：增益来自额外信息而非更大的搜索/教师开销；部署学生 CPU 成本确实低；旧 final test 不再包装为未见确认集。这是投入较高、目前条件性路线，不应因为近期模型大而直接替换主线。

  2. 统一工作点而非仅列 FPR。 保存连续分数；开发阶段统一 validation 经验规则；确认阶段用独立 calibration 锁阈值再测未开封 test。报告正常数量、有效独立组、TP/FP、召回、每家族支持和区间。1% 是经验预算，不是分布漂移下保证。
  3. 同输入基线和富输入方法分表。 只看 CSV 的学生不能与看 PCAP/真实 host 图的模型直接解释为架构优劣；可另做信息增量研究。
  4. 成本至少分四项。 数据采集/流完结等待、提取/编码、模型 CPU 推理、训练/调参/教师辅助成本。GPU 特征提取＋小 RF 不能叫 CPU 全链路轻量；选择器 runtime 不能冒充推理 runtime。
  5. 复现身份逐级升级。 官方入口已核→锁 commit/checkpoint/许可证→schema 工程试验→不泄漏的训练适配→同协议原始分数/成本→独立复算→新来源确认。任一步没做就保留“未执行/未验证”。

1{sT>tkT}≠1{sS>tkS}.

§3.2 不要求师生相似度完全相同，而比较相对阈值的平滑排序计数：

LEKD=1N∑n‖∑kσ((sT,n−tkT)/τ)−∑kσ((sS,n−tkS)/τ)‖.

事实：作者代码 ekd.py（blob b5ac88c252801a9f708c63ecca965cb31cc57d19）使用师生各自 EMA anchors、温度 0.01、学生最难负关系 top-2000，最终是排序计数的 MSE。推断：论文的概念选择说明与实际“全部正关系＋hard negatives 上平滑计算”应分开；不能只照摘要写成显式只更新离散分歧集。适配单行 IDS 分数时，应公开关系→行分数的变换、阈值估计和梯度处理，称为 adapted EKD，不能声称原任务复现。论文 §3，关键代码

3.2 CVaR／PAUCI 的“精确”究竟指什么

R01 定理 1 的 OPAUC surrogate 可写为

minθ,u∈Rn+1n+∑i=1n+[ui+1βn−∑j=1n−(ℓ(fθ(xi+)−fθ(xj−))−ui)+].

事实：ui 是每个正样本的持续状态；SOPA 不是每个 batch 临时挑一批 hardest pairs。推断：应核对样本索引、采样、状态恢复、类条件归一化与 beta；正确实现才对应该目标。“精确”不表示替代损失等于 0-1 pAUC、非凸全局最优，或测试 FPR 自动受控。R01 定理 1、算法 1

R02／R03 还需要 a,b,γ,s,s′ 等辅助变量；R03 无选择近似的形式增加逐样本选择变量。推断：不能省略它们后沿用其无偏性或收敛结论。R03 主要实验的 FPR 区间较宽，不能由论文表格直接推出 beta=0.01 的数值稳定性。R03 §IV–V、VII

单点召回与区间面积也不同：优化 ∫00.01TPR(v)dv 不能单独证明 TPR(0.01) 提升；应共同报告区间指标及冻结阈值的单点表现。

3.3 NP 迁移不等于“阈值迁移＋蒸馏”

R11 的基本问题是

minh∈HRφ,μ1,T(h)s.t.Rφ,μ0,T(h)≤α.

事实：程序利用四类有标签样本 (0,S),(1,S),(0,T),(1,T)，先对齐 source 的可行约束集，再利用 source 攻击数据减少 Type-II 风险；主要界含样本误差项。计算保证还要求凸性、梯度和有界性等条件。推断：不能宣称无 target 标签、任意非凸小 MLP、相关 flow、固定 beta=0.01 下都继承这些保证。其 transfer modulus 也不是可以直接拿 teacher confidence 代替的量。R11 §3–5

R04 的非参数阈值规则基于独立正常校准分数的次序统计量；在相应假设下，给定目标 beta 和违反概率 delta，最小可行正常样本量为

n0≥⌈logδlog(1−β)⌉.

beta=0.01、delta=0.05 时为 299；这是最低可行性，远非良好功效或精确估计所需样本量。多组同时保证需分配 delta；把同一会话的上千条 flow 当成上千个独立样本不满足这个推导。R04 §2、Proposition 1

3.4 AdaConG 的不确定度与我们所需风险不是一个量

R07 §3 使用代表 target 的独立校准集构造 C(x)，再令

u(x)=g(|C(x)|),w(x)=exp(−κu(x)),L=λtLt+w(x)λgLg.

事实：分类实例可用集合大小映射；KD 实验以受噪声影响的 CIFAR-100 教师评价。推断：二分类集合大小的分辨率很低；空集合处理也需明确。集合覆盖是边际事件，不是“教师在正常 1% 尾部正确”，更不是“此样本 KD 梯度必然有益”。因此 CP gate 必须与简单 entropy／confidence、correctness、同平均权重对照，而不能将“有校准”当作算法收益的解释。R07 §3–4

R14 进一步说明分布变化可破坏覆盖；其界需 score 分布条件，应用亦有 source-mixture 假设。推断：引入 conformal 一词不会消除依赖、未知 concept shift 或校准集不具代表性的问题。R14 §3–5

事实：作者 safe_exit.py 的校准函数对 1−py(x) 取 split-CP 分位数 q；推断时以 maxcpc(x)≥1−q 直接输出 argmax。代码 blob 为 02048f261d8d6ddbd8746929c6de2c004a606800。作者实现

审查反例，不是新实验：设所有样本 max probability 都是 0.6，其中 90% 预测正确、10% 预测错误，则 py 分别为 0.6、0.4。delta=0.05、大校准样本下，q 接近 0.6，所有样本满足早退条件，selective error 约 0.10。CP 的集合覆盖仍可能成立，但单标签早退风险不满足 0.05。

3.6 TFM 蒸馏文献存在实际协议分歧

事实：R08 §3.1 实际比较 FC 与 OOF，报告其设计集上 FC＋teacher-only 更好；R09 主张 OOF 避免 self-labeling，并有 adaptive temperature／confidence weight。推断：FC 使用 train 标签不自动构成 test 泄漏；它可能是一种有效的训练监督。但如果要根据教师“是否正确／有多可信”决定门控，就不能把教师已在上下文见过该行标签的预测当成样本外可靠性证据。我们的 group-OOF 要求应说明针对后一个识别目标，而非宣称所有 FC 方法无效。R08 §3.1，R09 §3

公平的协议对照应至少在一个固定教师／学生组合上比较 FC 普通 KD 与 OOF 普通 KD，保持学生训练预算和 query 数量一致，报告 context 体量与类别覆盖（OOF 可用上下文通常更少）。若另控制相同 context 预算，应说明抽样方式。用独立开发分区判断学生泛化，而不是以 FC 教师在已见行上的正确率证明其门控可靠。该对照只用于识别协议效应，不扩成所有教师／损失的全组合。

R10 的生成保真度项提示更多查询不保证更多真实信息。推断：不能把不可能的网络字段组合当作有效困难攻击；生成查询量和上下文成本必须计入资源预算。R10 §2–3

4. 对当前实现的数学定位

本节是当前代码的只读事实与审查推断，不更改现有 pilot。

  • src/ids/research_kd.py:229 的 correctness 用 0.5 分界，confidence 为 |2q−1|；这与正常 99% 分位点没有直接关系。
  • src/ids/research_kd.py:145 选择 batch 内最高分 normal 的 10%，再受 32 个 normal、64 个 attack、2048 对上限影响；attack 又按最低分选取。实际尾部比例随 batch 组成及上限变化。
  • src/ids/research_kd.py:124 对已选样本内 group 赋 1/(Gng) 权重；两类权重乘积用于 pair loss。它表示选中组等权，不能代替 population per-flow 风险、完整 group-DRO 或相关样本统计处理。
  • configs/research-v2.yaml:5 的评价目标是 0.01；与训练 10% capped mining 的错配真实存在。把 normal_fraction 改成 0.01 也不足以自动获得全分布分位数或 R01 的目标。
  • gated_matched_hard 已控制 gate 选择和有效权重，correct_only／confidence_only 已拆分机制。这些是有价值的识别控制，应保留，不应因为文献推翻首创性而抹去。

因此当前准确名称是：基于教师正确性与置信度门控的 KD，加有上限的 batch hard-pair 平滑排序正则。不应叫精确 pAUC、NP 学习、可证明低 FPR 迁移、分布漂移稳健算法。

4.1 风险迁移缺少的连接

令冻结决策 hT,hS∈{0,1}，P0,P1 为相同评价总体的正常／攻击条件分布。直接集合包含给出

FPRS≤FPRT+P0(hS=1,hT=0)⏟d0,TPRS≥TPRT−P1(hS=0,hT=1)⏟d1.

这是简单分解，不是新定理，也不是创新证明。若想把它变成有用合约，至少还缺：

  1. 教师在目标总体的可靠 FPR 上界；总体 AUC 更强不够。
  2. 学生新增正常报警概率 d0 的可控预算；若教师已耗尽 1%，不能再无预算地允许新增 FP。
  3. 从训练 surrogate 到一侧离散分歧的连接，以及有限样本估计误差。
  4. 模型、阈值、路由选择之后的独立校准；反复使用同一校准集挑最佳方案会引入选择偏差。
  5. 明确的独立统计单位、目标 mixture、未知攻击范围；当前 group loss 不提供这些条件。

R05 已学习相对阈值分歧；R11 已研究 NP 迁移。因此即使补出上述链条，也必须检查它相对成熟受约束学习到底新增了什么，而非把简单上界命名成新框架。

4.2 correlated flow、group 和 mixture shift

设正常总体由环境 g 混合：

FPRQ=∑gπQ,g0FPRg.

推断：训练混合的平均 FPR≤beta 不保证正常环境比例变化后仍≤beta；所有组都≤beta 则对这些组的任意混合成立，但这只是凸组合性质。等权平均各组损失并不约束最差组。纯攻击先验变化、正常条件分布不变时，FPR 本身不变；不能与正常子群混合变化混为一谈。

会话／近重复组、攻击家族、部署环境是三种不同分组：前者用于防泄漏／描述依赖，家族用于覆盖与召回，环境用于迁移风险。三者不能用同一个 group ID 直接替代。分组切分是必要设计步骤，但并不让组内 flow 突然 IID。可以报告 cluster bootstrap 的经验不确定度，不能因此声称分布无关 NP 保证。若改以会话最大分数控制“一个会话是否报警”，控制的已是另一单位的风险。

在正常／攻击条件分布都可任意变化、又没有目标标签或结构假设时，不应承诺固定 FPR 与高召回同时保持；R11 的有标签 target、R14 的 mixture／score 条件必须显式列出。

5. 最少关键对照与资源边界

5.1 先做诊断，不立即扩展真实训练矩阵

对已有缓存预测可先检查：教师 TPR@低 FPR、师生一侧分歧、各正常环境 FPR、困难攻击家族召回、低尾部教师错误；若教师在目标工作点没有优势，停止把 TFM 强教师当作前提。严格保留最终 test，诊断只使用授权开发分区。

若进入新 pilot，低 FPR 蒸馏最少应有：同容量 hard＋成熟低 FPR 目标、普通 KD、adapted EKD、所提规则。四项共用教师、训练步数、正类权重、数据与相同阈值协议；另加一个与所提规则同样本量／总权重的随机选择控制，排除仅靠 hard mining 或重加权获益。现有 matched-hard 控制可复用其识别思想，不能以换名字省略。

只选一个教师、一个学生、一个环境、三个种子作证伪 pilot；最多约 15 个学生 fit，而不是把教师×损失×字段×门控×seed 变成全组合。只有关键假设成立后才冻结、扩展双环境五种子。这里是预算建议，本轮未启动这些训练。

6. 仍值得验证的三个窄问题

Q1（优先主线）：小容量学生在正常 mixture 改变时，能否保留教师可量化的一侧风险预算？

待验证假设：在固定教师查询预算与小学生容量下，显式区分“继承教师漏报”与“新增正常报警”，再针对预设正常环境约束一侧分歧，是否比 EKD 的阈值关系匹配、普通 CVaR-KD 更稳定？

最强近邻：R05 的工作点排序、R11 的双类条件 NP 迁移、R04 的阈值合约；不能称首次风险迁移。可形成差异的部分只能是固定部署容量、可核依赖结构与具体风险预算如何联合处理。若只把各组 loss 等权，问题没有被解决。

最小击穿实验：先用同一批开发预测固定若干正常环境的比例变化，仅改变 mixture、不重训，检查 pooled 校准是否失效；再比较 hard-CVaR、普通 KD、adapted EKD、候选方法。在同风险上界／同校准预算下比较召回，而非允许候选多花 FP。若普通 groupwise 校准已经解释全部收益，或候选在 IID 条件下都不胜 EKD，就下调为协议／适配贡献。

数据与失败条件：需要真实环境／会话信息、独立正常单位及足够各组样本；缺少这些时不能承诺保证。若保证仅对已见组成立，应明确对新环境无保证。固定 MLP 并不满足 R11 的全部凸性计算假设，不能直接沿用其定理。

Q2（资源受限时的窄备选问题）：固定教师查询额度下，尾部目标能否指导“问哪些样本”？

最强近邻：R08 的查询覆盖、R10 的生成量／保真度、R05 的 critical relations；另外仍需继续排除 active distillation 的直接近邻，本次搜索没有证明此处空白。

最小击穿实验：同一教师、context、查询额度、训练更新数，比较 uniform random、普通 uncertainty、EKD critical-region 和目标风险导向选择。用完整开发总体评价，禁止只在被选样本上计算优势。先使用真实 train 行，避免同时引入生成器；若只比“问全量教师”省成本，却不胜等预算随机查询，就不保留算法主张。

这是教师成本过高时才启动的资源问题；不与 Q1 同时扩展成第二套大矩阵。即使有效，贡献也应限定为特定预算下的选择规则及证据。

Q3（部署备线）：只用便宜信息作升级决策，能否在整体正常风险约束下获得真实成本收益？

最强近邻：R12 的质量—成本最优路由、R13 的动态获取、R16 的安全任务 rescue；R15 说明“KD＋风险早退”概念也已有。不能以级联、困难样本、conformal 命名宣称创新。

可能的差异：在调用辅助模型／昂贵字段之前，用当前可得字段预测一侧纠错收益，联合约束整体正常 FPR 与实际成本；对正常 mixture 变化明确失效／回退条件。它仍可能只是成熟约束决策的 IDS 适配，需由实验而非措辞决定贡献级别。

最小击穿实验：先在已有模型预测上计算互补性与 oracle 上界，无需新训练；然后比较全量小模型、全量 HGB、同覆盖率随机升级、简单 confidence 升级、收益升级。若存在 rescue，还必须加入 validation FP-matched 的单阈值放宽对照，防止把增加 FP 的收益误认为算法收益。各策略使用统一整体校准、相同信息可用性和实测成本。若扣除 router／字段成本后不胜简单策略，停止。

当前建议：先用 Q1 的最小反证步骤决定是否存在值得迁移的低 FPR 信息；Q3 只在模型错误互补且可测真实成本时作部署备线。Q2 仅作为教师查询昂贵时的收缩方案。 这三项都是待验证问题，不是三项已经成立的创新点；新实验证据出现前，应主动下调原有“correctness-confidence＋ranking”首创主张。

3. 六个需要落实到实验的阅读结论

3.1 TabM：不能用一个 tiny 配置代表前沿对照

原文 §3.3／§3.5：训练分别计算成员损失，推理平均概率，早停应依据集成表现。当前适配器已改用集成概率的 weighted BCE 选轮；这属于修复复现偏差。论文附录搜索含 k=32 和更宽网络，现有 k=8、width=32 是低成本配置。需要另列合理调优的质量点，并比较训练较大集成后裁剪成员，成本与结果均实测。当前没有新协议真实训练结果。

3.2 ModernNCA：模型文件之外还有参考样本

原文 §3 的预测通过学习后的邻域关系聚合标签，训练可对参考样本随机抽取。它提示：UNSW／CIC 的重复模式、局部密度与异常组值得检查。但检索方法需要保存或产生参考表示，CPU 吞吐、启动内存和支持集规模都必须计入。若仅比较网络参数，容易把存储转移到支持集后误称压缩。此方法先作机制参照，避免第一批增加昂贵全量邻域计算。

3.3 TabICLv2：基础模型上下文也是训练资料

目标感知表示使某些预计算结果依赖上下文标签。OOF 不仅要把预测对象移出 fit，还须保证编码、上下文、缓存都来自该折训练侧。百万行、50GB 级论文能力不等于本项目 24GB 显存可用；CIC 约 128 万训练行，需要先做折内上下文规模与攻击支持检查。它是首选候选之一，理由是机制、输入和公开工件有较清楚对应，不是已证实比 HGB 强。

3.4 Mitra-v2：较新成绩的成本口径必须拆开

原文 §3.1、§3.6、§5 明确，headline 系统使用短微调及 8 折 bagging；不是零样本、单模型或已证明 Pareto 支配。作者也披露领先组区间重叠、预测时间未单独仪表化，以及多项预训练变化未完全分解。若选为教师，应先比较冻结前向与受限微调，记录所有 bag 子模型、上下文、显存与 OOF 成本；不能直接将其榜单名次作为选教师依据。

3.5 ConTextTab／LimiX-2：语义编码与遮盖不是空白

ConTextTab 已利用列名和文本语义；LimiX-2 研究上下文条件遮盖及联合表格建模。因此“给字段加语义”“遮住字段自监督”“加行列注意力”都需要更具体的差异。对网络统计量，应先证明语义分组比随机分组和派生字段泄漏控制更有效。没有这一步，换一个有语义名称的模块仍不足以构成创新。

3.6 BeyondArena：迁移检验比换一个榜首更关键

该工作把分组和时间划分纳入基准，强调不能把 IID 表格的结论直接推广到非 IID 任务。适配到本项目，应保留网络会话／采集单元的隔离、重复模式敏感性以及可靠时间元数据。按 CSV 行序构造“未来”不成立；合成组比例变化只能称受控压力测试。基础模型同样需要接受这些检查。

5. 超出首页宣传的具体核验

以下核验直接影响设计选择，均为文档/源码阅读证据，未执行相应项目。

  1. Suricata：关联键与判定层分开。 EVE 支持 flow_id、可选 Community ID 与抓包文件信息，alert action 与引擎最终 verdict 有不同语义。可借鉴为“记录、规则命中、模型分数、阈值、处置”分别存字段；不能只用红色状态块替代证据。EVE 定义、8.0.8 配置。
  2. Zeek：字段相同不等于定义相同。 Conn::Info 注释指出 duration 不计部分结束处无有效负载的 TCP 包，例如最终 ACK；字节还受序列号等语义影响。把此 duration 或 bytes 直接改名为 CIC 列存在训练/部署不一致风险。9.0.1 源码 Info。
  3. Wazuh：关联窗口有范围。 frequency、timeframe、same_srcip、same_field 定义具体计数规则；global_frequency 文档明确是 manager 范围，不是整个 cluster。若做流告警聚合，也应记录窗口、实体键和作用域，不能把聚合数当独立检测数。规则语法。
  4. Arkime：元数据存在不保证包仍在。 API 可按会话 ID/查询导出 PCAP，源码在 SPI 仍存在但 PCAP 文件不可用时返回相应错误，并按原始 packet position 读取/重组。界面必须表现保留期和缺证据状态。API、6.9.1 apiSessions.js。
  5. NFStream 与 CICFlowMeter：采集契约必须审计。 NFStream 明列 active/idle timeout、记账层次、毫秒时间字段、插件 on_init/on_update/on_expire 和早期/流结束统计；CICFlowMeter 说明 duration 为微秒、首包定方向。流结束才能得到的字段不能宣传首包检测；NFStream application_confidence 是 DPI 判别语义，不是攻击置信度。NFStream API、CIC 作者说明。
  6. River：在线验证必须约束时序。 progressive_val_score 实现先预测，再在相应标签可用时学习；支持 moment/delay 和时间/内存测量。没有时间、标签延迟和更新策略的独立定义，仅增加一个流式循环不会形成可信在线学习研究。固定版实现。
  7. PyOD：异常分数与 FPR 校准是两层。 BaseDetector 约定较大 score 更异常，contamination 用训练分数的分位数产生阈值；它表达训练异常比例假设，不能替代本项目在独立正常校准样本上的误报预算。当前文档还已有更多生命周期/置信与组合接口，不能把这些普通接口包装为首创。固定版 BaseDetector。
  8. ADBench：跑通脚本可能改变任务。 RunPipeline 区分异常标签的比例/数量，默认含 generate_duplicates=True、小样本阈值 1000 等数据生成选项。本项目不应原样调用其默认数据生成后，把复制样本当新独立样本或与既有完整族支持结果比较。固定版 run.py。
  9. Vectra：商业界面也明确承认证据不完整。 Detection PCAP 由滚动缓冲关联，不保证完整流；检测迟、负载高或数据源为日志时可缺失。我们应同样把“不可用/未采集/已过期/不适用”作为明确状态。官方 PCAP 文档。
  10. Corelight：可借鉴的是联系，不是营销吞吐。 Smart PCAP 文档具体给出日志里的 spcap.url、按 Zeek/Suricata 事件选择包和订阅模块边界；这说明“告警可追溯到包”已有成熟工程实现，CSV 字段展示不能等价替代。Smart PCAP。

P0：先补研究成立所需的契约与比较。 明确模型输入的原始字段定义、单位、方向、流终止/超时、缺失语义和特征可用时刻；用现有代码与数据证据逐项核，而不是先挑一个提取器接上。参考 TabArena/ADBench 的预算与标签条件管理，把研究 v2 的机制对照、共同训练/选择预算、失败结果和成本完整呈现。真实 v2 训练按实验室 4090D 路线进行；本机继续代码、单测和 synthetic 验证。旧 test 已开，不能把据此优化的新模型再报为独立确认，见 STAGE6_PROTOCOL。

P1：完善已有离线系统的可信使用闭环。 优先补输入不兼容提示、数据/模型/阈值版本、开发/确认状态、完整总量与抽样展示的区别、运行失败与证据缺失状态；用真实模型输出支持比较。此类交付属于可复现性和工程贡献，不能写成新的分类算法。若要宣称端到端可部署，再定义并测量包含读取/解析/预处理/推理的独立成本口径。

P2：有需求与数据后，只验证一条采集路线。 NFStream 的生命周期契约较清晰，可先做字段可生成性审查；若现有 CIC/UNSW 特征无法忠实生成，就缩小支持范围或重新定义并独立验证任务，不能填零/重命名强行兼容。随后才考虑一条 PCAP → 特征 → 固定模型 → 事件 → 可检查证据的最小闭环。这里的价值是部署验证，不应冒充特征提取或 NDR 产品层面的发明。

暂不做： 不安装全部工具、不重建 Security Onion/商业 NDR、不增加没有数据支持的攻击链/拓扑、不自动阻断真实网络、不为“前沿”堆叠在线学习或 agent、不用更多 run 数掩盖研究假设不清。MLflow/完整 SOC 集成应由实际协作需求触发，当前 manifest/哈希/结果表能满足的要求不必立刻增加服务负担。

可提交的贡献边界：新的可检验损失/选择机制及其归因属于候选方法贡献；严格低 FPR 与困难族实验、负结果、资源权衡属于实证贡献；schema 审计、来源封存、CPU 推理与可信界面属于工程贡献。它们都可能有价值，但标题、摘要和答辩应分别说明，不能互相充当证据。
