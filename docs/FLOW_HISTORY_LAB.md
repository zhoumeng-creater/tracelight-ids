# 第十九轮实验室运行指南

单条流记录很难分开部分扫描与正常连接。本批检验同一源地址过去一分钟的连接行为能否改善排序，并在正常误报预算 1% 下提高检出。使用 NF-ToN-IoT-v3 和上轮实验室已有的 core 环境。发布标签为 `flow-history-lab-v1`。

## 在实验室启动

在存有第十七轮原始 run 的 Windows 实验机执行。使用新目录，首次运行自动完成合成预检、两套数据准备、训练、评价、部署计时和打包。

```powershell
Set-Location -LiteralPath 'D:\zhoumeng\Graduate'
git clone --branch flow-history-lab-v1 --single-branch https://github.com/zhoumeng-creater/tracelight-ids.git tracelight-flow-history
if ($LASTEXITCODE -ne 0) { throw 'Clone failed' }
Set-Location -LiteralPath 'D:\zhoumeng\Graduate\tracelight-flow-history'
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\RUN_FLOW_HISTORY.ps1
```

入口默认使用 `D:\zhoumeng\Graduate\venvs\tracelight-route-core\Scripts\python.exe`、`tracelight-route-batch\local\route-batch-20261108\run` 和新 checkout 的 `local\flow-history-r19`。CPU 预算按物理核数自动设置，上限 24；本实验机对应 24 核，GPU 为 CUDA 设备 0。共享机器可在首次运行时用 `-Threads` 指定可用核数。沿用已安装的 PyTorch、scikit-learn、PyArrow 等，无需下载新的预训练权重。原始数据位置从既有协议读取，原 CSV 已移动时可指定 `-Source '实际路径\NF-ToN-IoT-v3.csv'` 或官方 ZIP。使用 ZIP 且缺少已解压 CSV 时，会在本批目录展开约 5.30 GB 的 CSV。旧八份角色文件须可按实验室第十七轮记录的位置读取。

中断后在同一 checkout 重新执行同一条脚本命令，参数保持一致。已完成阶段按 SHA 复用，模型拟合、评分、不同线程的成本测量分别保存。历史阶段中断后重新核验源和抽样行，复用经校验的已完成分片。一次运行由一个协调进程持有锁，Windows Job 在协调进程退出时回收子进程。仅检查环境和合成测试可运行 `.\scripts\RUN_FLOW_HISTORY.ps1 -CheckOnly`。

完成后回传 `local\flow-history-r19\` 下**同一次执行**的 `flow-history-results-*.zip` 和同名 `.zip.sha256.json`。只需此次增量包。先读 `last_invocation.json` 和 `summary.json`；失败也尽量打包错误与已经完成的阶段。模型与逐行分数在包内，原始全量流、排序分片和计时片段留在实验机。

## 为什么做这批

第十七轮已打开的新通信组中，完整 KV 对 29,003 条正常流量误报 274 条，实测 1% 最多容纳 290 条。主要混淆组有 544 条扫描和 80 条正常记录，完整 KV 没有对其中任何一条告警。如果整组都报警，要继续守住 1%，还须从其他位置消除至少 64 个已有误报。旧开发集允许 118 个正常误报，完整 KV 恰好用了 118 个。这两个数字决定了本轮必须同时查看扫描与正常的逐行得失。[已归档分数的复算](flow_history_20261111/development_evidence.json)

原始文件的两个 IP 和流起止时间可以按记录号回溯。先前已逐行核对旧 P/C/E 的 33,192 条记录及其 48 个字段。NF-v3 的流内包间隔与跨流历史是两种信息。作者研究了 NetFlow 的时间特征，MAWIFlow 作者另提供跨时间的评价配置；这些工作给出观察和验证思路，60 秒是本项目事先固定的尺度。本次检验属于已有方法的对照。[本项目元数据核验](research_alignment_20261108/scanning_mechanism/data_semantics.md) · [NF-v3 作者原文](https://arxiv.org/html/2503.04404v3) · [MAWIFlow 作者实验配置](https://github.com/TheLurps/public-ids-research/blob/7260ec0cd56964314b1761a6bf7ba32c3bfb5042/experiments.md)

## 两套评价各回答什么

| 数据 | 训练与阈值 | 可以回答 |
|---|---|---|
| 旧开发 P/C/E | 原 8,192 条 P、5,000 条正常 C、20,000 条 E。读回完整 KV 和 QCOC 的原始分数，以原 SHA 和行身份核对。 | 旧样本与标签预算相同，新增观测能否超过同学习器的对照，以及与已有完整 KV、QCOC 各差多少。 |
| 同源的向前时间检验 | 重新训练一套模型。按 UTC 的**完成时间**，P 为 2019-04-23 00:00 至 16:00，C 为 23 日 16:00 至 24 日 00:00，E 为 24 日 00:00 至 30 日 00:00。每段前 60 秒只作历史预热。P 两类各最多 4,096，C 正常最多 10,000，E 最多 50,000，E 抽取不看标签。 | 在排除八份已打开角色表通信组后，早时段学到的判别规律能否用于后时段的新通信组。P/C/E 之间也按通信组隔离。 |

日期依据旧 E 的已知分布选定。旧 E 的 1,078 条扫描按流开始日期计，4 月 23 日有 221 条、24 日有 857 条。新时间样本仍来自同一批采集，主机可重现。通信组排除规则作用于评分和训练的目标行，历史仍可使用该时刻之前可观察到的所有未标注流。前向队列在数据准备前就已固定，不按开发成绩或无拟合诊断选臂。时间段样本不足会报告实际计数；若缺少评价条件，不移动日期或更换种子。前向结果与旧开发结果分别解释。

历史按**源 IP 和 IP 协议**分组。从全部 27,520,260 条原始流计算 `[当前流完成时刻 − 60 秒, 当前完成时刻)` 的已完成流数、不同目的 IP 数、不同目的端口数、无返回包的流所占比例。同毫秒先取历史后更新，使用这批记录之前的状态。空历史四项取零。源/目的 IP、绝对时间、攻击标签和族名均不进入模型。计数采用“流结束时记录即可取得”的离线假设，生产导出器到达延迟需另测。

## 固定比较

每套数据最多 5 个拟合，两套共 10 个。下载、训练或重新评价第十七轮的 TabM 均不在队列内。

| 学习器 | 输入 | 训练与作用 |
|---|---|---|
| 小型 MLP | 原 48 字段；48 加四个恒零槽；48 加四个真实历史值 | GPU。两层 128/64、固定 seed、80 轮、批量 512、BCE。同宽两臂的初值及批次顺序一致，预处理仅用 P。恒零槽控制输入宽度的影响。 |
| 直方图梯度提升树 HGB | 原 48 字段；48 加四个真实历史值 | 多核 CPU。沿用项目树基线的 200 轮、31 叶、学习率 0.1；按固定预算训完。它提供一种可以学习非线性规则的现成方法。 |

先保存各数据角色的无拟合诊断，即使训练中断也可以查看。它统计已登记的 47 字段 SYN 模式中，四项历史量各自如何给扫描和正常流排序，原有的完全相同输入在加入历史后还剩多少相反标签。单例增多能让精确碰撞消失，能否泛化仍须看前向得分。

检测按每臂自己的正常 C 登记阈值，升序秩取 `ceil((n+1) × 0.99)`，严格大于才告警。固定工作点外，另报所有族的计数、总体与扫描对正常在 0–1% 误报区间的归一化 pAUC、主要混淆组的排序与误报、逐行配对得失、各源主机和日期的分项。

**检测候选条件**为前向 E 的实际误报率不超过 1%，相对同学习器原 48 字段的正常误报不增、总检出不减、扫描检出和扫描低误报 pAUC 均提高。MLP 还须同时胜过同宽的恒零槽对照。条件是本轮筛选口径，少量样本的变化仍按实际计数解释。主混淆组另报扫描增加是否伴随组内正常误报增加；缺少相应样本时记不可评价。旧开发集超过较弱对照、前向切分失败或回放不等价的成本数字都不能单独支持部署。没有预设包体、内存或毫秒硬线；检测过关后看实际包、状态内存、单行 p95 与吞吐的取舍。

## 实验室算力与成本口径

- 全源流用多核解析和分片重放，分片按源/协议保持顺序。登记磁盘中间量、排序与重放时间、并行工作量、活动窗口峰值和整个进程的内存。
- MLP 拟合及批量评分用 CUDA，HGB 使用多核 CPU，两条训练队列可以同时运行。MLP 用实际模型验证 GPU 前向，并在 P 上实测推理批量，保存计时、显存和最终选择。GPU 不可用时会记录该臂失败；其他可独立完成的计算仍保留。
- 两条训练队列都退出后，才逐项启动独立 CPU 成本进程。每个模型都测单线程和设定的多线程两档，比较 CPU 与原评分在固定、重新登记阈值下的告警。预先算好历史列时只计模型输入变换及评分。
- 另对原 48 和真实 52 的 MLP、HGB 测量**带历史状态的逐流成本**。用全源中流量最多的一个源/协议键，取有预热的约 512 条连续流并完整保留同毫秒并列。核对在线更新结果与独立离线计算的四项历史、分数与告警。记录从已按完成时间送达的数值流记录到告警的 p95、吞吐、RSS；采集器、网络和上游排序耗时单列在测量范围外。单键压力片段只能反映该片段，多主机状态另看全源审计。

| 回传文件 | 阅读重点 |
|---|---|
| `summary.json`、`last_invocation.json` | 完成度、前向可评价性、达标条件、实际效果和不同设备的部署成本。 |
| `evidence/inputs/` | 来源/划分、历史重放、原始输入碰撞与加入历史后的对照、抽样行历史。 |
| `evidence/{development,forward}/<arm>/` | 拟合记录、C/E 分数、指标、按主机/日期分项、逐行 CPU 重放和计时。 |
| `models/`、`resources-*.csv` | 新拟合的轻量模型，以及各阶段实测 CPU、GPU 利用率、进程树内存、显存占用。 |

若历史分布仍高度重叠且两种学习器在后时段均无收益，就结束这四项观测的路线，保留已有 KV/QCOC/TabM 的效果与成本比较。若历史量本身能分开混淆记录，而告警仍失败，先核对被推高的正常记录和各族得失，再确定需要改进的训练目标。只有检测增益在后时段保留、并且实际部署成本可接受，才值得把这个方案接入毕业设计的检测与结果导出流程。

## 与毕业设计的关系

第四轮已在 UNSW 和 Improved CICIDS2017 上比较随机森林、小型 MLP 与原始字段筛选。以 CIC 的三种子均值为例，小型 MLP 用互信息筛到 24 个字段后，模型从 26,220 降到 14,752 字节，单条预处理加预测 p95 从 7.011 降到 2.276 ms，攻击召回从 99.3677% 升到 99.6446%，实测正常误报率均为 0.9999%。在 UNSW 上，同样筛选后召回从 85.1525% 降至 80.9816%。这两组结果可用于论文和演示中的轻量化比较。第十九轮检验历史观测能否减少 NF-ToN-IoT-v3 上的扫描漏检。判断增加历史是否划算，须把额外的状态内存和逐流处理时间一起计入。

## 发布前验证

在本地 Windows 的 RTX 4050 Laptop GPU 和多核 CPU 上，分别用两套合成数据跑过全部五种配置，共 10 次拟合和 10 次评分。两条队列同时执行，第二次启动复用了全部 20 个已完成阶段。逐流检查使用 480 条合成流预热、513 条合成流计时，核对了四个历史量、分数与告警。真实数据的检出和 4090D 实验室的耗时由本批回传。[验证清单](flow_history_20261111/validation.json) · [双队列记录](flow_history_20261111/queue_smoke.json)
