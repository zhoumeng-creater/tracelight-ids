# 第二十五轮就绪修复展示数据

此页面在原有流量回放中加入已封存结果。新增区展示汇总统计，不加载模型，不生成新告警；原有八分钟校准回放仍使用此前核验的真实逐行记录。

## 来源

冻结实验：`readiness-replay-lab-v1`，提交 `6d303df3d00f5abb788af4dcd12854d458e55900`。

本地归档位于项目的 `实验归档/20261115_第二十五轮就绪修复`。导出依据为：

- `results/evidence/all-budget.csv.gz` 和 `all-paired.csv.gz`：由独立效果复核逐项验证的预算、家族配对汇总。导出前同时核对独立复核 JSON 中的 SHA-256 和回传包清单。
- `复核/效果/42来源就绪边界.csv`：严格先前参考记录、就绪原因和边界。
- `results/evidence/evaluation/<source>/hgb/events.csv.gz`：仅抽取当前来源的作者事件 ID 与家族，按 ID 去重；不累加策略、阶段或模型重复项。文件逐一核对回传清单。
- `复核/资源/resource_audit.json`：进程数、实测 CPU 核数、进程树 RSS、主调用耗时及实际模型调用计数。

页面显示输入摘要，全部输入摘要保存在 `r25-data.js`。数据不含端点地址、流 UID、完整连续分数或全部逐行决策。

## 展示范围与指标

覆盖 42 个来源日期、5 个冻结模型组。显示旧八字段、旧质量追加、端口计数本地阈值、质量与计数本地阈值四项策略；原实验另有其他策略，完整结果保留在归档。比较基线可以选择旧八字段、旧质量追加或修复前同策略。

误报率以该来源该 UTC 日全部已观测记录中的正常标签为分母；预算为 `floor(normal / 100)`。没有正常标签时显示“无法核算”，不判为零误报达标。启动期与就绪后均计入全日；两段划分采用修复后就绪边界。旧固定阈值策略不因本地参考就绪而更改阈值。

逐类表显示总记录、基线检出、当前检出、新增、丢失和剩余漏检。新增/丢失来自逐条配对汇总，不能由两个总检出数相减替代。导出时验证 `after - before == gained - lost`、正常配对与预算一致、基线误报一致、全部家族分母之和等于来源记录数。

攻击表可切换“本日全部攻击”和“仅原未开攻击”；后者取原汇总 `exposure` 为 `forward_unopened`、`earlier_transfer_unopened` 或 `forward_same_testbed` 的记录。误报资格始终按该日全部正常标签计算。原未开子集不另显示事件 ID 数，因为当前事件汇总未按此子集分拆。例：SFC 4月14日 MLP29 主策略全部其他攻击检出97,138条，其中原未开其他攻击67,853条，不能互换。

未解决标签单列，不计入正常或攻击分母。当前没有记录的类别不列为“全检出”。作者事件 ID 数不代表独立企业环境，跨日延续也不能直接当成独立攻击实现。

部分日期在原实验中是未开的前向确认，修复时已经打开；页面保留这一历史角色，不将修复回放称作新的盲测。达标日的检测收益与超标日的原始检出分别呈现。

本轮复用已有分数，训练和模型前向均为零。设备级 GPU 利用率不能归因于本轮；资源区显示实际 CPU 并行与总调用耗时，不将旧串行评价和新修复回放当作相同工作量计算加速比。

## 重新生成

在项目仓库执行，参数指向包含 `results` 和 `复核` 的归档目录：

```powershell
python docs/flow_replay/build_r25_evidence.py '<第二十五轮就绪修复归档目录>'
```

脚本只读取已归档汇总，生成当前目录的 `r25-data.js`，不访问网络、训练模型或运行模型前向。
