# 下一轮最小验证：冻结模型的 F 范围裁剪审计

日期：2026-11-05。状态：实验协议与脚本已准备，完整两环境实验室审计尚未完成。本轮新增模型拟合次数固定为 **0**；结果不自动晋级候选，不启动 KD、PLE、TabM 或新的训练矩阵。

## 1. 要回答的问题与已有证据

本轮只检验：**现有 MLP 对 F 取值范围之外输入的响应，是否造成可重复定位的漏报；将全部数值坐标限制在各自 F 范围内，分别修复和破坏哪些已有决策，付出多少管线成本？**

CIC24 已发现 2,272 条完整特征相同的主导漏报记录，24 字段 HGB 能检出它们。新增冻结响应检查中，F 极值范围裁剪能够恢复这组记录；small 在旧阈值下新增 74 条 FP，按既有 R+C 规则登记后仍须披露新增和修复事件，不能用净 FP 变化概括。wide 的已有 C 检查未增加 FP。这些是选择本次审计问题的开发证据，不能再称事前未知结果。

这些发现支持检查输入支持范围，尚不能推出所有 MLP 都受益、裁剪可以部署或需要训练新的表示。近期方法研究也表明数值表示、区间边界行为和推理成本应分开核查。其原文及作者源码依据见[学生结构与数值表示复核](research_alignment_20261105/student_representation_review.md)。本轮不复制某篇方法，不以极值裁剪作为算法创新。

## 2. 冻结范围：两环境各 8 个 MLP

使用已封存的 UNSW、CIC screen 工件；各环境均为原 seed 17 的 8 个 MLP，共 16 个。不得只取 CIC24 或表现有利的模型。

| 每个环境的模型 | 字段 | 数量 |
|---|---|---:|
| small hard warmup | all、reduced | 2 |
| wide hard warmup | all、reduced | 2 |
| small hard 续训选中检查点 | all、reduced | 2 |
| small direct_pauc 续训选中检查点 | all、reduced | 2 |
| 合计 | 原字段、结构、权重与检查点全部冻结 | 8 |

模型清单取自封存 `summary.json`，其中 `auxiliary` 的 `hard_warmup` 四项与 `runs` 四项共同构成清单。预期目录分别为 `warmups/{all,reduced}-{small,wide}-s17` 和 `students/{all,reduced}-{hard,direct_pauc}-s17`，以工件中的实际 `relative_dir` 为准。数量、种类或 seed 不符时停止核查，不补训练、不自行挑选另一组。

每个模型仅有两种输入策略：

1. `identity`：保持原预处理器、输入和模型。
2. `F_numeric_minmax`：使用原预处理器变换 F，计算**该模型全部数值编码坐标**的最小值和最大值，对后续数值坐标统一裁剪；类别坐标不变。

裁剪界限来自 F 输入，既不用标签，也不用 R/C 分位数。缺失填补、StandardScaler、类别编码、字段选择均沿用原工件；不重新拟合这些部件。F 经裁剪后的编码矩阵必须逐项不变，网络权重哈希必须不变。这里的“0 拟合”指没有模型参数优化和预处理器重估；仍会读取 F，计算确定性的输入界限。

不增加分位点、分列开关、模式特例、攻击族规则或多个裁剪强度。即使完整结果不利，也不能在本次输出中更换策略。

## 3. 数据与重放验收

数据必须是生成原 screen 的 prepared 数据，精确匹配原 `plan.json` 的 `binding.data` manifest。入口只加载 prepared 的 `train`，依据原 `fit-identity.parquet`、`reference-identity.parquet`、`constraint-identity.parquet` 恢复 F/R/C 身份和顺序。禁止重做 prepared、替换 manifest、只凭相同行数或字段名称放行。

本轮禁止读取 **V、calibration、test** 的记录、标签或分数。读取总 manifest 的元数据不授权读取这些分区。C 继续是已经参与模型选择和阈值构造的开发集。

运行前与运行中必须满足：

- 封存 screen 的完成标记、绑定和文件哈希通过现有校验；原目录只读。
- F/R/C 身份精确重现，分区覆盖、样本唯一性及既有组隔离校验通过。
- `identity` 在原阈值下的 R、C 决策与封存 `training-scores.npz` 逐项相同。CPU/BLAS 分数小差异可以记录；只要造成一个决策变化，就停止并定位重放差异，不静默换基线。
- 输出目录与 screen、prepared 目录分离，并且运行前不存在；失败结果保留，不能覆盖。

完整审计的技术验收是两环境均各有 8 个报告、16 个模型全部通过上述校验。单个模型失败后的不完整输出不合并成“所有模型审计通过”。

## 4. 两种阈值视图与配对事件

每个模型、每个 R/C 分区均报告两个视图。模型决策统一使用 `raw_score >= threshold`。

| 视图 | identity 阈值 | 裁剪后阈值 | 回答的问题 |
|---|---|---|---|
| 旧阈值冻结 | 原工件阈值 | 同一个原工件阈值 | 只改输入，哪些决策改变？ |
| 双方按既有规则登记 | 对 identity 的 R/C 分数重新应用原规则 | 对裁剪后的 R/C 分数应用同一规则 | 相同工作点规则下，哪些决策仍改善或受损？ |

既有规则不变：分别计算原预算下的 R 正常阈值和 C 正常阈值，取二者最大值；本轮沿用原 `max_fpr=0.01` 和原并列分数处理。禁止手动下移阈值、寻找最利于 2,272 条记录的阈值或新设有利的误报容忍值。第二视图的 C 误报受阈值构造控制，不能据此声称独立误报确认。

脚本 `results[...][role].paired` 均相对原封存阈值的 identity；双重登记的同规则比较应读取 `paired_registered_identity`。重登记裁剪相对原阈值 identity 的桥接比较也保留，但不可代替同规则比较。

四类事件须分别列出，不能只给净差：

| 配对事件 | 原正确性变化 | 计数定义 |
|---|---|---|
| 修复 FN | 原漏报攻击变为检出 | `y=1, old=0, new=1` |
| 新增 FN | 原已检出攻击变为漏报 | `y=1, old=1, new=0` |
| 修复 FP | 原误报正常变为正确 | `y=0, old=1, new=0` |
| 新增 FP | 原正确正常变为误报 | `y=0, old=0, new=1` |

每张主表同时提供原／新 TP、FN、FP、TN、分母、阈值、FPR、TPR 和四类配对事件。pAUC、PR-AUC 等排序指标可以辅助解释，不替代冻结工作点的事件表。

按攻击族列出 FN 修复与新增；按**原数据已有分组字段**和 `feature_hash` 列出 FP 修复与新增的组 ID、记录数、模式数及旧新交叠。保留相应 `sample_id`、旧新分数与阈值，便于逐项复核。单一完整特征模式可跨多个会话，不将 feature hash、联合组或记录自动视为独立统计样本。

工具自动保留 `group_column`、四类事件的组数，以及 `all` 中各事件的 `*_group_patterns` 列表，逐项包含原组 ID、完整 `feature_hash`、攻击族和记录数；源 R/C 身份与保存分数可进一步追溯到样本。不需要另写工具才能取得具体误报组。CIC small 的旧阈值新增 74 条 FP 必须保留为单独事件集合；即使另有 FP 被修复，也不能将其写成“没有新增误报”。

## 5. 成本测量及比较前沿

正式测量只在实验室 RTX4090D 主机进行，模型推理使用 CPU，线程数沿用原 screen 配置。每个模型的 identity 与裁剪策略接受完全相同的输入；各配对的执行先后随机交错，随机种子固定为脚本中的 `20261105`。权重加载在计时外，预热不计入正式样本。

固定测量量为 **3 块 × 25 次 × batch 1/256 × 两策略**。batch 1 交替抽正常／攻击记录；batch 256 各取 128 条正常与攻击并打乱。按同一冻结 C 身份和 seed 选取样本，保留全部 `sample_id`、原始耗时和可重现的配对顺序，使不同模型也能核对是否测了相同输入；`plan.json` 同时记录环境快照和线程数。这个工作负载用于比较成本，不代表部署攻击比例。

计时从已有 DataFrame 到预处理、裁剪和网络原始分数，**不含**磁盘 CSV 读取、流量特征提取及阈值比较。报告每块与全部 75 次的 p50/p95、batch 256 吞吐、配对耗时比；原始数组按连续 25 项划为一块。三块属于同次测量，不是三个独立实验环境。不得只选最快块，或因裁剪较慢追加计时直到通过。

本轮暂不测 RSS，不推算或声称内存节约。原模型包和 `diagnostic-candidate.joblib` 的实际字节数必须同时报告，包括预处理器和裁剪界限；不能只列权重参数量。

若需继续研究某一裁剪候选，事先采用以下工程预算：同模型、同样本、同 batch 的裁剪后 CPU p95 不超过 identity 的 **1.25 倍**，三个测量块分别满足；实际完整模型包也不得超过原包的 1.25 倍。这是为仅增加逐元素边界处理设定的保守研究预算，目的是限制为当前错误修补投入的部署开销；25% 不是文献定律，也不是已验证的用户设备性能标准。超过预算时停止该候选的部署推进，仍保留其机制证据。

每个环境还须与已封存的**全字段 small hard 续训模型**比较完整的质量—成本前沿：字段数、编码维度、实际包大小、上述同样本 CPU 测量及 R/C 的 FN/FP 事件。warmup 仅与同阶段 warmup 作字段／容量解释；不能将训练阶段差异归于表示。裁剪后的 reduced 模型即使修复旧问题，若仍被全字段 small hard 以不更多漏报、不更多误报及不更高实际成本支配，就没有新的轻量部署理由。

## 6. 成功、停止与主张边界

本次审计不以“出现一个有利模型”作为完成标准。完成标准是 16 个既定模型的技术重放、两种阈值视图、全部配对事件、误报组披露和成本测量齐全；有利与不利结果都保留。

| 判定层级 | 预先固定的标准 | 能得到的结论／停止动作 |
|---|---|---|
| 技术有效 | manifest、角色身份、旧决策、权重和 F 编码全部通过重放；16 个模型齐全 | 可以解释干预结果；任一绑定或旧决策失败先停止，修正实现后另用新输出目录重跑，不绕过校验 |
| CIC 已见机制复现 | 对相应已发现模型，冻结干预再次恢复同一 2,272 条完整特征模式，并同时复现和披露其配对代价 | 支持“这些冻结模型的 F 范围外响应参与该失败”；未复现则撤回这条解释，先定位工件、转换及阈值差异 |
| 跨模型／环境审计 | 所有预定模型均报告，且明确哪些有修复、哪些无变化、哪些恶化 | 不要求所有模型都受益；若效应仅限特定模型或环境，就把结论限制到实际响应，不能合并平均后称普遍有效 |
| 候选继续研究资格 | 每个 R/C 分区、两个同规则视图均没有新增 FN；同时满足第 5 节预注册成本预算；完整披露所有新增／修复 FP 及分组 | 任一新增 FN 或超预算，停止该模型的裁剪候选推进。通过也仅保留为开发候选，不自动修改默认模型或启动新训练 |
| 误报与部署资格 | 不使用新增任意 FP 容忍值；逐组检查新增 FP，并与全字段 small hard 的质量—成本前沿比较 | 有新增 FP 时必须写明未满足“无新误报”的替换条件，不以净 FP 或 R+C 的 1% 构造结果放行。当前缺少具体业务容忍依据，不能判部署成立 |
| 独立泛化确认 | 来源独立、从未用于选策略的新数据及事先冻结的确认协议 | 当前来源缺失，本轮不能完成这项判定；旧 V、calibration、test 不为此解封 |

“无新增 FN”是一条保守的本轮候选预算，防止用新攻击漏报换取已见模式恢复；它不是允许忽略新增 FP 的交换条件。两环境不能互相抵消代价，R 与 C 也不得合并后掩盖一侧恶化。若只满足机制复现而不满足候选资格，保留机制结论并停止该候选；不因此继续添加 KD、重加权或 PLE 来挽救它。

本次协议本身使用了已见 CIC 结果来确定研究问题。即使全部开发候选条件满足，也只能证明冻结工件上的开发效果与成本，不能写成预注册的独立方法成功、泛化完成或论文创新成立。
