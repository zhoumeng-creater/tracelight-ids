# 真实正常参照覆盖

2026-11-19。只读取已经开放的 TCP 阶段表与 AIT 正常下载候选关系。没有训练、真实模型前向、异常分数、阈值选择，未使用 C、russell、harrison 或 Meterpreter。

**目前不能称正常参照覆盖已经足够。** 精确零锚在 F 中主要覆盖同一次采集的重复序列，对 fox 的可用正常连接覆盖为 0；大多数 fox 正常仍有相同段结构和数值范围支持，因此也不能由此断言近似匹配必然失败。

## 1. 口径

- 参考库为 F 中有整连接正常依据且满足现有字节几何条件的 6,840 条 TCP 连接，包含 2,797 种完整有序 `(方向, 唯一字节数)` 序列。
- 其中 2,304 种是单例，493 种重复，最大一型出现 267 条。排除查询自身及同 stable_flow_id 的测量别名；当前 bank 没有重复 stable_flow_id。
- F 去自身覆盖是训练支持描述，不是独立评价。fox 的 V 已经开放，只称跨 run 开发支持。
- 跨 capture 与跨独立 run／campaign 分列：AIT santos 的 cloud_share 和 intranet_server 同属一个 run；Unraveled 属于另一个 campaign。不能把两个 capture 当独立攻击复现。
- “方向结构支持”只要求方向序列完全相同，不比较字节。“坐标包络”要求每个位置的字节数位于相同方向结构参考的逐坐标最小／最大范围内。它可以由不同参考扩大范围，不能把包络内部点都称正常。
- 分母保留无几何资格的正常连接；它们没有被改成未知或从原始正常总数中删除。

## 2. 精确完整参照与时序

| 正常来源 | 全部正常 TCP | 几何可用 | 排自身后的 F 完整精确参照 | 跨 run／campaign 精确参照 | 同 capture 严格更早的精确参照 |
|---|---:|---:|---:|---:|---:|
| santos cloud_share | 314 | 313 | 198 | 0 | 171 |
| santos intranet_server | 125 | 125 | 49 | 0 | 32 |
| Unraveled target | 6,775 | 6,402 | 4,289 | 0 | 3,824 |
| F 合计 | 7,214 | 6,840 | 4,536 | 0 | 4,027 |
| fox cloud_share | 357 | 348 | 0 | 0 | 不属于 F 同采集描述 |
| fox intranet_server | 74 | 74 | 0 | 0 | 不属于 F 同采集描述 |
| fox V 合计 | 431 | 422 | 0 | 0 | 不属于 F 同采集描述 |

4,536 条 F 精确覆盖全部来自同一 capture，跨 capture 也为 0。只排自身仍会把同采集重复业务计入覆盖，不能据此声称正常模式具有跨来源泛化。

严格更早采用 `reference.replay_export_time < query.replay_export_time`，同刻不算更早。它排除了部分未来重复带来的支持，从 4,536 降至 4,027。这是已知正常标签回看下的特征前缀；原件没有证明这些正常标签当时已经可得，不能直接转成可部署的在线正常库，也不是新的独立 test。

## 3. 结构和数值支持没有等同于完整解释

| 对象 | 可用数 | 同方向段结构 | 逐位置都能找到精确参考值 | 完整精确序列 | 同结构坐标包络 | 同结构双向总字节包络 |
|---|---:|---:|---:|---:|---:|---:|
| F 正常，排自身 | 6,840 | 6,799 | 4,946 | 4,536 | 6,448 | 6,602 |
| fox 正常 TCP | 422 | 420 | 0 | 0 | 402 | 413 |
| fox 正常 HTTPS | 421 | 419 | 0 | 0 | 402 | 413 |
| fox HTTPS 控制 | 15 | 15 | 0 | 0 | 15 | 15 |
| fox 已确认下载 | 1 | 1 | 0 | 0 | 0 | 0 |

421 条可用正常 HTTPS 对应原始 430 条正常 HTTPS，另有一条正常 TCP 及 9 条表示不完整的正常连接。不能把全部正常 TCP 与 HTTPS 分母混写。

包络对 fox 正常和 15 条 HTTPS 控制都较宽，不能拿它作为分类规则。两条已确认 AIT 下载都没有处在同结构的双向总字节包络内，当前差异仍可能被总量解释，没有从这里建立高阶阶段机制的必要性。

同业务角色条件更严格：仅使用 santos cloud_share 参考时，fox cloud_share 348 条正常中的方向结构支持为 341，逐位置坐标包络覆盖为 **0**；使用全部 F 正常后，后者变成 337。实际前两段为：

- santos cloud_share 的 313 条可用正常，全部是 `[(0,517),(1,2351)]`；
- fox cloud_share 的 348 条可用正常，全部是 `[(0,517),(1,2345)]`。

第二段固定相差 6 字节。这里没有读载荷，不能给这 6 字节指定 TLS 或应用语义，也不能自动把它定义为可删除的环境因素。事实说明：精确型判定对正常来源变化敏感，而混合其他业务形成的大包络会掩盖这种差异。

## 4. 完整参照约束实际收紧了正常业务

F 正常中有 **410 条**，每个位置都能在同方向结构的正常参考中找到完全相同的方向／字节段，但排除自身后没有任何一条完整参考与它相同。santos cloud_share 4 条、intranet_server 7 条、Unraveled 399 条。仅使用同 capture 严格更早的参考，仍有 304 条这种正常组合。

例如已知正常 `ait:santos:cloud_share:CU2fmX09fvOvolTx` 的完整序列是：

```
[(0,517), (1,2351), (0,844), (1,1661)]
```

没有另一条完整相同参考；第三段 844 可以来自正常 `CnZHm62UeOZSvgVyw7` 的同位置，第四段 1661 可以来自正常 `CJlRR348b6ljZ5jFpb` 的同位置。逐位置解释能够精确完成，完整解释不能精确完成。9 个实际例子及各位置参考的完整序列保存在 `coverage_real_normal_counterexamples.json`。

410 条证明完整轮廓精确相等比逐位置精确支持更严格。对旧模型，若局部输入就是上述 token 或保留这些差异的一一数值表示，有限参数下的正 softplus 权重乘平方偏离、带 presence 的正 gap 成本可进一步推出：独立位置成本为 0，完整编辑路径成本大于 0。此推论不适用于允许重复真实对应的新成对 DTW，也没有评价任何学习器的误报。所有已确认控制和下载都没有“每个位置精确正常、整条无完整参照”的情况；当前精确证据未支持把该收紧作为攻击识别所必需。

## 5. 正常下载按动作保留候选

| 来源 | 正常下载动作 | 唯一候选连接 | 整连接正常／未知 | 几何可用候选 | 有精确参照候选 | 至少一候选精确的动作 | 全部候选精确的动作 |
|---|---:|---:|---:|---:|---:|---:|---:|
| santos | 44 | 375 | 314／61 | 370 | 225 | 43 | 2 |
| fox | 42 | 406 | 357／49 | 395 | 0 | 0 | 0 |

santos 的 225 包含 198 条正常候选和 27 条未知候选。精确匹配到正常参照没有改变这 27 条的标签。43 个动作各有至少一个精确候选，不等于 43 个动作真正的下载连接已经覆盖；只有 2 个动作的整个候选集合都精确覆盖。原 one-of 关系与候选完整性原样保留。

## 6. 产物与采用判断

- `coverage.json`：分来源／标签／支持域的完整汇总和 86 个正常下载动作候选。
- `coverage_records.jsonl.gz`：8,514 条连接的逐条支持事实，保留不满足几何条件的记录。
- `coverage_real_normal_counterexamples.json`：实际正常组合的逐位置见证。
- `scripts/reference_evidence/coverage.py`：可复算程序；只进行精确关联、结构和范围统计。

当前可以确认的是：F 库有大量同采集重复支持；跨 run 精确零锚没有覆盖 fox 正常；正常来源存在明确的阶段数值变化；完整解释约束确实收紧一部分真实正常组合。不能由精确匹配失败否定所有可学习近似匹配，也不能把宽包络或训练重复率当成正常覆盖已充分的证据。
