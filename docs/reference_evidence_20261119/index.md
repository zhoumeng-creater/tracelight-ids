# 正常参照覆盖、完整解释必要性与缺口修复

2026-11-19。使用已有真实连接和正常动作材料，完成精确支持、连续几何、正常组合反例与无删除路径分析。**当前撤下“完整正常参照约束”作为算法创新主线；旧可学习空节点缺口版本结束探索。无缺口版本已实现，保留为普通对照，不启动新训练。**

原因不是代码无法实现，而是设计所需的攻击现象尚未出现，约束在精确解释层面收紧真实正常业务的证据却已经出现。此次没有得到一项已成立的算法创新。以下结果明确了哪些事实可继续使用，哪些主张应结束。

## 1. 正常参照有多少实际支持

参照只取 F 内整连接可信正常、阶段表示合格的 6,840 条 TCP 连接，共 2,797 种完整方向／唯一字节序列。每个查询排除自身及相同物理测量的别名。fox 是已开放的跨 run 开发材料。

| 对象 | 全部可信正常 TCP | 阶段表示合格 | F 库中完整精确支持 | 相同段数与方向结构支持 |
|---|---:|---:|---:|---:|
| F 正常，排自身 | 7,214 | 6,840 | 4,536 | 6,799 |
| fox 正常 | 431 | 422 | 0 | 420 |

F 的 4,536 条精确支持全部来自同一 capture；跨 capture、跨 run／campaign 都为 0。严格只用同 capture 更早完成导出的参考，降为 4,027。这个前缀结果使用回看所得的正常标签，不证明标签在当时已可得。

**精确零覆盖不等于所有正常都离参照很远。** santos cloud 的 313 条可用正常都以 `[(0,517),(1,2351)]` 开头，fox cloud 的 348 条则都以 `[(0,517),(1,2345)]` 开头。6 字节的稳定差异已经足以破坏精确相等；没有载荷证据，不能将它命名为某种 TLS 字段或直接视作应删除的环境噪声。

为区分“没有完全相同”与“数值相差很远”，在**相同段数、相同方向序列**的 F 正常参照内计算：

\[
M_{\rm whole}(q)=\exp\!\left[\min_r\max_i|\log(q_i/r_i)|\right].
\]

它表示最佳完整参照仍需容纳的最大逐段字节倍率：1 是完全相同，1.12 表示各段均在约 1/1.12 至 1.12 的比率内。它是固定输入几何，不是攻击分数；没有挑选可接受倍率。

| fox 正常业务 | 有该结构参照／可用连接 | 倍率中位数 | 95% 分位 | 最大值 |
|---|---:|---:|---:|---:|
| cloud_share | 346／348 | 1.117 | 2.467 | 315.897 |
| intranet_server | 74／74 | 1.026 | 17.097 | 130.122 |

多数连接在这种几何下接近正常参照，但尾部差异很大。cloud 最大值对应一条 58 段正常连接，该结构域只有一个 F 参照，且来自 Unraveled；intranet 的极端正常连接也由 Unraveled 提供最近参照。这不能当作可比业务覆盖。以上数字也不评价允许异长对齐的新 DTW 对照。

同业务与混合业务必须分开：只用 santos cloud，fox cloud 的逐位置数值包络覆盖为 0／348；混入全 F 正常后变成 337／348。混合包络变宽没有补出同业务证据。

**覆盖结论：**已有库可以支持真实参照研究，但尚未证明足以承担各正常单元 1% 误报约束。不能用 F 重复率、混合包络或合法路径存在代替这一证明；也不能由精确零覆盖判定所有近似参照方法失败。

正常下载的动作证据继续保留 `one_of`：santos 的 44 个正常下载动作中，43 个有至少一条精确覆盖候选，只有 2 个的全部候选都精确覆盖；fox 的 42 个动作无精确覆盖候选。候选中未知连接不改作正常，不选体量最大的候选充当唯一下载连接。详见 [coverage.md](coverage.md)。

## 2. 完整解释实际排除了什么

在当前方向／唯一字节表示中，完整精确相等与逐位置精确支持有以下真实分歧：

| 查询 | 连接数 | 每个位置均有正常精确支持，但无完整精确参照 |
|---|---:|---:|
| F 正常 | 6,840 | **410** |
| fox 正常 | 422 | 0 |
| 已开放控制 | 520 | **0** |
| 可信恶意下载 | 2 | **0** |

410 条全部来自 F：santos cloud 4 条、intranet 7 条、Unraveled 399 条。它们是排自身后的真实正常组合，不是 410 个独立开发反例，也不是 410 次误报。放宽到任意位置，正常中有 1,352 条局部全覆盖而无完整精确参照；12 条甚至有相同完整多重集，只是阶段顺序不同。

一个具体正常查询是 `ait:santos:cloud_share:CU2fmX09fvOvolTx`：

| 阶段位置 | 查询的方向／字节量 | 同位置正常提供者的完整字节序列 |
|---|---|---|
| 0、1 | `(0,517)`、`(1,2351)` | `C0BOJj2u6f5R0ykJUd`：517, 2351, 1086, 1541 |
| 2 | `(0,844)` | `CnZHm62UeOZSvgVyw7`：517, 2351, 844, 2115 |
| 3 | `(1,1661)` | `CGuogdEeMqJKXGoii`：517, 2351, 842, 1661 |

提供者均为同一 santos cloud 业务的可信正常连接。查询关联一个正常 ownCloud 下载动作，其完整候选集合有 15 条；可以认定该连接正常，不能认定它唯一承载文件下载。逐位置都能精确解释它，另一条完整精确参照却不存在。

520 条控制包括 Unraveled 的 473 条、santos 的 31 条、fox 的 16 条；两条下载分别来自 santos、fox。它们不是 522 次独立攻击复现。对这 522 条，每条至少有一个方向／字节 token 在整个 F 正常库中未出现。**尚未找到“所有阶段都有精确正常解释，只有组合才暴露攻击”的实例。**这没有证明独立阶段模型已经检出它们，也没有证明连续表示不会产生新的局部重叠。另有 11 条 `other_attack` 不满足几何条件，没有进入上述结论。

因此，真实共享前段支持“不能把连接正标签复制给每个阶段”；它不推出必须使用 MIL，更不推出必须让同一条正常连接解释全部阶段。完整解释增加的约束确有数学区别，但当前没有所设想的攻击必要性。完整关系与标签追溯见 [necessity.md](necessity.md)。

## 3. 近似关系也未补出完整约束的必要性

在同一结构域、同一正常库和同一局部差异下，独立参照是
`M_ind = exp(max_i min_r |log(q_i/r_i)|)`，完整参照是前述 `M_whole`。恒有 `M_ind ≤ M_whole`。后者较大表示约束更严格，不能直接解释为检出更好。

fox cloud 正常的完整／独立倍率中位数为 1.117／1.059，intranet 为 1.026／1.016。这些中位数不是配对差值，也不是告警率。

另外按每个方向的总字节归一化，单独查看阶段组成。两条恶意下载的原始字节倍率约为 18,844.7，完整与独立相同；归一化后两者均为 1。因为它们每个方向只有一段，该归一化会把每段都固定成 1。这里被消除的是体量信息，不能称下载获得了正常业务解释，也没有完整约束的额外贡献。

Unraveled 控制的完整原始倍率中位数约 5，归一化后约 1.248。数值变化说明总体积参与了区别，不能把全部差异归因于攻击组合。现有材料没有等体积正常下载对照，本轮也没有通过选择倍率来回避这一点。完整逐连接结果见 [geometry_summary.json](geometry_summary.json) 与 [geometry_rows.jsonl.gz](geometry_rows.jsonl.gz)。

## 4. 缺口已在普通对照中移除

旧模型的“所有阶段都被路径消耗”不等于“所有阶段都与真实正常阶段比较”。只匹配共有首段，再让剩余阶段与低成本空节点比较，仍是合法路径。增加匹配比例或调整缺口价格没有现成业务依据，因此旧版本结束探索，原代码留作历史记录。

新建的普通对照采用：

1. 从捕获首方向开始，把相邻两个方向段无损成对，奇数末段单独保留。
2. 只比较首方向、尾段存在类型与完整对存在类型兼容的真实参照；单个尾段不能对应一串完整对，不支持的类型返回未支持。
3. 每个完整对的两个方向分别计算相同局部成本，取最大值，再做覆盖所有行列的无缺口瓶颈 DTW。
4. 真实尾段必须与真实尾段比较，并进入最终最大值；没有补零、空节点或删除边。

这样，后段必然进入真实比较，不能沿旧缺口退出。相邻成对表示已在 8,235 条非空真实序列上精确还原；fox 的 422 条合格正常均有结构兼容参照。后一个数字只是合法路径存在，不能替代数值或业务覆盖。

两个实现均已交付：[固定成本算子](../../scripts/reference_evidence/paired_no_gap.py)、[可微普通对照](../../scripts/reference_evidence/paired_reference_control.py)。可微版复用旧 `RelativeCost` 及相同的 α、β，不增加学习参数；后段与尾段梯度通过有限差分检查。矩阵路径穷举和真实还原分别证明实现与表示性质，没有运行真实模型前向。

**DTW 仍会忽略连续相同完整对的重复次数。**现有材料已有 31 个这样的等价组，共 941 条正常连接、64 种原始序列。例如 `(379,799)` 重复 1、2、4、5 次，完整路径可只比较相同真实对而得到零局部差异。成对输入没有丢数据，匹配规则却对这些次数不敏感。没有发现这些等价组中混入攻击；不因此增加次数惩罚。完整推导、实际 ID 与检查见 [gap_resolution.md](gap_resolution.md)。

## 5. 相对同信息简单方法，还剩什么创新

| 组成或比较 | 实际差别 | 当前判断 |
|---|---|---|
| 完整参照 vs 独立阶段参照 | `min_r max_i` 与 `max_i min_r` 不可交换；前者收紧组合 | 差别真实，但必要攻击现象未出现，正常收紧已出现；撤下主线定位 |
| 成对、无缺口完整匹配 vs 固定距离完整模板 | 同一方向／字节信息，同一正常库，只改变局部成本是否学习 | 属于标准瓶颈 DTW／离散 Fréchet 适配，修复漏洞不是创新 |
| 非负条件成本、精确自配为零 | 给已存完整表示最低值 | 是有用性质，不能扩大为未见正常保护；可学习度量本身已有先例 |
| 连接标签学习阶段证据 vs 简单集合／序列分类器 | 不向每个阶段复制正标签 | 可保留研究问题，但弱监督和 burst 编码已有先例；尚无本项目特有学习机制及其收益 |

近期直接近邻继续采用已核的一手来源：PRADOT 2025 作者代码的推理按局部 patch 独立选原型；EMS-uDTWAD 2026 已将完整窗口与正常参考库作 uDTW 比较；ICCS 2025 的加密流量 MIL 已使用 burst 编码及 bag 监督。它们与本项目任务、标签和工作点不同，但足以排除把这些组成重新命名为原创。原文、固定作者提交和代码位置见 [近邻依据](../stage_conditional_design_20261119/stage_neighbors.md)。

若未来某项新学习条件有真实依据，最小区分仍是：同局部成本的独立参照、同参照库的固定距离完整模板、同输入的简单集合／序列分类器。所有方法应看到相同完整阶段、正常标签与参考库；候选必须计入参考存储、逐参考比较和最长序列成本。这张比较关系不是本轮新增实验矩阵。

## 6. 本轮决定与后续出口

| 项目 | 决定 |
|---|---|
| 完整参照约束作为当前创新主线 | 撤下该定位；精确解释已收紧真实正常组合，尚无所设想的攻击必要性 |
| 共有首段＋可学习 null-gap 原候选 | 结束探索，不调 gap 价格、匹配比例或温度 |
| 无缺口成对匹配 | 保留为普通固定／可微对照，不作为新算法发布或启动训练 |
| 正常参照数据、局部不确定标签和真实反例 | 保留供后续机制核对与论文使用；不以补来源替代本次否决 |
| 覆盖 × 端口四臂 | 原 tag、输入、注册与结果出口不变；只按已冻结用途收尾 |

下一次提出新训练，必须说明已有真实残余错误对应的学习困难、简单同信息方法为什么不能充分处理，以及改动怎样针对该困难。本轮没有找到足以满足这三点的新机制，不通过追加模型、数据或阈值网格补出一个候选。四臂回传按[已有出口](../research_history_20261119/outcome_policy.md)解释，不自动扩展实验。
