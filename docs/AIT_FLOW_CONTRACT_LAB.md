# AIT 既有抓包的数据定义与证据核验

固定版本：`ait-flow-contract-v1`。本批承接第二十七轮，独立于第二十九至三十一轮训练及当前操作风险设计。它只处理已经下载的同一份 PCAP，模型拟合、模型评分、阈值搜索均为 0。

## 为什么需要这批处理

已有原件支持 32 条 WebShell 请求、68 次正常 HTTPS 页面操作和两个下载动作。正常操作涉及 294 个不同连接候选，远程员工 33 次操作全部为多连接，不能为了唯一匹配而删除。口令表下载目标已从原命令核定；工具包两条 TLS 候选的具体角色、原 Zeek 八字段、31,668 条 IP 长度异常及日志导出时刻仍未核清。

本批将这些问题一次处理。完整数据约定见[contract.json](../configs/ait-flow-contract-20261118/contract.json)，既有动作证据和关联锚点在同目录；所有规则在新导出之前固定。

## 输出与判读

| 对象 | 固定处理 | 结果用途 |
|---|---|---|
| 真实 Zeek 输入 | 原生 conn.log 的协议、双端口、持续时间、双向包数和 IP 字节；缺失为 −1 | 核对八字段来源；不以 TCP payload 代替 IP 字节 |
| 校验和敏感性 | 标准校验与 `-C` 忽略校验和分别完整导出 | 比较连接、字段和证据变化；不按有利结果挑一臂 |
| HTTP/TLS/DNS/files/weird | 保留同一观测点的原生结构化日志 | 核对 rockyou 请求、工具包端点、文件传输与异常；没有日志也须记录 |
| 正常业务 | 保留全部 68 个动作及所有候选、未决背景和冲突 | 不将 3975 条背景候选自动标正常，不用响应大小生成标签 |
| 时间 | 分列包时间、连接末时刻、回放导出时刻和 EOF 状态 | 真实检测器送达、正常反馈时刻仍未知；不把事后真值写成在线反馈 |
| 全包长度诊断 | PCAP captured/wire 与 IPv4 声明长度分别统计，包含少量无载荷包头样例 | 定位异常范围；不由长度差直接断言丢包、损坏或 offload |

HTTP 明文中目标和 URI 相符比纯时间重叠提供更强证据；TLS SNI 或 DNS 只补端点信息，不证明具体文件。重复命令、多个 TCP 和两次下载均保留其所属的同一攻击链。正常大响应/下载候选需要业务来源确认；命名像文件、没有攻击标签、响应较大均不是正常真值。

## 时间和评价边界

整个 PCAP 都交给 Zeek，保留筛选窗口之前的连接状态与之后的结束记录。四日窗口只用于后续标记，不切断长连接。完整流统计只能在连接结束或超时导出后使用；回放中记录的 `network_time()` 是网络逻辑时间，不是历史检测器实际收到日志的证明。

Zeek 的 `ts+duration` 也不等于捕获到的最后一个包：其持续时间可能不包含关闭后的尾随非有效载荷包及最终 ACK。输出将它标为 Zeek 报告的结束估计，与 R27 捕获末包、导出时刻分别保存。[Zeek 8.0.11 Conn::Info 定义](https://docs.zeek.org/en/v8.0.11/scripts/base/protocols/conn/main.zeek.html)

控制候选中最长连接持续约37分钟。后续若用完整流评分，必须按导出后告警报告延迟，不能把成绩回填到命令开始时。正常任务成功时间可以支持明确反馈假设的回顾分析；只有实际送达记录才能证明真实在线可用。

本批不建立新的正常校准池，不计算误报率。正常流分母、未决处理及反馈条件尚未固定时，不能靠背景未标注或只保留单候选形成有利分母。未来评价可用事后真值，但训练、阈值校准或更新必须满足使用时的信息可得条件。

## 环境、资源与回传

使用固定版本 Zeek 运行环境，运行时记录版本、命令、镜像/二进制身份和输出哈希。入口先用合成抓包核验环境，再运行正式原件。现有 PCAP 须同时通过343,232,723字节、CRC32和R27 SHA-256；找不到原件时不重新下载整包，也不静默用其他文件替换。

本实现固定 Zeek **8.0.11**。Windows 自动入口要求已有 **Ubuntu 24.04 amd64 WSL**，从官方 Zeek 与 Ubuntu 源下载12个固定软件包，共12,182,010字节，逐包核 SHA 后仅解包到本工作树的 `local/ait-zeek-runtime`；不使用 apt 全局安装。Linux 可使用已安装的相同版本。若 WSL 不存在或发行版不匹配，入口生成失败回传，不安装发行版或重启系统。运行环境依据：[官方安装说明](https://docs.zeek.org/en/master/install.html)、[二进制软件包说明](https://github.com/zeek/zeek/wiki/Binary-Packages)。

在实验室仓库 PowerShell 中执行：

```powershell
git fetch origin tag ait-flow-contract-v1
git worktree add .worktrees/ait-flow-contract ait-flow-contract-v1
Set-Location .worktrees/ait-flow-contract
.\scripts\RUN_AIT_FLOW_CONTRACT.ps1
```

入口在 Git 已登记的工作树中查找 R27 原件。若 PCAP 已移至其他位置，追加 `-Pcap '实际路径\log.pcap.1642684613'`；WSL 发行版名称不为 Ubuntu 时追加 `-Distro '实际名称'`。默认复用 route-core Python；`-Python` 可指定既有解释器，不升级模型环境。`-CheckOnly` 只运行合成单元检查，正式入口还会运行真实 Zeek 合成自检。

回传 `local/ait-flow-contract-results-*.zip` 和同名 `.sha256`。失败时也会生成回传；重复同一命令会复核并复用已成功阶段。若某 Zeek 导出被重建，后处理绑定该次具体日志哈希，不能混用旧 UID 或旧关联结果。

两项 Zeek 导出和一次包长度诊断最多三个独立 CPU 作业并行，每个作业处理完整抓包；单个有状态包流不按时间分片。GPU 任务为0。记录进程和阶段墙钟、退出状态；完成阶段按输入与代码绑定复用，失败阶段和成功阶段分别保留。

回传只打包结构化日志、分析表、运行记录、失败说明及哈希，不包含 PCAP、容器镜像、模型权重或旧实验。实验室保留原件以便复核。

## 下一步的决定条件

本批回答“哪些记录和信息能用于后续研究”，不会自动启动效果实验。后续若八字段语义和事件关联成立，可将 AIT 用作外部历史机制案例或另行登记冻结阈值迁移评价；若正常文件下载对照仍不足，下载泛化要求保持未完成。

若本观测点最终没有可核实的正常文件传输，记录其覆盖不足，结束该来源的下载确认分支；不自动追加其他场景、抓包或训练来延长这条路线。两种校验和口径若使关键字段/事件对应明显不一致，先定位提取语义，不能择优报告。上述结论只决定 AIT 的研究角色，不阻塞其他已登记的模型或操作风险工作。

WebShell 固定 JPEG 回显可能造成特定响应体积。即使新导出后两类仍容易区分，也不能直接当通用 C2 规律或算法创新。新方法须解释跨事件可复现的混淆，与同信息强基线比较，并报告原要求的逐时段误报、逐类新增/丢失、实际延迟和成本。
