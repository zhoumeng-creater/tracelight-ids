# TraceLight 补漏实验

## 实验室怎么跑

把 **TraceLight-Residual-Rescue-Lab-v1.zip** 带到实验室，解压到有足够空间的本地磁盘，双击 **RUN_RESIDUAL_LAB.cmd**。程序使用 Windows x64 的 Python 3.12 和 CPU。它从包内安装固定依赖，核对输入与模型，再跑完四组。实验室使用过的 Python 3.12.3 可直接用。包内含数据、四份旧模型、代码、依赖与运行说明。实验无需下载旧档案或连接 GitHub。

运行结束以后，把本轮结果 ZIP 和对应 SHA-256 文件一起放入实验归档。结果包含新模型、逐条分数与报警、每项比较、成本和判断依据。具体输出路径见解压目录内的实验室 README。

## 数据够做什么

| 用途 | 冻结来源 | 证据 |
|---|---|---|
| 两组小模型训练 | Unraveled，主 HGB 的拟合未见这次采集 | 12,308 条正常、473 条控制。主 HGB 放过 12,249 条正常和全部 473 条控制。两组使用同一批控制，专训组只去掉 59 条主 HGB 已报错的正常流，其中 TLS 56、HTTP 2、SSH 1。另有 73 条正常连接的字段缺失，按共享预处理处理。 |
| 定报警线 | Russell 的旧正常校准集 | 3,475 条正常，三个业务组分别为 910、188、2,377。 |
| 历史开发评价 | Fox、已打开的 OpTC | Fox 为 431 正常、16 控制、1 下载、213 未确定；OpTC 为 41,630 正常、24 控制、1 下载、518 未确定。正常流量按原登记业务验收，攻击另按已有候选连接与事件证据验收。 |

473 条流都归到同一场采集、同一登记控制观测事件，档案没有 473 个独立指令的真值。原主 HGB 的 Santos 拟合集没有 HGB 漏报正例。未确定及非目标攻击不转作训练正常。当前实验可以检验所选训练方法在旧材料上的收益，独立确认需要另一批此前未使用的同场数据。Harrison 与预留的 Meterpreter 都不进入这次实验。下载在覆盖检查中单列，第一版小模型没有恶意下载训练正例。

可在包内的 data/data_audit.json 查证上述计数。制作方的 [输入构建器](../scripts/residual_ids/build_inputs.py) 从原综合归档提取必需成员，复核原 SHA-256、59,707 条身份的顺序、标签、数据角色和观测时钟，再生成较小的可携带输入。输入保留八项连接统计和既有转换值。包不需要原始抓包。

## 四组比较

1. **原 HGB**。使用已冻结的按业务共同报警线。
2. **单独使用 TabM**。使用原档三个普通训练的检查点，每个单独报告。运行在 CPU，同一份 Russell 数据用相同业务预算一次定线，并与原来存档的阈值结果核对。这个现有方案使用了不同的历史训练覆盖，是替代方案的对照。
3. **HGB 加普通小网络**。正常使用全部训练样本。HGB 已报警的流保留，小网络只可能补报其余流。
4. **HGB 加专训小网络**。和上一组使用同种子、同两层网络、同训练顺序和步数。主 HGB 已报警的开发例子在小网络的训练中取零权重。其余例子的标签来自已有证据。

两组小网络共用预处理。连接的两个端口都屏蔽。训练标签、业务归属、来源名和采集时间只作审计与评价。保留未知标签的报警计数，未知不加入误报率分母。预处理、网络和训练常数以代码为准。适用范围是完整连接记录已经可用时的离线评价。

原 HGB 的固定规则在 Fox 的 3 组和 OpTC 的 26 组正常记录上均未超额，两个历史场景都有实际的控制漏报。HGB 在 Fox 放过 641/661 条，在 OpTC 放过 42,087/42,173 条。因此小网络几乎要看所有连接，最后比较 HGB 加小网络的总开销。

两组补漏模型并用 HGB 与小网络的告警。在 Russell 中，HGB 已用的误报名额分别为 0、1、7，业务预算分别为 9、1、23，留给小网络的是 9、0、16。每组用 **全组正常数** 算名额，再用 HGB 没报警的正常连接定小网络的线。取各业务所需的最严格一条作为共用报警线。严格高于才报警，同分不拆开。在评价集上超额如实列出。

## 结果回来后怎样判断

- **主 HGB 已在某组超额**。只追加告警的方案在该组无法达标。结果反映方案前提与环境不匹配。
- **普通补漏和专训补漏都失败**。先看已确认控制在补漏分数里能否排过高分正常，两者排不开说明当前评分无法在预算内解决。能排开但冻结线没收住误报，才考虑校准能否跨环境。用评价数据算的诊断上界不作部署报警线。
- **两组补漏效果差不多**。训练专门化没有显示价值。这个条件尤其重要，因为本轮两组见过相同的 473 条控制，只相差 59 条正常连接。
- **专训比普通补漏多检出已核实控制事件且每组误报达标**。再核对原检出保留多少、新增是一个事件的重复连接还是多个事件，并与单独 TabM 一起比较模型体积、单条响应和批量评分成本。只有普通 TabM 无法提供同等检测和成本取舍时，才有继续验证这套设计的价值。
- **无论哪种结果**。分别解释数据覆盖、候选机制、报警线迁移和合计开销。旧开发样本的收益写作开发证据。要主张在新采集中有效，须再用独立同场证据确认。这轮结束后不按 Fox、OpTC 或回传表现自动追加种子、训练轮数或阈值搜索。

第二十四轮已试过在 HGB 告警之上用历史分数补报，有些采集补回了控制和下载，也有采集增加大量误报。本轮保留同类误报核算，改变的是第二模型的训练样本。2026 年的 RiskGate-IDS 也做两阶段检测，约束的是进入第二阶段的计算量，并用少量目标标签拟合排序。其论文和公开摘要可对照，本轮未复现其实现。现有公开结果不能把两阶段框架或剩余误报名额本身算作新算法。 [项目历史追加对照](RAW_WORKPOINT_LAB.md) · [RiskGate-IDS 原文与摘要](https://www.sciencedirect.com/science/article/pii/S187454822600048X)
