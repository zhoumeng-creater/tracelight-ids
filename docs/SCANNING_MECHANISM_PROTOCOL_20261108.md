# Scanning 源端口语义与支持覆盖的最小机制对照

2026-11-08。阶段：工件分析、2025—2026年原文／作者源码审查与三臂正式入口已完成，完整本机合成回归288项通过。本文冻结实验问题与三臂设计；执行见[实验室指南](SCANNING_MECHANISM_LAB_V1.md)，标签`scanning-mechanism-lab-v1`。本机未构造真实P映射、拟合真实预处理或运行真实模型。

**54条扫描退步不能统一用P缺少完整同输入解释。下一步检验源端口的编号关系与身份信息分别如何参与完整模型的低误报判断。** 新表示完整KV已有总体收益，普通QCOC也已接近它的检测总数，继续优先调整压缩参数不能解释压缩前的Scanning失效。

## 已经查明的问题

第十四轮新完整KV检出6711条攻击、误报118条，Scanning仅3/1078；其1075条扫描漏检占全部1459条漏检的73.68%。Scanning与正常流的总体AUC为旧表示0.8952、新表示0.9002，而旧54条检出在新模型中位于正常C的第97.62%—98.94%分位，未跨过低误报登记门槛。当前要解释的是高分正常流附近的区分。

P含512条Scanning。E的1078条扫描中，1017条的非ID44字段模式出现在P扫描中，1023条出现在P正常中，1013条在两类支持中均出现。统计形状有覆盖，不等于有可迁移的标签区分。

| 旧54条检出后失检的Scanning | 行数 | 解释 |
|---|---:|---|
| 四个ID分别在P出现 | 51 | 单值出现不等于组合覆盖 |
| 完整48字段匹配P扫描 | 15 | 其中0条同时匹配P正常；完整同输入缺失／P同输入标签冲突不能解释这15条，支持权重与上下文交互仍未排除 |
| 去源端口47字段匹配P扫描 | 52 | 行为和其他三个ID已有支持 |
| 去源端口47字段匹配P正常 | 50 | 源端口以外的字段不能区分这些相反标签的支持 |

54条均属于PROTOCOL=6、目的端口443、L7_PROTO=91。50条共享同一47字段模式，只有源端口可变；该模式P为89扫描／11正常，C为9正常，E为217扫描／33正常。两类源端口范围广泛重合，单个划分内的源端口集合不重合，跨P/E却存在同源端口、同48输入而标签相反的例子。不能把行身份唯一直接等同于稳定的攻击语义。

以上见[工件发现](research_alignment_20261108/scanning_mechanism/artifact_findings.md)及[完整计数与输入SHA](research_alignment_20261108/scanning_mechanism/artifact_coverage.json)。44／47字段投影的相同输入错误下界，只适用于该投影；当前48字段仍可能包含有用信息，不能借投影下界宣布原任务不可分。

**原始记录已对齐，输入覆盖与网络事件覆盖需要分开。** 本轮从官方ZIP流式核对全部27,520,260条原CSV记录，CRC和CSV SHA-256通过；33,192条P/C/E记录的48字段、标签和攻击族全部对齐。旧54条失检均来自P扫描已出现的三个源主机，但仅19条具有P扫描中出现的同一有向IP对。上述15条完整同输入匹配行中，只有2条具有P扫描同有向IP对。模型看见相同48字段，不代表支持集覆盖了相同网络事件。

P/E共享31个源主机、179个目的主机、314个有向IP对，有向五元组交集为0；P/C/E都覆盖2019-04-23至29。通信组隔离不能代替独立主机或时间验证。IP和绝对时间不在当前模型输入中，这些重合本身不证明特征泄漏；它们限制现有结果的泛化主张。

主47字段模式的217条E扫描与33条正常来自相同三个源主机，源IP本身不能区分它们。时间集中度和目的覆盖留下了跨流信息线索，但抽样行的窗口计数不代表完整流量的扇出或速率。当前三臂仍固定P，先检验源端口机制；不将这份元数据审查变成支持集重选或新窗口特征实验。详见[原始元数据补核](research_alignment_20261108/scanning_mechanism/data_semantics.md#原始元数据补核)及[聚合结果](research_alignment_20261108/scanning_mechanism/raw_metadata_audit.json)。

## 固定三臂及干预定义

三臂均使用第十四轮同一P/C/E、8192条支持和原二分类标签／顺序、同一冻结TabICLv2权重、完整KV。只改变源端口第0槽；目的端口、IP协议、L7及其余44字段均保留。各臂从对应P输入重新构建完整上下文缓存，不能只改变查询而复用B0缓存。

| 臂 | 输入干预 | 要回答的问题 |
|---|---|---|
| B0 `baseline` | 第十四轮新表示，原冻结预处理 | 复现已有完整KV工作点 |
| B1 `src_frequency_bijection` | 源端口按P出现频次分层双射，冻结原缩放 | 保留身份、已见关系和P单列分布后，数值排列是否参与失检 |
| B2 `src_mask_zero` | 冻结FP32输入的源端口槽置正零 | 删除源端口信息后，正常与扫描的区分如何变化 |

**B1的构造。** 对合法域$V=\{0,\ldots,65535\}$，只用P源端口统计$c(v)=\sum_{i\in P}\mathbf{1}[v_i=v]$，令$S_k=\{v:c(v)=k\}$。每个$S_k$内的升序值，依次映射到同层按SHA-256键排序的值；键为紧凑UTF-8 JSON数组`["src-port-frequency-bijection-v1",20261108,k,v]`，哈希相同以整数值排序。零频层包含所有P未见端口，单值层保持不动。只用这一映射，不因E结果重选种子。

这给出全域双射$\pi$，满足$c(\pi(v))=c(v)$，因此P源端口多重集合保持不变。使用第十四轮保存的中心$\mu_P=35989.91845703125$和尺度$\sigma_P=21268.044830665465$：

$$z_{\mathrm{src}}^{B1}=\operatorname{FP32}\left(\frac{\pi(v)-\mu_P}{\sigma_P}\right).$$

不重新拟合缩放或其他字段预处理。P的源端口FP32边缘多重集合不变，任意两行源端口相等关系、P已见／未见关系以及完整48输入相等关系均保持。C/E的源端口分布不保证不变；相应分数和校准阈值的变化需分列。

实际映射只在实验室由P构造，并在首次模型评分前保存。摘要是按0—65535顺序排列的little-endian uint16表的SHA-256，共131072字节。必须报告各频次层固定点，以及P/C/E、54条目标行、15条完整P匹配行的实际变动比例，同时报告编号位移、端口区间和源／目的端口相等关系的变化；若目标未被改变，不得借阴性结果排除源端口解释。

**B2的构造。** 在原冻结预处理之后将第0槽置`float32(+0)`，其余47槽逐位不变，仍为48列。零表示原标准化中心，不是原始端口0。绕过再次常量列筛除；低层推理使用固定48列，不改列顺序。该臂有意删除信息并可能制造异标签碰撞，须审计实际FP32输入碰撞，不能把它描述成保真变换或预定部署方案。主47字段模式的217条E扫描与33条正常将在B2成为同输入：确定性逐行判决的总错误至少33条，这不是33条必然漏检，也不等于已经证明模型如何使用源端口。

三臂不改变类别先验、不重选P、不增大N、不用family作输入、不加ensemble、不训练权重、不接QCOC／CRT。B1保持P边缘的限制是本项目的诊断控制，不是新学习算法；它可能破坏真实端口区间及源／目的端口之间的相等关系，不能仅由敏感性宣布原编号是伪相关，或将影响独归于某一种距离。

## 实验室验收与结果解释

输入、权重和原预处理SHA见[机器可读设计清单](research_alignment_20261108/scanning_mechanism/design_manifest.json)。保留当前P8192／正常C5000／E20000、seed20261107、CPU FP32单线程评分、查询批128；映射种子20261108是独立固定常数。CUDA只用于构建。正式工作量为3次完整上下文构建、15000条C评分、60000条E评分，0优化器更新。

先复核B0与第十四轮已登记分数／阈值／判决的一致性，再处理B1/B2。分数和阈值的逐项容差固定为$3\times10^{-5}+3\times10^{-5}|s_{\mathrm{old}}|$，C/E逐行判决必须一致；有不一致时先定位运行差异，不放宽容差、调整阈值或改基线记录。每臂仅由本臂同一正常C登记$\alpha=0.01$、序位4951、严格`>`的阈值。E在机制设计前已经打开，此次只作机制定位，不用于映射选择或独立确认。

输出必须覆盖：

1. 三臂全量逐行C/E分数、阈值与配对判决；整体TP/FP、所有攻击族、扫描对正常的总体AUC，以及FPR区间$[0,0.01]$内的ROC面积和该面积除以0.01的结果。相同分数同时计入、边界线性插值，不另作标准化，不从E选阈值。
2. 旧54条丢失、15条完整P扫描匹配、TCP6／dst443／L7=91子群，以及主47字段模式的217扫描／33正常。子组只用于报告，不能进入输入干预或P选择。
3. 原始分数变化、C中的经验分位变化、阈值变化分开；不把不同臂原始分数阈值的数值大小直接当难度比较。
4. B1映射覆盖与全部不变式；B2实际输入碰撞与标签冲突。保存真实映射和三臂工件身份，以便独立复算。

| 观测结果 | 可以支持的解释 | 后续决定 |
|---|---|---|
| B1实际改变目标编号，目标分数或判决随之改变 | 在支持身份／P单列分布不变时，具体编号参与模型输出 | 研究编号关系对目标和正常流的共同影响；不能把某次偶然改善直接推广成新编码 |
| B1使扫描回升但正常误报或其他族明显恶化 | 表示影响存在，改善仍是有代价的取舍 | 不选其作为赢家，不为它另调阈值／种子 |
| B1目标逐行分数差均在上述数值容差内、判决相同，且目标确实被扰动 | 这一次受控重编号没有解释目标错误 | 下调该特定解释；不宣称所有表示等价 |
| B2出现新的异标签投影碰撞 | 被删除字段原本提供输入区分信息 | 单凭碰撞不判断模型是否实际使用该信息 |
| B2产生超容差的分数变化或判决变化 | 模型对删除源端口这一干预有响应 | 与碰撞分析合看，记录修复／新增，不预定删除方案更好 |
| B1/B2在目标子组均无超容差分数变化、无判决变化，且B1已有效扰动 | 本次两个源端口干预没有解释目标错误 | 停止该干预分支，结合原IP／时间审查决定是否有证据另立跨流信息问题 |

机制敏感性与检测收益分开登记。若某干预净TP>0、净FP≤0，可称这份开发数据上的总体改善；Scanning及其他族回退仍逐项报告。单一固定映射不提供总体不变性检验，也不作多映射显著性推断。任何据此提出的新表示或上下文方法，须在新的冻结训练／校准协议和未打开确认材料上检验。
