# R30 训练轨迹、缓存分数与成本核验

本次回传的六条训练轨迹完整，选轮和早停按登记规则执行。保存的 `best.pt`、`model.pt`、summary 与 freeze 哈希逐一相同；没有发现选错权重、训练未覆盖小组、持续梯度裁剪或冷载分数改变的证据。训练任务已经取得实质性拟合进展，但留出集仍显示跨协议正常尾部与 B 正例低分尾部交叠，不能把剩余问题全部归为标定，也不能据此宣布模型设计已经完善。

核验仅读取已归档 JSON、parquet、NPZ 和文件字节；未加载模型、未前向、未训练、未搜索阈值或生成部署决策。复核脚本为同目录 `training_audit.py`，输出为 `training_audit.json`。脚本用 `score_identities.json` 的 `(source_id,row_id)` 对齐 F/V，再独立计算已缓存分数的组 BCE、标准化 pAUC 和正负排序。

## 3. 两个 V 面板满分，为何 pooled 仍不满分

blind 的 A_TCP、B_UDP 面板均 pAUC=1，且正负严格分离；全 V 却仍存在真实排序交叠。交叠全部涉及 B 的 UDP 正例低分尾部与 A_ICMP、A_TCP、B_TCP 正常流，B_UDP 正常流没有越过 B 正例。三个种子的交叠正例身份完全相同，共 39 行，每个 B_i300 单元 13 行。

| blind 种子 | B 正例 min / median / max | 最高 B_UDP 正常分数 | B 正例低尾与 B_UDP 正常的严格间隔 | 发生逆序的正常组 |
|---|---|---:|---:|---|
| 17 | −3.641 / 16.194 / 41.978 | −17.241 | 13.600 | A_ICMP、B_TCP |
| 29 | −5.923 / 16.494 / 28.751 | −15.622 | 9.699 | A_ICMP、A_TCP、B_TCP |
| 43 | −6.124 / 25.338 / 51.313 | −10.620 | 4.496 | A_ICMP、A_TCP、B_TCP |

对应 aware 的 B 正例 min / median / max 分别为 1.031/10.499/17.046、1.439/5.211/7.867、1.568/8.746/14.849。blind 的中位数和上端更高，只有一部分正例落入低分尾部，不能称为 B 正例整体负移。F/V 全部 profile×protocol×label 组的 min、q10、median、q90、max 和 BCE 已保存在 JSON 的 `score_distributions`。

跨组逆序对数分别为 201、472、259；这些是冻结分数的排序描述，没有拟合新的阈值。39 行是低于至少一个 V 正常分数的正例数，**不等于部署漏检数**。NLL 较高也不等于固定部署阈值判错。实际部署问题须以归档 C 阈值和 E_B/E_D 决策为准。

这使“剩下的只是标定”缺少依据：V 已能观察到排序交叠，排名和分数尺度都需要解释。同时，不能由 V 交叠直接断言 E_D 的超预算误报就是同一个机制。

## 4. 成本与冷载

六个模型均 416704 参数、1742942 字节。CPU 单线程、含预处理的热单行 p50 为 1.556–1.575 毫秒，p95 为 1.782–1.900 毫秒；batch128 吞吐 2455–2484 行/秒。单独模型计算 p50 为 1.075–1.083 毫秒，预处理 p50 为 0.337–0.354 毫秒。整 worker 进程 RSS 峰值为 632.5–633.8 MB，该数包含 Python 和依赖基线，不是模型独占内存。

冷工件加载耗时 2.490–2.527 秒，不含 Python 启动，OS 文件缓存未控制。六个模型冷载分数和预转换输入分数均与登记路径完全相同。单行调用相对登记批量路径最大分数漂移不超过 2.291×10⁻⁵，GPU512 不超过 2.286×10⁻⁵；各自已测样本在登记 CPU 阈值上均无决策翻转。GPU512 吞吐为 139907–158065 行/秒，每个模型仅 3 次重复，用于描述这次运行。

R29 同机 TabM+PLE 的 CPU p50 为 1.556–1.576 毫秒，batch128 吞吐 2439–2477 行/秒，冷载 2.465–2.480 秒。R30 的部署成本处于同一量级，没有本轮轻量化收益证据。工件从 R29 的 1676606 字节增至 1742942 字节，不能称为压缩改进。

## 5. 与 R29、R26 能比较什么

R29 到 R30 同时改变了训练支持（加入 A）、组权重和采样、V 面板及排名选轮、最终重训方式；R29 有最终 P 重训，R30 只有六个 F 轨迹且 final_refits=0。跨轮整体改善可以描述，但不能唯一归因于 A、去协议、组采样或某一项修改。R30 两臂的配对比较只能识别这套共同合同下是否保留显式协议输入的净效果，并包含由此产生的训练时长差异。

R26 的 target 支持有 10682 行，其中 180 个 ExternalC2 正例；R30 F_B1 只有 90 行，另加入 F_A1 的 5123 行。R26 的 source/mixed 支持、模型族与权重合同也不同。R26 可作历史效果参照，不能作为相同数据、相同更新步的结构消融；该回传没有与 R30 对应的独立冷载/部署延迟成本文件。

本次可保留的结论是：监督与训练合同已让模型学会现有任务的重要结构，权重交付和推理复现链路有效。尚未成立的是：D 既往漏检已被唯一定位、正常尾部问题已经解决、去协议本身解释了跨轮大幅改善、或下一次训练必然成功。下一步设计判断应使用本次冻结的跨组排序、实际误报行和登记决策共同定位信息与目标的缺口，不能只因 pooled pAUC 接近 1 或调低 NLL 就重新安排训练。
