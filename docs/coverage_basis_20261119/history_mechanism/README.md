# 历史摘要的实际机制判断

建议从下一次拟合方案中删除固定的 19 维历史臂，不运行 HGB27 来碰运气。保留代码、冻结表和本次逐事件结果，作为这条方案为何撤下的证据。这里否定的是“上一条流 + 全前缀均值 + 间隔 + 同端点 + 空历史”这一具体组合用于控制与下载的依据；控制通道中的重复通信确实存在，不能把本结论写成所有历史信息都无用。

本次只读取既有数据，检查 254 个 santos/fox 动作、24 个 OpTC Empire 控制连接、1 次已证恶意下载、1 次关联重复传输，以及 5,026 个正常网页文件对象。共输出 5,306 个事件/对象、6,401 个事件—候选—主机视角明细，所有原候选都有历史记录。拟合、模型评分、阈值计算均为 0。没有改 F/V/C、mapper 或冻结观察表。

## 真正下载指令没有进入下载查询的过去

AIT 的 4 次下载均能用 actor 日志中完全相同 URL 的 `wget` 命令关联到明确的控制动作及成功回执。控制与下载是不同 TCP。问题是，完整控制流的导出均不早于下载流的查询时刻：

| run / 对象 | 触发指令的 actor 行 | 控制导出减去下载导出 | 查询前可用 |
|---|---:|---:|---|
| santos / WPHashCrack，较早候选 | 376 | +17.203102 秒 | 否 |
| santos / WPHashCrack，较晚候选 | 376 | 0 秒 | 否，同批查询后更新 |
| santos / password list | 386 | 0 秒 | 否，同批查询后更新 |
| fox / WPHashCrack，较早候选 | 849 | +30.495563 秒 | 否 |
| fox / WPHashCrack，较晚候选 | 849 | +0.001553 秒 | 否 |
| fox / password list | 859 | 0 秒 | 否，同批查询后更新 |

因此，这套完整流摘要在本次 4 个下载动作上都没有读取真正的 `wget` 指令连接。把控制流的结束时间替换为其开始时间，或者让同导出时刻的记录互相读取，会改变已固定的可用时间合同。不能据此补成“先看到控制，再识别其下载”的成功机制。

actor 命令和 URL 用于核对行为及顺序，没有进入网络特征。OpTC 的已知控制与下载只有作者动作、进程及网络关联支持；本次没有把它们升级为某条控制消息导致下载的因果边。

## 上一条实际保留了什么

下表列全 6 个 AIT 下载候选，不从一个动作中挑最有利的一条。

| run / 对象 / 候选 UID | 上一条连接对应的证据 | 已完成先行动作的候选是否全已可用 | 前缀流数 | 已确证同链流数 |
|---|---|---:|---:|---:|
| santos / WPHashCrack / CwXMJf1cqy4ultcTI2 | 更早的 mysql 查询，actor 行 366 | 28/28 个动作：是 | 5,275 | 27 |
| santos / WPHashCrack / C31x88Ktas8beE4u7 | 未标注背景，CkfUn84KIXFqcfVFO5 | 28/28 个动作：是 | 5,280 | 27 |
| santos / password list / CCXIoY2v3POzsti4f | tar 解压，actor 行 381 | 31/31 个动作：是 | 5,283 | 29 |
| fox / WPHashCrack / CyyYte1hKA3vEfNQt4 | 更早的 cat /etc/profile，actor 行 839 | 13/13 个动作：是 | 11,488 | 12 |
| fox / WPHashCrack / COqx2c3viED3yTs56g | 未标注背景，CZ8coB1ExnfT2tvB12 | 13/13 个动作：是 | 11,494 | 12 |
| fox / password list / Cjaku94eD7bn5eoPj2 | tar 解压，actor 行 854 | 16/16 个动作：是 | 11,497 | 14 |

两次 WPHashCrack 的较早候选保留了更早同链命令，较晚候选均已被背景流覆盖。两次 password list 保留的是脚本中先执行的解压命令。这说明“更早同链动作可用”与“固定最后一个槽保留有用关系”是两件事。santos、fox 使用同一攻击脚本家族，重复出现相同顺序不能算两种独立控制实现。

OpTC 已证下载的前缀中有 24 个已知控制连接、336 个未定性质的连接。24 个控制在既定的 `offline_flow_end_replay` 下均已结束，最后槽却是未标注的 CzaMrB33RmJ7Z8NAdh；最后已知控制距查询约 972 秒。重复传输的前缀是 25 个已知链连接加 338 个未知连接，最后槽仍是未知连接。这里的 25 包括前一次已证下载，重复传输本身仍只有关联标签。

控制阶段有明确的局部正证据：OpTC 后 23 个控制都把上一控制留在最后槽，且同端点；AIT 控制候选中，santos 26/45、fox 12/21 的最后槽是已确证同链流，另有 5/45、4/21 为同链候选。这支持研究重复控制通信，却不能把下载阶段缺失的指令记录补回来。

## 正常下载给出的反例

按完全相同的历史规则分析全部正常下载，未按大小、端点重复或最后槽类型挑样本。动作多候选、同一连接承载多动作均保留；下表按唯一连接视角计数，避免重复加权。

| 正常业务集合 | 动作/对象数 | 唯一候选父连接 | 最后槽：整流 normal / 正常动作候选 / 未知 / 空 | samepeer = 1 |
|---|---:|---:|---|---:|
| santos ownCloud | 44 个动作 | 375 | 231 / 37 / 107 / 0 | 347/375 |
| fox ownCloud | 42 个动作 | 406 | 218 / 24 / 164 / 0 | 327/406 |
| OpTC 网页图片和 CSS | 5,026 个对象 | 559 | 101 / 384 / 73 / 1 | 469/559 |

86 个 AIT 正常下载动作全部至少有一个 samepeer=1 的候选；其中 santos 22 个、fox 11 个动作的全部候选均为 1。两个 run 的候选 peer 各自只有一个值，分别是云盘前的代理地址。AIT 的 6 个攻击下载候选却全部为 0，OpTC 两个下载/传输为 1。这个比特在不同场景中反映了代理和端点布局，现有证据不支持把它解释成跨场景的恶意控制关系。

正常 ownCloud 观察在 cloud_share，攻击下载观察在 intranet_server；正常集还包含同 intranet_server 的 111 个普通页面读取动作，详表一并输出。不能把不同服务位置之间的差异当作攻击意图差异。OpTC 的 5,026 个对象也不是 5,026 条独立流；其中整流正常资格与正常对象关联在结果中分列。

## 全前缀均值保留不了动作关系

6 个 AIT 下载候选的均值覆盖此前 3.865–4.054 天、5,275–11,497 条流。已确证同链流占计数的约 0.10%–0.55%，另有少量同链候选；这些比例不是各数值维度的判别贡献。已证正常流、正常动作候选及大量未知背景均一起进入均值，未标注背景不能被称为正常或无关。

该均值是 log1p 后逐维平均，保留总体分布，丢失先后顺序、端点归属和哪条指令对应哪个对象。已知链只占少数不等于均值数学上必然无效；本次能确定的是，没有证据把这 8 个全局均值对应到本任务所需的控制—下载机制。长历史本身并非错误，成熟方法采用长历史时保留了特定的协议或实体状态，见 method_comparison.md。

## 采用判断与文件

撤下当前固定 19 维训练臂。不能把删去全前缀均值、调整窗口或改成按 peer 记忆再包装成下一轮必做实验；本次资料没有确定这些替代方案的采用资格。单流强基线的既有数据资格不受本判断影响。本轮对算法主线的新增成果是确定了一个可用时间上的失败原因，以及该具体摘要不能承担的解释。

- `event_history_evidence.jsonl.gz`：5,306 行逐事件/对象证据，保留 actor 来源、全部候选及每个先行动作的可用情况。
- `candidate_history_evidence.jsonl.gz`、`all_event_candidate_history.csv`：6,401 行候选级记录；CSV 将前缀五类计数展开。
- `attack_download_details.json`：6 个下载/传输事件，含 4 次 AIT 的精确 URL 指令关联及导出时刻。
- `summary.json`：动作级和唯一连接级分母，真实模型调用计数均为 0。
- `analyze_history.py`、`source_receipt.json`：可复算脚本及输入 SHA-256；脚本断言历史总数等于冻结 context、最后槽严格早于查询且同组同主机、samepeer 与输入端点一致。

AIT 的时钟是离线 Zeek 实际导出时记录的 network_time，不是部署接收时钟；OpTC 是明确的流结束重放。两者没有合并成在线早检测结论。旧 AIT 表、F/V/C 分配、模型代码均未改。
