# 本次结果能支撑的研究范围

当前采用范围收束为：用可核实动作与正常业务标签评价单流强基线，控制和下载分别报告，再按完整链报告覆盖；删除固定 19 维训练臂。HGB8 已有输入与监督资格，本轮没有得到应替代它的新历史算法。

历史方面唯一有实际正证据的具体问题是：**在同端点重复 C2 中，过去已经完成并导出的连接重复性是否提供单条流缺少的行为信息？**这里的可观测量是同监控主机—对端的重复连接与连接间隔，单位是重复通信过程。OpTC 后 23 个控制查询的最后槽都保留前一控制；AIT 两个 run 的控制阶段也有此现象。EarlyCrow 的重连、连接间隔和端点 profile，CESNET 的同 client—server—service 周期序列，已经把这种机制具体化。因此本项目可以把它列为成熟参照的研究问题，不能称为本文新算法，也不能仅凭本次攻击正例直接新增其训练实验。

下载问题应写成：**在下载候选连接导出时，现有网络观察能否将实际恶意对象传输与正常业务传输区分？**当前 actor 真值能证明 AIT 的具体 `wget` 行为，却不能令其尚未导出的完整控制流提前成为模型输入。4 次下载均出现这个可用时间约束；两次较晚 GitHub 候选还丢失了最后槽里的更早同链命令。OpTC 下载前的控制关联也没有逐命令触发真值。把这两种来源合并后训练一个关系模块，无法补出所缺的观察与监督。

据此，不支持下列原创声明：由历史摘要恢复控制—下载因果链；学习到与实现和场景无关的动作关系；19 维对恶意语义作了有效压缩；按真实在线时钟提前识别了下载。也不支持把上一条改成短窗口、端点记忆或新损失后直接启动下一轮。此处没有确定这样的替代机制。

本轮的确定成果是一个会改变方法选择的负结果：**完整流导出时钟使真正的下载指令在目标查询时不可用，而固定最后槽与全前缀均值不能可靠保留较早动作关系。**这足以撤下当前历史臂。论文若仍要求算法原创，需要另有成立的机制证据；本报告没有把成熟重复 C2 特征或观察口径修正冒充原创算法。
