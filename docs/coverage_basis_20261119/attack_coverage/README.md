# 攻击实现覆盖：实际来源装配结果

**当前版本已完成整件 PCAP 与全捕获装配，见 [完整来源说明](full_capture/README.md)。** 目标主机 12,824 条连接含 Normal 12,308、C2 473、其他攻击 11、未知 32；全部 12,582 条合法作者流均有原包核对证据。核心表位于 `full_capture/`，已通知统一表装配使用该版本；两个片段只作历史。新增 C2 监督已可用，攻击下载实现仍未补齐。

## 以下为先前片段装配历史

本轮新增了 Unraveled 的 **5 条完整 C2 通道连接和 16 条完整正常邮件 HTTPS 连接**。控制与正常业务都来自 10.1.3.8，同属一个作者采集环境，目的端口均为 443。当前可使用这些连接作已开来源的输入与标签核对；新增材料还不能作为整条攻击链的 F/V 材料。没有运行训练、模型前向、阈值搜索或性能实验。

## 新 C2 标签的证据

作者原始流表对 flow id `38783`、`39070`、`38807`、`39146`、`39707` 各自给出五元组、毫秒首末时刻和 `Exfiltration over C2 channel / Data Exfiltration / APT` 标签。这是逐流 C2 标注，不是把该主机的全部流量统标攻击。五条连接均为 `10.1.3.8 → 10.8.10.84:443`。

对应 PCAP 原字节已下载，Zeek 8.0.11 `-C` 解析为已建立 TLSv1.3 通道。每条连接都核对了：

- 原表与 PCAP 的五元组、毫秒首末包时间、双向包数和双向 L2 字节数完全对应；
- 原片段含 SYN、双向 FIN，Zeek 状态为 SF、`missed_bytes=0`；
- raw8 来自本次 Zeek 原记录，未把 NFStream 的 L2 字节冒充 IP 字节，也未把两者时长定义强行改成相同。

因此这 5 条保留 **B 级作者逐流 C2 标签 `label=1`**。没有取得对应 implant 的 PID 和具体执行命令，不把这些连接当作 5 次已知命令。作者列出 Covenant、Metasploit 和 Windows Sliver，但没有逐流框架对应表；框架名称未定不构成拒收逐流 C2 标签的理由。

作者 README 给出四类标签的含义；本次已取代码树和工具代码中未找到实际赋标程序。故不能声称独立复现了作者真值生成过程，也不能反向断言作者一定使用端口规则。原始流表是本轮 C2 真值来源，PCAP 是连接与输入证据。

## 正常业务与完整性

目标主机的行为日志记录了 `privateemail.com` 导航、成功登录和退出。16 条完整连接同时满足作者 Normal 标注、该主机/域名、TLS SNI、实际浏览时段和全部包完整性核对，保留 **B 级正常业务标签 `label=0`**。它们是正常邮件网页业务，不冒称正常程序下载。

主机日志未带时区。导航时刻 `2021-06-21 08:11:58.719` 与同域名 TLS 起始 `15:11:58.762 UTC` 相差 7 小时加 43 毫秒，据此记录时钟对齐推论；尚无系统时区配置原件。成功登录在主机时钟 08:12:25.321，退出在 08:35:26.720。本次 PCAP 只覆盖该 episode 的前段，不能拿这 16 条当完整正常 episode 或自然流量比例分母。

完整保留两个片段的 **381 条背景连接**：5 条 C2、16 条正常业务、360 条未知。25 个目标候选中还有 1 条 C2、3 条邮件连接被右边界截断，它们全部保留，标签为 null；其他背景也不因为非攻击地址或作者缺标签就自动变成正常。

两个原字节片段的实际范围：

|---|---:|---:|---:|
| normal_mail | 1624288297.209179–1624288473.428742 | 4,564 | 5,254,396 B |

选取依据为已声明业务/攻击时间，无模型评分。片段是原 PCAP 的连续记录区间，加回同一原件的全局头；`caplen`、`orig_len`、包字节都未修改。两片段均未发现 `caplen<orig_len` 或实存帧短于 IPv4 声明长度。片段不代表整天历史；`available_at` 保持 null，保留离线 Zeek 导出时钟。

作者 6/21 流 CSV 有 45,960 条宽度正确记录、177 条列数异常记录；6/22 为 38,280 条正确记录、117 条异常记录。所有异常原行已留在 `network_mapping/malformed_author_rows.jsonl`，没有靠移列猜标签。

## 可使用范围与下一动作

现在可把 **5 条已知 C2 与 16 条正常 443 业务**加入开发来源覆盖表，检查统一 raw8、时间字段、来源分组和控制类别是否正确。这些标签已写入 `network_mapping/connections.jsonl`；尚未分配 F/V，`training_eligible=false` 与标签未知是两个概念。

目前不能声称：这 5 条构成独立的 5 条攻击链、已知每次执行命令、已经补足下载实现、具备完整正常率分母、或拥有整条新实现 F/V 链。补齐同一 C2 的更多重复流也不会补上下载动作。

已取得的完整作者日流表给出了下一步的数量依据（`full_author_day_summary.json`）：目标主机共 12,582 条合法作者流，含 12,100 条显式 Normal、473 条显式 C2、9 条远程发现。TCP 目的端口 443 上有 5,050 条 Normal 和 473 条 C2；按 TLS 应用名筛选则有 5,128 条 Normal 和 473 条 C2。同一受害 IP 上两类标签并存，说明不是把整个受害主机统标攻击；但控制服务器 10.8.10.84 的 473 条流全标 C2，现有证据不能排除按控制端点/时窗赋标。

**下一必要动作是一次取完并提取这一件 net1013x PCAP，装配所有显式 Normal/C2 与未知背景，不必换来源。** 原件为 3,518,820,352 B（3.277 GiB），匿名范围访问已验证且 ETag 固定；当前未启动全量下载。作者标作 6/21 的文件实际覆盖 UTC 6/21 07:08:58 至 6/22 07:29:02，不能当成 UTC 自然日。完整原件能补齐同场景控制和正常分母，仍是同一攻击 campaign。

作者显式逐流 Normal 可按来源等级保留；不要求每条正常流额外具备进程日志。未标注、Background 和列数异常行不能据此转成 Normal。全量关联时仍需处理 NFStream 分流与 Zeek 连接边界差异：保留全部候选，出现混合/冲突标签就保留未知，不强行一对一。

下载实现还缺具体下载 URL/文件对象与发生时刻。现有 6/21、6/22 已取流表没有下载动作标签，已取 host audit 也没有该 payload 下载回执。完整提取可以补控制覆盖，但不能仅凭“首次 C2 前的普通 HTTP”猜攻击下载；这项缺口应独立保留，不用它拒收已有 C2 真值。

IEU-C2D/C2Detector 作者 README 明确公开内容为交互状态序列；目录中的 C2.zip 为 1,860,186 B。论文实验原流量 2.57 GB 不等于公开了 PCAP。当前公开件不能完成所需动作—网络连接—正常业务装配，因此本轮未准入该来源。
