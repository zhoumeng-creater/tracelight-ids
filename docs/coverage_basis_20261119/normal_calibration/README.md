# 历史 v1：russellmitchell 正常校准候选与后期业务验证

**本页以下结果保留为历史，当前消费应使用 `v2/`。** v1 将 SF 和活动明确结束误当成正常身份的必要条件，这是本轮额外加上的限制，不是作者标签规则，也不是固定 raw8 合同的要求。修正版将正常标签证据、输入质量和整来源角色分开：全 run 有 3,475 条正常证据充分且输入可用的连接，33 次精确匹配的正常下载完成动作；详见 `v2/README.md`。

旧 C25 在 v1 有 9 条被这两项附加门槛排除：6 条仅因非 SF（S3 三条、RSTO 三条），另 3 条仅因已知正常用户的 ownCloud 活动没有明确结束。九条均没有未知客户端或攻击请求；没有证据推翻原正常 actor／请求事实。v2 的 25/25 均保留正常标签与当前输入。v1 的 `normal_identity_qualified` 混合了身份、输入和活动完整性，不应继续解释为作者正常真值。

已从完整来源装配可直接消费的正常连接表。早期候选 C 为 **365 条连接、39 个业务 episode、39 个依赖组件**；后期正常时段验证为 **618 条连接、40 个 episode、38 个依赖组件**。文件业务仍少：早期 ownCloud 的 3 个完整活动中，只有 1 个活动产生了已核实的文件下载；这 **1 个服务请求、1 次正常用户下载完成动作**对应 6 条可能连接，不能说成 6 次独立下载，更不能用 365 条总连接替代文件业务覆盖。

按服务请求与正常用户的精确文件对象、开始—完成时间去重后，早期 C 是 1 次下载动作／1 个请求／6 条连接候选；后期正常验证是 17 次动作／17 个请求／72 条连接候选，涉及 5 个活动；角色未定部分是 7 次动作／7 个请求／34 条连接候选。`owncloud_file_transfer_request` 分层名称表示连接时间范围内存在该请求的可能关联，不代表已唯一确定每条连接都传输了文件。

## 原件与装配依据

只读取已打开的 russellmitchell 来源。共核对 12 份 Apache 完整轮转日志、4 份内部用户状态机日志、作者服务器映射、有效期文件以及该服务唯一相关的 intranet 攻击标签文件。新增下载仅为四份缺失的 cloud 后端／代理日志，压缩共 285,461 字节；其余从已有原件复用，均按 ZIP 目录 CRC、大小与 SHA256 留收据。

作者将 russellmitchell 有效期定为 2022-01-21 00:00 至 2022-01-25 00:00，并规定通过原日志行号对应攻击标签；没有对应攻击标签的日志事件属于正常行为。这里只将该规则用于原服务日志，再结合正常用户活动和整连接的全部候选请求，未直接给整段网络流量赋正常标签。[AIT 作者说明](https://zenodo.org/records/19483937)

已有 intranet 原始 PCAP 按 `source-fit-contract-v1.1`（commit `793f1d4f59bdce4c3e82176bf6be84186deee224`）的固定规则完成一次全捕获提取：11,000 条连接；cloud 复用同合同已有的 21,925 条完整连接。规范化仅提升满足条件的记录 `orig_len`，不改变原件、捕获字节、时间戳或 `caplen`。统计口径为声明 IP 数据报长度。源码快照及文件哈希见 `code_source_receipt.json`，运行环境见 `runtime_receipt.json`。

16,374 条目标服务连接全部保留为候选，1,253 条获得整连接正常身份依据。候选必须有完整 SF 连接、完整 raw8、位于作者有效期内，且其整段时间内的全部可能服务请求都有正常活动依据。ownCloud 另核对代理前端与后端请求身份，保留所有可能客户端；VPN／未知客户端或活动不完整不会因访问同一服务而变为正常。该证据没有唯一确定 Apache 请求的客户端 TCP 端口，因此表中标注为有条件的整连接正常身份，而非逐请求唯一关联。

episode 使用原状态机从选择目标业务到明确返回活动选择的完整活动边界。包括未结束、跨日活动在内的全部候选关系都保留；可能由同一连接关联的活动组成依赖组件。先固定早期／后期日期，再按完整组件分配，不按连接数、流量形态或分数调整日期。270 条连接本身已有正常身份依据，但其组件关联未结束活动，因此角色未定。20 条跨日连接候选也整体保留未定。

## 可消费文件

- `C_candidates.jsonl.gz`：365 条早期候选 C；每行含 raw8、固定的 8／27 维输入、正常身份依据、活动与依赖组件 ID、完整上下文引用。
- `normal_time_validation.jsonl.gz`：618 条后期正常时段验证，格式相同。这是已打开来源内的时间分配，不是新的盲测来源。
- `qualified_connections.jsonl.gz`：全部 1,253 条已获正常身份的连接，含 270 条角色未定记录。
- `connection_candidates.jsonl.gz`：全部 16,374 条服务连接候选及逐条未通过原因，不能把未定行当正常。
- `business_episodes.jsonl.gz`、`dependency_components.jsonl.gz`：255 个源活动及其完整分组关系；实际进入两侧消费表的活动为 79 个。
- `request_evidence.jsonl.gz`：每条 Apache 原始成员、行号、哈希、作者标签、用户活动候选及代理关联依据。
- `file_business_evidence.json`：去重文件请求、全部连接候选、精确对象／时间对应的正常用户下载完成动作；文件业务计数使用此表，不能直接数候选连接。
- `context_inputs.jsonl.gz`、`context_rows.jsonl.gz`：25,638 个完整主机视角的固定历史上下文。完整捕获的无标签背景也进入历史，含有效期以前的捕获记录；消费连接自身限定在作者有效期内。时间使用离线 Zeek 导出 network_time。
- `historical_C25_disposition.json`：保留原 C25 身份和旧收据，不改历史判定。25/25 raw8 与当前出口相等；按本轮更完整的活动分组，9 条落入后期正常验证，16 条角色未定，均保留曾作为 C 候选打开的事实。
- `summary.json`、`assembly_check.json`、`output_receipt.json`：日期／业务分层、14 项装配检查和工件哈希。

14 项装配检查通过：连接／活动／依赖组件无跨角色交叉，角色由固定日期确定，正常身份均有完整请求依据，raw8 与上下文引用存在，历史严格早于当前记录，跨日连接未拆分，旧 C25 原输入一致。没有拟合、评分或阈值计算。

## 目前能支持什么

这批实物支持分开报告 intranet 浏览与 ownCloud 工作流在早期和后期的经验误报；也支持按 episode／组件统计重复与相关性。它不构成总体误报率不超过 1%、置信度 95% 的证明。NP 顺序统计保证要求相应的独立同分布样本及训练／校准独立性；作者还明确将样本同质性列为该方法的限制。这里是同一次模拟、少数用户、共享服务与生成机制下的相关连接，39 个组件也未经证实为 39 个独立总体样本。[Tong、Feng、Li 原文，第 4、8 页](https://jsb-lab.org/wp-content/uploads/2018/02/ScienceAdvances_eaao1659.full_.pdf)

若要对文件传输单独作稳定的低误报判断，当前最明确的缺口是早期 ownCloud 只有 1 次已核实下载动作；不能用其 6 条可能连接、284 条浏览连接和 75 条界面/API 连接填补这一缺口。
