# R29 输入与架构修订评审

日期：2026-11-17。状态：设计评审完成；新候选判决尚未计算。证据数值、文件路径和 SHA-256 见同目录 `information_and_architecture_review.json`。

## 1. 明确选择

下一步只保留一个不训练候选：冻结既有 `source-raw8-hgb ∪ fixed rule`，复用 R29 三个 PLE 模型的原始缓存分数，仅把增量通道阈值限制为不低于 BCE 原生判界 0。三个种子分别评价，不挑最好种子。暂不增加特征、协议头、pAUC 损失或模型宽度。

这个选择针对两个已经分开的失败：新模型替代旧通道会丢失旧 TP 身份；极低的 C 阈值又把大量训练域正常流量释放为报警。保留通道从结构上解决前一项；原生判界下限限制后一项能够释放的报警集合。两者都不依赖再次训练才能发挥作用，因此应先用现存缓存做一次预先固定公式的判决验证。

该系统包含使用源数据和端口的旧 `raw8` HGB 及固定规则。结果应表述为保留基线后的系统增量，不能归为同输入、无端口的 TabM 结构收益。

## 2. 公式、确定作用与未决问题

记冻结保留通道为 $b(x)$，种子 $s$ 的原缓存分数为 $z_s(x)$，原始 C 校准阈值为 $t_{C,s}$。固定候选为：

$$
t_s=\max(0,t_{C,s}),\qquad
\hat y_s(x)=b(x)\lor\bigl[\neg b(x)\land z_s(x)>t_s\bigr].
$$

严格大于号及有限值处理须沿用冻结协议。这里复用原始 C 阈值，不根据 ED 调整，也不在零附近扫描。

现有分数定义是各成员 sigmoid 概率取均值后再取 logit，所以 $z>0$ 对应该均值大于 0.5。0 的依据是本次冻结的 BCE 概率表示；对分数任意平移后仍套用 0，已是另一个算法。

公式有三项集合性质：

1. 保留通道原有的全部报警身份均保留，旧 TP 不会被增量通道否决。
2. 增量报警集合是原始低 C 阈值下增量报警集合的子集。
3. 相比直接 OR 原始低阈值判决，FP 不会增加，增量 TP 可以减少到零。

这些性质没有给出新增 FP 为零、B 检出 72/72、每个 cell 满足 1% 或保住 R26 MLP 全部 TP 的保证。训练 P 在原生 0 判界有 0 FP/180 TP，只说明该缓存上的训练拟合；D 的输入分布和排序仍需固定判决检验。本设计使用了既有开发结果，是后验提出的候选，不能把同批 ED 再次评价写成独立泛化确认。

## 3. 为什么直接 OR 不够

下面仅对两组**已经存在的原阈值判决**做集合合并；没有计算本节新提出的零下限候选。

| 既有判决 | B：TP / FP / 合格 cell | D：TP / FP / 合格 cell |
|---|---:|---:|
| 旧 HGB∪规则 | 66 / 12 / 3 | 1694 / 15 / 12 |
| 上项 OR R29 PLE17 | 72 / 55 / 1 | 1883 / 103 / 4 |
| 上项 OR R29 PLE29 | 72 / 53 / 2 | 1876 / 99 / 5 |
| 上项 OR R29 PLE43 | 72 / 55 / 2 | 1894 / 98 / 4 |
| 上项 OR R26 MLP29 | 72 / 36 / 3 | 1903 / 81 / 9 |

B 有 3 个 cell，D 有 12 个 cell。原始低阈值直接 OR 虽保住旧 TP，仍无法满足全部 cell 的 FP 预算，因此不能直接采用。

旧通道在 C 的 5511 条正常流量上为 0 FP，在 B/D 分别已有 12/15 FP。C 上 0 FP 不能理解为未来不占 FP 预算。未来验收必须同时列出保留通道 FP、仅增量 FP 及两者总和，按各 cell 原始整数预算核查，不能仅报告 pooled FPR。

## 4. 现有输入支持什么，不支持什么

五项连续输入加 protocol 已能包含当前正常与攻击的部分判别信息。F-B 有 604 条 UDP 正常和 90 条 UDP 正例：正常持续时间中位数约 0.277 秒、最大约 1.774 秒；正例中位数约 1476.690 秒。正常/正例的发向平均 IP 包长中位数分别约 256.769/630.081 字节。原模型已能把训练中的这两组排开，不宜再把所有失败归因于没有这种正常形态。

平均包长、方向包数比、方向字节比均由已有五项输入确定，并未增加观测信息。把它们显式加入可能改变归纳偏置，但现有证据不足以把这种改动直接定为修复。

F-A TCP 正例与 D 正例之间仍有明显支持差异：

| 描述量 | F-A 正例中位数 | D 正例中位数 |
|---|---:|---:|
| 持续时间（秒） | 1.012 | 31.024 |
| 发向平均 IP 包长（字节） | 163.000 | 334.461 |
| 回向平均 IP 包长（字节） | 204.438 | 446.435 |

D 的 1964 条正例中，仅 65 条持续时间落在 F-A 正例的持续时间边际范围内，仅 45 条同时落在 F-A 正例四项包数/字节数的边际范围内。这里的“范围内”不是相同计数签名，更不是完整输入相同。这些数字说明加入 A 监督仍需要跨持续时间、包长及联合形态外推，不能推出泛化不可能，也不能证明新增 A 已解决 D 的旧 TP 丢失。

## 5. 为什么本轮不继续叠加架构与损失改动

### 5.1 协议内 pairwise pAUC 的已有反证

仅读取 P 最终检查点保存的 `train_scores.npz`。P 正例均为 UDP；所有训练 UDP 正例分数已高于所有训练 UDP 正常分数。

| 模型 | 最低正例分数减最高 UDP 正常分数 | 任意此类 pair 的 logistic loss 上界 |
|---|---:|---:|
| PLE17 | 22.4361 | 1.804×10⁻¹⁰ |
| PLE29 | 14.0480 | 7.926×10⁻⁷ |
| PLE43 | 14.8349 | 3.608×10⁻⁷ |

所以，在同一训练支持上继续使用普通 pairwise logistic/pAUC 目标，已经几乎没有纠正错误排序的梯度。它可能改变间隔或从头训练过程，但“针对低 FPR”这个名称本身不能证明它会修复 D 的误报。不能为避免饱和立即追加温度、间隔和权重搜索。

### 5.2 协议条件头不能自动隔离牵连

若只把输出层改成协议条件头，共享主干仍接受不同协议的梯度，全局预处理仍可能相互影响。协议内 pairwise 排序又不固定跨协议分数偏移，共用 C 阈值时仍可能重新分配不同协议的报警风险。输入里本已有 protocol；新增条件头增加的是结构约束，而非信息。只有把表示、训练与预处理等相应环节也分开，才接近完全隔离，这已超出当前证据支持的最小修改。

### 5.3 保留、修改、拒绝

| 项目 | 当前决定 | 依据 |
|---|---|---|
| 五连续字段、protocol、冻结评分定义 | 保留 | 已含训练可分信息；避免改变信息条件和分数原点 |
| 旧 HGB∪规则的原身份与阈值 | 保留 | 结构保证已有报警身份；其 FP 必须计入总预算 |
| 增量阈值下限 | 固定为原生 0，C 仅能收紧 | 明确限制低阈值释放的报警集合，无拟合成本 |
| 增量的新训练、A/B 残差训练 | 本轮不做 | 先验证现存模型的固定判决是否有可用增量 |
| 显式平均包长、协议头、pairwise pAUC、更大 TabM | 暂不实施 | 未增加信息或尚无针对当前错误的充分作用证据 |
| 原阈值直接 OR | 拒绝采用 | 已有集合合并在多 cell 超预算 |
| 根据 ED 调下限、选种子或反复改公式 | 拒绝 | 会把本轮证据继续消耗为参数选择 |

如果固定候选不满足验收，结论应是现有冻结分数在该结构下没有达成所需增量；届时再决定问题是输入支持、任务要求还是模型训练，不用新的调参矩阵掩盖失败。

## 7. 下一次固定判决验证的输入与验收

R29 `回传` 中已经存在所需输入：

- `inputs/C.parquet`、`inputs/ED.parquet`：真值、来源、row_id 与 cell 身份；不得按文件行位置拼接。
- `reports/legacy_hgb_or_rule-decisions.parquet`：保留通道原判决。
- `evidence/tabm_ple_s{17,29,43}/C-scores.parquet`、`ED-scores.parquet`、`calibration.json`：三个种子的冻结分数和原始 C 阈值。
- `inputs/references.json`、`protocol.json`、`freeze.json`、`reports/units.json`：身份、协议、冻结记录与原验收单元。

身份必须以 `(source_id,row_id)` 一对一连接，验证覆盖率与真值、cell 一致，再使用固定公式。验收预先固定为：三种子分别完整报告；B 的 72 个正例及全部 15 个 cell 的原整数 FP 预算不放宽；旧保留通道 TP 身份逐一保留；R26 MLP29 额外 TP 的得失单列，不能只报 pooled recall 掩盖交换。若主报告要求更严的旧 MLP 身份或 cell 保护标准，须在计算前一并冻结。

同时报告保留通道 TP/FP、仅增量 TP/FP、最终 TP/FP、逐 cell 预算与逐身份增失，标注冻结系统的运算和维护成本。C 上保留通道 0 FP 的事实与其真实风险不等同。

本轮完成的是公式、信息依据、缓存可用性及验收设计；未计算零下限候选的任何新判决，未训练、加载模型、执行 forward、新评分或搜索阈值。
