# 新机制的失败依据：两个已证实靶点与一个尚未成立的假设

2026-11-19。本次只定向读取既有结果与其拥有文档，未加载模型、重新评分、重校准或用旧测试集选择新方法。原 R30/R31 的数字用于解释历史失败，不作为当前 AIT／Unraveled 四臂的效果结论；当前四臂尚未在本机找到完整回传。

**最有依据的设计靶点仍是“已有正常支持却整体排高”的正常成分，其次是“混合监督后丢失跨传输排序”。现有材料没有证明模型必须依赖更高阶的阶段／ACK 结构才能解决它们。**

## 1. 靶点一：已有训练正常支持，仍把整个成分置于告警尾部

R30 三个主模型全部检出 B72、D1964，15 单元合规仅 8／5／4。D TCP 误报中，同四计数 F_B 正常可匹配数分别为 88／96、93／106、114／131；其中 73／69／97 条的 duration 也在相应 F_B 组范围内。近邻原分数绝对差中位数仅 0.034416／0.045793／0.003391。这里四计数为双向包数和 IP 字节数，近邻按 log1p(duration) 选择。

seed43 的正常 `(11,8,1285,4725)` 成分，在 C 中 23／23 告警，在 D 中 84／84 告警。F_B、C、D 分数中位数为 −11.836、−11.832、−11.810，原 C 阈值 −12.252099；成分比例由 C 的 0.417% 增至 D 的 0.878%。一个 D 单元仅该成分就有 14 条误报，超过总预算 8。

拥有证据：[R30 正常尾部审查，21—41 行](<E:/OneDrive - Coventry University/中传/毕业论文/代码/tracelight-ids/.worktrees/packet-interaction-20261119/docs/R30_NORMAL_TAIL_DESIGN_REVIEW_20261117.md:21>)；更细的原分数、匹配规则与恒等分解在 [input_mechanism.md](<E:/OneDrive - Coventry University/中传/毕业论文/代码/tracelight-ids/.worktrees/packet-interaction-20261119/docs/r31_design_review_20261117/input_mechanism.md:19>)。

**允许推出的设计约束**：新机制若声称修复该类失败，必须能改变“不同正常成分之间的相对位置”，而不只是让同一成分内部更平滑。若一个正常成分的全部输入被映射到同一点，模型仍可给这个点高分；硬投影和组内不变性不能自动解决成分中心问题。

**不能推出**：这些错误普遍来自训练缺样本、PLE 范围外外推、duration 太长或容量不足。六模型全部 D TCP 误报均未超出 F 的五数值 PLE 端点；F 无异标签预处理同值冲突。但这也不能证明训练后的嵌入无信息损失，原检查未读取其权重。

还有一个具体限制：R30 全 F 正负已严格分离，间隔 2.5374／3.5587／8.9514。在其保存的分数上，全 F 最高 147 条正常与全部正例的标准 logistic pair 分数导数绝对值均值为 2.18e−7／2.73e−7／1.13e−9，前两个种子的尾部主要被 A 正常占据。这不是参数梯度，也不能否定从头训练的排序方法；它要求新增目标明确说明作用于哪些正常记录，而非仅扩大已有正负间隔。[对应拥有证据](<E:/OneDrive - Coventry University/中传/毕业论文/代码/tracelight-ids/.worktrees/packet-interaction-20261119/docs/R30_NORMAL_TAIL_DESIGN_REVIEW_20261117.md:55>)

R31 后的分组风险路线已经退出当前默认主线，不能把这段历史重新解释为恢复原训练的授权。当前新候选也不自动继承旧 R30/R31 的永久零回退硬门。

## 2. 靶点二：高拟合与混合监督没有保证跨传输排序

R26 在旧窄来源上，B72 的检出及事后逐单元排序上界均为 0；增加目标历史监督后，端口置零 HGB 和三个 MLP 均 72／72、3／3 正常单元合规。这是监督支持改变后现成方法成功的直接证据，不能继续假定八字段无信息或必须扩大模型。

相同轮次的 target→mixed 不是普遍改善。端口置零 MLP29 的 D 检出从 1773 降为 46，事后 1% 排序上界由 1798 降为 58；这是排序退化，不能靠原分数的单阈值修复。与此同时，mixed 原八字段 HGB 检出 1952／1964，排序上界合计 1951，却只有 2／12 D 单元合规。两类失败必须分开：MLP 丢排序；HGB 的已登记流程风险失控。

拥有证据：[R26 原实验分析，第 19、59—71 行](<E:/OneDrive - Coventry University/中传/毕业论文/实验归档/20261115_第二十六轮历史监督/实验分析.md:59>)。

R29 的同种子消融进一步表明数值表示具有实际作用：PLE 相对无 PLE 新增 D 检出 1607／1560／1657，未丢失对应无 PLE 模型原检出；D 总检出为 1652／1560／1657，而无 PLE 为 45／0／0。所有候选的训练支持已高度拟合，继续降低训练误差不是已证修复方向。[R29 原实验分析，第 67、93—95 行](<E:/OneDrive - Coventry University/中传/毕业论文/实验归档/20261117_第二十九轮模型训练/实验分析.md:67>)。

**允许推出的设计约束**：学习机制应说明怎样保留与标签有关的跨字段数值关系，并面对来源混合后排序可能退化的反例；不能通过一律删除协议、体量或时间变化来获得表面不变性。强简单模型和成熟数值编码必须保留为相同输入的直接对照。

**不能推出**：R26 已隔离出“来源冲突”是唯一原因。该轮混合同时改变训练量、权重、更新次数及 MLP 标准化；R29 的训练正例为 UDP，D 正例为 TCP，覆盖与表示也相互关联。它们支持研究问题，不足以直接挑定一个域对齐损失、对比目标或专家架构。B/D 又缺少 D 控制服务的同端口正常，不是新控制／下载来源的独立确认结果。

## 3. 当前不能升级成设计靶点的说法

**“阶段条件配对能消除正常环境因素”尚未成立。** 新 F_expanded 有 12,747 正常、505 攻击；按协议＋四计数精确条件，792 个正常组具有至少两个已观测 duration，涉及 9512 行，但跨完整来源、同条件且不同 duration 的正常组为 0；505 条攻击均无精确同条件正常支持。是否存在正常参照可能形成标签捷径，正常差分也没有被识别为可删除的环境因素。

拥有证据：[当前 F-only 配对计数，第 118—133 行](<E:/OneDrive - Coventry University/中传/毕业论文/代码/tracelight-ids/.worktrees/packet-interaction-20261119/docs/innovation_mechanisms_20261119/representation_mechanism.md:118>)。这里不用旧 R30 的精确组去规则化新 F。旧 R30 F 本身也有 7134 个精确四计数正常模式、5750 个单例；不是换一批精确桶就能解决支持问题。[原支持检查](<E:/OneDrive - Coventry University/中传/毕业论文/代码/tracelight-ids/.worktrees/packet-interaction-20261119/docs/OPERATING_RISK_CORRECTION_20261118.md:64>)

最新原包结果同样没有给出结构必要性：518 条 HTTPS 控制仅 3—11 ACK 段，481 条数据字节 ACK 映射可由普通方向字节块恢复；普通 ACK 加权前缀算子有精确集合聚合实现。剩余 37 条的额外关系也出现在正常业务中。不能将这些段自动命名为“命令阶段”，不能将 ACK 当作应用命令因果。

拥有证据：[真实包与算子决定](<E:/OneDrive - Coventry University/中传/毕业论文/代码/tracelight-ids/.worktrees/packet-interaction-20261119/docs/packet_interaction_20261119/index.md:17>)。新包信息仍可用于设计原型，但当前没有模型成绩证明它修复了上述正常高分问题，也没有同信息比较证明强简单方法吸收不了它。

## 5. 对当前设计工作的直接建议

优先把候选写成能够改变“有支持正常成分的相对高分”或保护“跨来源数值关系”的明确学习更新，然后用代数、真实训练支持与简单等价实现判断是否值得保留。凡是只改变同组内方差、统一分数尺度、固定阈值、或对既有信息作等价读取的版本，都不能解释目标一。凡是删除来源可预测信息却不说明标签相关关系如何保留的版本，都没有解决目标二。

当前可以继续设计与实现无需真实训练的原型；不能把历史 B/D 的具体错误模式写进新规则，也不能提前把 AIT 四臂尚未返回的错误当成既成事实。没有实证证明“同信息简单方法不能吸收的阶段结构”，这项关键命题应保持未证，而非通过换一个架构名称补齐。
