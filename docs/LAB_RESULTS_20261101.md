**现有实验可以作为开发基线保留。** 本文记录从带回工件核实的结果，不使用未核实的口头摘要代替原始预测。

实际环境为 RTX 4090D 24GB、Windows 10、Python 3.12.3、PyTorch 2.6.0+cu126；树模型和 LR 在 CPU 上训练，MLP 使用 CUDA。数据是固定公开镜像 UNSW-NB15，内部验证集 26,302 条（正常 8,400，攻击 17,902）。12 次基线采用 seeds 17、29、43；以下阈值均由验证集正常样本确定，属于开发比较。

|---|---:|---:|---:|---:|

各 run 验证集正常误报率不超过 1%；RF 有两个种子为 0.9881%，其余为 1%。同一数据划分上的种子重复不是独立测试集，标准差为零也不代表没有泛化不确定性。HGB 在本组操作点效果最好，MLP 和 LR 更小，RF 结果稳定；不需要据此否定任何方法。

原包 444 个文件；清单所列 443 个文件全部匹配，ZIP CRC 检查通过。26 个 run（12 个真实基线、6 个特征初筛、8 个合成验证）工件校验通过。18 个真实数据 run 的验证预测已独立复算 recall、FPR、precision、Macro-F1、AP、ROC-AUC，与保存指标一致。12 个全字段 CPU 基准的分位数和吞吐由原始计时复算一致。原包 SHA-256 为 `4904a026f4b3dcd671ad2b714e09791f45cd7c7c6e450cb94247d9b339b2671a`；原包和完整模型保存在个人实验归档，不随代码再分发。

## 两处需要修正文稿的具体问题

原分析脚本将“该模型检出数减去四模型共同检出数”标为唯一检出，计算会包含其他模型也检出的样本。seed 17 严格按“该模型检出且另外三个均漏检”复算，LR/RF/HGB/MLP 分别是 **70/60/233/92**。四模型共同漏检 1,695 条的结果没有变；其中 Fuzzers 为 1,489/2,727。四模型 OR 告警会产生 203/8,400 = **2.4167%** 正常误报，不能直接当作满足 1% 预算的集成方案。

旧特征初筛的 RF 用 100 棵树，全字段用 200 棵；MLP 初筛用 40 epochs/patience 6，全字段用 60/patience 8。初筛仍是有效的探索记录，但不能将全部差异归因于字段数量；且旧包没有精简模型的 CPU 测量。因此“RF 16 字段是最优轻量点”暂不成立，[第二轮](STAGE2_PROTOCOL.md) 将配平训练规则、测齐全部候选。两处更正不影响已复算的基线指标。

## 保留的评估边界

原训练源和测试源存在 1,302 个完全相同特征组，涉及 10,279 条训练源记录和 8,541 条测试记录。内部 train/validation/calibration 已按精确特征组隔离，但不能由此声称原测试源无重叠。最终评估前需固定重叠敏感性报告规则。

当前没有最终冻结或 evaluation 工件。以上是验证集研究证据，尚不是封存测试结论；镜像原始文件尚未与独立官方副本比对。CPU 计时为 100 个固定样本各测 30 轮，共 3,000 次单条调用，加单独的 batch=256 测量；不是每条记录各测 3,000 次，也不包含采集和网络系统开销。
