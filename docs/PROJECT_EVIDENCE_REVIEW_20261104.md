## 4. F/R/C/V必须按实际代码用途解释

旧v3/v4中，教师用F或F的一部分拟合；更新学生的硬标签损失用F+C；R注册阈值；C参加约束和可行性检查；V既参与候选资格又参与选轮。`src/ids/upgrade_research.py`的`_fit_condition`先计算V的FPR/TPR，再据其选择checkpoint。因此旧V已经是开发选择集，三seed也只是同一数据划分下的优化重复。

新BudgetTransfer原型把拟合统一为F、R/C用于阈值和选择、V延后读取，这是本轮选择时序的改进；它不会让历史V恢复独立性。该原型的46次pilot/138次full矩阵尚无真实回传，而且同类排序机制已撤回优先推荐，不能作为下一步默认任务。

已有精确分组、完整预测和失败封存仍有价值。它们能定位错误来源、复算判定、保留负结果；单元测试数量与工件齐全不能回答“教师知识可否迁移”或“超过公平强基线”。

## 5. 本次补齐实际OOF教师的零拟合诊断

旧`audit_teacher_value`只查询full-F参考教师，明确没有查询native折预测。原包已保存每个`fold-k.joblib`，所以本次直接扩展原入口，不新建训练方案：

1. 由封存`targets.parquet`中的fold身份找到每行真正的教师；模型SHA须与v3完成清单一致。
2. 每折先查询共同R并分别注册native/旧clip的float64阈值，再查询原F-heldout和C；不查询该折F训练部分或V。
3. 按折报告拟合家族支持、目标ties、正常尾部、pAUC、工作点TP/FP及逐族检出；旧clip预测必须逐行重现封存目标，不能静默替换历史教师。
4. 保存F同序的native/legacy OOF分数、fold、固定判定，以及各折R/C分数。跨折只汇总各自已注册阈值的事件，不把不同教师的raw margin混排后计算一个伪OOF AUC。

实现位于`scripts/audit_upgrade_thresholds_lab.py`的`audit_oof_teacher_value`，并接入现有`audit_teacher_value`。新工件schema3新增`fit-identity.parquet`和`teacher-value-s<seed>/oof-scores.npz`，旧schema1/2仍可核验。源码修改不改变任何旧tag、原模型、原ZIP或历史判定。

本机验证覆盖合成HGB/MLP端到端审计、禁止重新fit/step、同序OOF恢复、原heldout查询范围、旧目标精确重现、来源绑定与浮点阈值。真实native OOF诊断仍须由实验室RTX4090D运行本轮checkout后回传。

## 6. 这份审计能够决定什么

审计能够判断旧教师的尾部信息是否被clip破坏、实际OOF教师在合法工作点有无检出信息、目标问题集中在哪些折和家族。它不能证明额外字段可被小学生恢复，也不能选择新的学生函数类。full-F教师与旧F+C学生监督量不同，旧学生又经过V选轮；两者的错误互补是线索，不能当公平方法排行。

下一次新拟合应先建立同F标签、同R/C选择、相同输入/容量预算下的hard与成熟直接低FPR目标，再加入普通native KL控制。先回答学生究竟缺输入、容量、低FPR目标还是优化预算，才决定新KD的知识对象。原有升级保护与同类排序只作为明确问题下的对照，不再统领训练矩阵。

后续独立确认还应明确验证对象：新来源上直接评估旧冻结模型，检验的是模型迁移；在新来源的训练部分按已冻结算法重新拟合，再评价其未使用测试部分，检验的是方法复现。两者都要在打开对应确认结果前固定协议，不能把换数据后的重新训练结果写成原模型的跨域泛化。
