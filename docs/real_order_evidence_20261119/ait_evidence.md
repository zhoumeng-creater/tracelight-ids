# AIT：真实先后关系与正常业务的可比性

2026-11-19。此次读取现有 santos/F 和 fox/V 的动作、完整背景连接、冻结标签及严格导出时钟。没有新下载、模型评分、拟合、阈值或窗口搜索；未使用 russell/C 或保留 harrison 材料。本页是对真实先后事实的固定统计，不是检测性能比较。

**现有 AIT 材料确认了可用的先后结构，但尚未确认这种结构能区分攻击与正常。** 攻击命令大多数先后关系在完整流导出时保留；同主机正常页面的先后关系也全部保留。另一方面，攻击后仍有可靠正常查询继承全部控制历史，因此“过去出现过控制”不能直接决定当前连接恶意。按当前冻结范围，不支持仅凭存在次序或历史量差异安排新训练。

## 1. 哪些正常业务真正接近攻击

| 比较对象 | santos/F | fox/V | 实际可比程度 |
|---|---:|---:|---|
| intranet_server 上确证 HTTPS webshell 控制连接 | 30 | 15 | TCP/443、同监控主机 |
| 同主机 TCP/443 的整流可信正常连接 | 125 | 73 | 可作为控制对照；对应普通页面读取，不是正常远程命令 |
| 正常页面动作及全部候选 | 53 动作、137 连接 | 58 动作、228 连接 | 非全部候选都具备整流正常资格；其余 12／155 条保持未知 |
| ownCloud 正常下载 | 44 动作、375 候选连接 | 42 动作、406 候选连接 | 在 cloud_share，不能冒充 intranet_server 上的同服务下载对照 |
| 恶意下载 | 2 动作、3 候选连接 | 2 动作、3 候选连接 | 在 intranet_server；每 run 只有 password list 的 1 条 TCP/80 连接是确证整流攻击，两个 GitHub TCP/443 候选保持未知 |
| 额外完整正常 SSH 控制 | 0 | 1 条 TCP/22 会话 | 6 次已完成输入共用同一连接，不是 6 条独立正常控制，也未触发下载 |

这里不把端口输入当分类器特征。端口和主机只用于解释可比范围：若把 ownCloud 正常下载与 intranet 下载整体比较，观测位置、服务、客户端和运行阶段同时改变。现有材料不能把由这些条件产生的差异归因于恶意顺序。

## 2. 已确认的先后关系不是攻击特有

对 actor 中已完成且不重叠的命令动作，保留每个动作的全部候选导出时刻。仅当较早动作的**最晚候选导出**仍早于较晚动作的**最早候选导出**，才记为全部候选保序。

| 实际动作关系 | santos | fox |
|---|---:|---:|
| 攻击 webshell 命令先后对 | 527/528 全候选保序，另 1 对同批 | 153/153 全候选保序 |
| 同一正常 actor 的相邻 intranet 页面动作 | 51/51 全候选保序 | 56/56 全候选保序 |
| 同一正常 actor 的相邻 ownCloud 下载动作 | 28/42 全候选保序，14 对存在交错／候选共享 | 30/40 全候选保序，10 对存在交错／候选共享 |

这些分母是两条攻击链或少数 actor 内的关系数，不是独立攻击次数。santos 与 fox 还共用攻击脚本家族。它们说明完成流的时间条件并未抹掉所有历史关系；同时，正常业务也有稳定有序关系。要证明算法价值，必须比较具体观察形态的先后量，不能用“能够保留先后”直接推导“能够识别攻击”。

两 run 的 ownCloud 分别有 52／40 个连接作为多个正常动作的候选父连接，且没有一个下载动作是唯一候选。该关系不能展开成确定的动作序列，不能把多个候选顺序相加当作多条已确证证据。完整流顺序与业务动作顺序必须分别解释。

## 3. 真实正常反例：攻击之后正常业务继承了完整控制历史

严格使用完整流的 `available_at`，同刻先查询后整批更新：

| 同主机、同 TCP/443 的可信正常连接 | santos | fox |
|---|---:|---:|
| 首个确证 HTTPS 控制导出前 | 107 | 52 |
| 首个至最后一个控制导出的区间内 | 0 | 0 |
| 最后控制导出后 | 18 | 21 |
| 上述后续正常查询的前缀确证 HTTPS 控制数 | 全部为 30 | 全部为 15 |

控制导出区间分别仅约 99.43 秒和 73.19 秒。可信正常查询没有覆盖这两个短区间；控制客户端与正常客户端也完全不交。因此，若某个历史量只在该短阶段取特殊值，还不能排除运行阶段、客户端或访问形态差异。

同时，后续 39 条可信正常连接确实继承了全部已完成控制历史。这是使用同一主机状态时必须面对的真实反例。它不证明当前有向比例必然误报，因为查询读取仍可能区分当前正常连接；它证明**“控制历史存在”并非当前连接恶意的充分条件**。

可追溯示例：

- santos 正常 `CAEFI04bjkV7H8vwVc`，导出 `1642421264.516484`，查询前已有全部 30 条确证 HTTPS 控制；同刻还有另外两个正常查询。
- fox 正常 `CbuTMi1JXSi87GQK7f`，导出 `1642516960.334038`，查询前已有全部 15 条确证 HTTPS 控制。

本次没有发现正负查询共享完全相同导出时刻，因而没有把相同时间状态误写成已发现的正负同表示冲突。状态随其余背景继续变化，不能只用这些反例宣称任何历史模型都失败。

## 4. 下载触发与更早控制仍须区分

四个恶意下载动作、六个实际候选的严格前缀，都没有真正发出相同 URL `wget` 的完成控制流。已有结果在本次按原来源复核：santos 两个 GitHub 候选的前缀分别有 5,275／5,280 条连接、其中 27 条确证同链；password list 前缀 5,283 条、其中 29 条。fox 对应 11,488／11,494／11,497 条、确证同链 12／12／14 条。

较早 GitHub 候选的最后槽是更早同链命令，较晚候选的最后槽是未知背景；password list 的最后槽为先前解压命令。更早控制可用这一事实成立；真实触发命令不可用也仍成立。候选需要证明的是较早形态组合的辨识价值，不能把晚到命令补进历史。

## 5. 可直接复算的真实输入

- `拟合来源与划分落实_20261119/dataset/context_inputs.jsonl.gz`：完整背景，santos intranet/cloud 分别 6,072／16,146 条；fox 分别 13,278／32,358 条。使用 `measurement_flow_id` 与当前冻结 `rows.jsonl.gz` 的 `flow_id` 连接。
- `group`、`host` 是状态隔离键；`available_at` 是固定 Zeek 离线导出 `network_time`，不是实际部署接收时间。`raw8` 为 `[protocol, orig_port, resp_port, duration, orig_pkts, resp_pkts, orig_ip_bytes, resp_ip_bytes]`；`flow_end_at` 不能替换可用时间。
- 原事件 `dataset/events.jsonl.gz` 保留 actor、HTTP 请求及全部候选。现行角色和整流标签取 `覆盖与历史依据落实_20261119/batch/rows.jsonl.gz`。未知背景可作为已观察特征进入历史，但不得作正常监督。
- [analyze_ait_evidence.py](../../scripts/order_evidence/analyze_ait_evidence.py) 与 [ait_evidence.json](ait_evidence.json) 保存以上固定计数、可追溯身份及输入 SHA。

本页没有选窗口、衰减率或有利坐标，没有使用候选输出决定哪些正常连接可纳入。它为后续对真实表示的数值比较提供业务依据；能否由候选 Rg 区分、以及是否优于同信息二阶读取，仍须由实际同输入结果回答。
