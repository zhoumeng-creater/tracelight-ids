# OpTC 与 Unraveled：真实先后关系及正常反例

2026-11-19。本轮读取现有连接、动作和业务证据，不训练、不调用模型、不选择阈值、不下载新来源。事实提取脚本为 [inspect_optc_unraveled_order.py](../../scripts/order_evidence/inspect_optc_unraveled_order.py)，完整计数与源 SHA 见 [optc_unraveled_evidence.json](optc_unraveled_evidence.json)。保留材料 Meterpreter 未读取。

## 结论

**这些材料证明存在可用的重复通信与传输前序，也提供了明确的正常反例；它们尚未证明“有向交互比例”相对一阶历史或同信息二阶模型增加了攻击判别能力。**

最有约束力的真实反例来自 Unraveled：在同一个受监控主机、同一攻击活动时段，2,300 条可信正常连接全部已有此前 C2 历史，其中 769 条还是与 C2 相同的 TCP/443。因而“历史存在控制，随后出现当前连接”是正常业务和攻击共享的背景。必须由当前连接与历史的具体关系产生额外区分，不能把历史攻击存在本身当作当前流的恶意证据。

| Unraveled | 主机 `10.1.3.8` 的 12,824 条连接，含 12,308 正常、473 C2、43 非目标／未知 | 原 PCAP 离线 Zeek `replay_export_time`，严格早于查询 | 完整已下载捕获的所有完整记录；不等于实际部署接收时间 |

OpTC 入口：`统一事件与方法落实_20261119/optc/context_replay_inputs.jsonl.gz`。Unraveled 入口：`覆盖与历史依据落实_20261119/attack_coverage/full_capture/connections.jsonl.gz`，只筛 `involves_monitored_host=true`。可信目标标签以冻结 `batch/rows.jsonl.gz` 为准；11 条其他攻击不转成 C2 或正常。

OpTC 的 365 条不是攻击链日志裁片。已重新扫描原 `optc_2019-09-24_conn_17-18.log.gz` 的 1,553,112 条记录，以任一端点等于目标主机筛选，得到恰好 365 个 UID，与导出无增减。原文件 SHA 为 `429a509bfb01972c69950f18c72ad6571859021cc145105e1a92d0eb274b92f3`。见 [source scope check](optc_source_scope_check.json)。不过，输出轮转会包含更早开始的连接，也可能将早开始连接记在后续轮转；按流结束排序只是离线约定。空前缀不能解释为主机此前没有正常活动。

所有同刻记录共享同一旧前缀，不编造批内顺序。Unraveled 的 473 条 C2 中有 64 条查询的最近前批不止一条记录，所以“最近连接同 peer”另报告 any/all 上下界；单取排序后的最后一个 UID 不是因果前驱。

## 2. OpTC：重复不是攻击独有，冷启动与日期也形成混杂

| 可信查询 | 条数 | 最近前批同 peer：全部／至少一个 | 曾有同 peer 前序 |
|---|---:|---:|---:|
| Empire C2 | 24 | 23／23 | 23 |
| 正常浏览器 TLS | 41,588 | 40,846／40,846 | 41,584 |
| 同一主机 IP 的正常 TLS（9 月 19 日） | 172 | 172／172 | 172 |
| 完整正常 HTTP 文件传输 | 42 | 26／26 | 31 |

C2 的同 peer 间隔中位数为 30.1746 秒，同主机正常 TLS 为 0.001989 秒。这是实际节律差异，却还不是有向二阶关系的证据；间隔统计和周期性直接近邻也能利用它。正常 41,588 条 TLS 中，最近同 peer 间隔范围已覆盖 C2 的间隔范围。

24 个 C2 的流结束时刻位于 2019-09-24 16:59:55–17:10:46 UTC，而且恰好构成这份 365 条声明背景中的最前 24 条，前缀数为 0–23。正常 TLS 前缀数中位为 1,793.5，同 IP 正常为 95.5。若表示把这些记录区分开，可能是查询发生在输出轮转的不同位置，不可自动解释为恶意行为次序。

24 个 C2 的协议、双向包数与 IP 字节数形成 8 种形态，7 个查询与前一条记录这五项完全相同；不能把所有真实 C2 当成同一个合成基向量。其余 raw 数值差异是否需要历史才能识别，目前没有实证成立。

## 3. OpTC 下载与真实正常文件业务

恶意下载 `optc:20190924:CSHrim2uG4Jj6MUi31` 的查询时刻为 17:26:57.936547 UTC。严格前缀为 360 条：24 条已知 C2、336 条未知，0 条已确认正常。最近记录 `CzaMrB33RmJ7Z8NAdh` 是未知，不能把它叫作触发下载的控制。此前共有 307 条 TCP/443 记录，并非只有 24 个 C2。

42 条可信正常 HTTP 文件传输全部也已有已完成的正常 TLS 前序。一个实际可比连接 `optc:20190919:CzBYVl2SykMQhic3ak`：正常网页图片，双向包数 `(8,52)`、IP 字节 `(624,62057)`；恶意下载对应 `(8,52)`、`(725,61690)`。前者在查询前有 4,758 条 TCP/443 记录。它的正常身份由父页面、浏览器 actor、HTTP/files 对应与全连接事务依据确定，没有依赖模型输出。

两者持续时间分别为 6.252175 与 0.012191 秒；正常 HTTP 使用 80，恶意下载使用 8080。它们有真实的传输体量可比性，但不是完成同一动作的正常／恶意配对，不能把检测差异唯一归因于历史方向。

5,026 个可信正常页面文件对象的父 HTML 连接，实际可用情况如下：

| 父页面与文件对象关系 | 对象数 |
|---|---:|
| 独立父连接已经完成，可进入历史 | 1,744 |
| 父页面和对象在同一条连接 | 1,096 |
| 独立父连接尚未完成 | 2,185 |
| 独立父连接与查询同刻 | 1 |

所以正常业务也存在“语义前序已经发生，但其完整流尚不能进入历史”的情况。不能只为攻击恢复未结束前驱，或把正常的父页面先后当成与攻击相反的顺序。

该来源没有已核实正常 EXE 下载、软件更新或控制命令触发下载；同受害主机 IP 的完整正常 HTTP 文件连接数为 0。现有网页对象是有用反例，但不等同于正常程序下载或命令链。

## 4. Unraveled：同主机、同服务、同攻击时段的正常对照已存在

473 条 C2 都是 TCP/443，通信对端为 `10.8.10.84`；没有可信正常连接使用这一对端。它们分属同一个 campaign，不能按连接数换成 473 次独立攻击。正常同主机 TLS/443 共 5,081 条；SSH 20 条只说明作者标注的正常 SSH 流，不提供具体命令及后续文件动作。

C2 导出时段为 2021-06-21 23:37:22.541058 至 2021-06-22 07:29:02.143561 UTC；第一条 C2 查询已有 10,048 条历史连接。这个时段仍有 2,300 条可信正常，其中 TCP/443 为 769 条。769 条正常 TLS 中有 749 条此前已经访问同一 peer，说明熟悉端点与重复通信同样常见。

更直接的反例是：

| 查询 | 前缀已有可信 C2 | 前缀 C2 数量范围／中位数 |
|---|---:|---:|
| C2 查询 473 条 | 472 | 0–471／236 |
| 同时段正常 2,300 条 | 2,300 | 1–471／253 |
| 同时段正常 TLS/443 769 条 | 769 | 10–449／260 |

正常查询不仅共享 C2 历史，其历史 C2 数中位数还高于 C2 查询。这排除了“更多历史控制证据就足以判定当前流恶意”的简单解释。由于所有业务共享主机级记忆，当前查询读出必须证明它能够区分正在进行的正常业务；历史攻击标签只用于此次事实分析，绝不可进入模型输入。

控制连接前一同 peer 导出间隔中位数约 60.0074 秒，正常 TLS 同 peer 间隔中位数约 65.5802 秒。二者重复节律存在重叠，不能凭一个示例宣称某种周期独有。实际 C2 的协议／包数／字节数组合有 67 种，方向是否相消必须由完整真实表示计算，不能直接套用“纯重复为零”的合成反例。

最近前批同 peer 的上下界：C2 为 88–99／473，同期正常 TLS 为 96–144／769。这个差异本身没有形成恶意语义，也不是本候选特有信息。

## 5. 下载的“大方向”实际由三条未知协议／质量记录主导

根任务将固定表示作用于真实背景后，恶意下载的 13 维方向向量中，第 5、11、12 项（从 0 开始）分别是“duration 缺失”“UDP”“其他协议”，数值为约 `−0.984825、−0.984825、−0.986419`。三项占方向向量平方范数的 **99.6692%**。查询自身是 duration 完整的 TCP；这些信号来自前缀。

已逐条追回原连接：

| UID | 观测结束时间（UTC） | 原始事实 | 原 conn 行 | 标签 |
|---|---|---|---:|---|
| `CPdC8j3SCUkw9Gccff` | 17:24:36.339617 | 到 `8.8.8.8:53` 的 UDP；单包 56 IP bytes，duration 缺失 | 661637 | unknown |
| `C4hCrq1WFLFdAFIKf9` | 17:24:37.361120 | 到 `8.8.4.4:53` 的 UDP；单包 56 IP bytes，duration 缺失 | 662153 | unknown |
| `CKHWt23hPE1PcMlWhl` | 17:24:37.361244 | `142.20.60.1 → 142.20.57.246` 的 ICMP；两包 168 IP bytes | 682974 | unknown |

它们分别在第 354、355、356 条严格前缀以后出现，距离下载约 141.60、140.58、140.58 秒，明显晚于前 24 个 C2。原文件为前述固定 SHA 的 9 月 24 日 conn 轮转。两个 UDP 单包的时钟来自“唯一观测包既为首包也为末包”的既有离线解析，duration 字段仍为 null；没有据此推断实际日志何时发出。

9 月 19 日的 44,944 条正常组背景全部为 TCP、duration 完整，因此 42 条正常 HTTP 下载对应这三个方向通道均为 0，一阶支撑通道也全部为 0。当前显著差异首先是**两个来源的协议／缺失结构及其出现位置**，不能直接解释成控制触发下载的顺序。仅“这些通道是否出现”已能从一阶 P 读出，二阶方向没有为这一事实提供额外信息。

没有把 UDP/53 记录升级成可信正常 DNS，也没有把 ICMP 标成恶意。数值归因只说明哪些已观察事件贡献了方向；三条记录的业务语义与攻击因果边均未成立。

逐条数据、方向能量、42 条正常对照及表示文件 SHA 见 [optc_download_direction_attribution.json](optc_download_direction_attribution.json)；可复算脚本为 [attribute_optc_download_direction.py](../../scripts/order_evidence/attribute_optc_download_direction.py)。该脚本读取根任务已计算的表示，不重新训练或评分。

## 6. 这些事实能支撑的下一步

可在固定原数据角色中核查方向表示，并把单流信息、一阶存在／计数、协议／缺失模式、轮转边界与二阶先后分开解释。尤其应说明：正常查询共享攻击历史时，查询读取究竟增加了什么；可见差异是否已经被当前连接、P 或同信息 B 解释。

这份证据不支持直接安排有向记忆训练：当前最确定的真实先后信号是重复与节律，而正常业务同样存在；OpTC 的正常与攻击还处于不同日期／轮转。若真实方向主要反映这些条件，或不能超过同信息近邻，应结束这一候选，不通过增加记忆层、阈值或新来源挽救。
