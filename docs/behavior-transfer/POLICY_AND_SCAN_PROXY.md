# 阈值与无回应扫描代理的实验口径

`policy.threshold` 沿用项目既有有限样本序位。给定参考分数和比例 $a$，取第 $\lceil(n+1)(1-a)\rceil$ 个升序分数，只在严格大于阈值时告警，同分整组处理。序位超过参考行数时阈值记为 null，并关闭该分量的告警。旧 C 为确认正常的记录；本地首小时包含全部已观测记录，不使用标签，本地比例控制的是该小时告警比例。后续正常误报是否低于 1% 由封存后真值核对。此处冻结沿用仓库的 $(n+1)$ 序位，与开发阶段 $\lceil n(1-a)\rceil$ 序位最多相差一位，因此需要按本轮协议复算首小时对照。

`register(frame, components, alpha)` 对固定分量等分比例，再取判定并集。两分量各分配 0.5%，三分量各分配精确的 1/300，序位计算使用有理数，避免三等分时因浮点误差多移一位。该规则在同一参考集合上的并集不超过总额度。旧模型告警与另行登记的历史规则直接取并集时，要单独报告总误报，不能把每一路单独通过当作并集已通过。

`prefix_rules` 只使用 `flow_end_ms < cutoff_ms` 的完整首小时记录。本日志尚未推进到截止时刻时继续使用旧 C。截止时刻和其后的整个同钟组都属于后缀。初始小时照常告警、计入结果；后续时段使用已登记的本地阈值。每个来源文件或已登记数据块作为一次冷启动，首小时后冻结阈值。SFC 数据块按日志代理时钟切成 UTC 日；DEDALE 作者日文件的流尾可能跨 UTC 日，同一文件后续日期继续使用该文件首小时阈值。结果按实际 UTC 日期、初始小时和后续时段分别报告。登记结果的 `scope` 为 `local_unlabeled_alert_rate`，`n_reference_rows` 记录全部参考行数，`n_normal` 作为旧接口兼容键保留同一个数值，它不表示已确认正常的行数。

扫描代理 `scan_history.build_scan_history(frame, workers=1)` 返回前 5 分钟两个计数及逐流标志。纵向计数按源、TCP、受害目标分组，计不同目的端口；横向计数按源、TCP、目的端口分组，计不同目标地址。进入计数的记录必须有有效端口，且 `response_evidence_code=0`。这表示日志观测到发包而未观测到回应；状态 -1 无法判定，状态 1 已记录到回应。未知记录和有回应记录均不进入此计数。

窗口为 `[clock-300000ms, clock)`，排除当前记录和整个同钟组。当前记录也必须符合上述 TCP、端口和回应条件，纵向前置计数达到 15 或横向前置计数达到 25 时，该流收到代理告警。每条符合条件的流均计一次；后来的记录不会回改前缀判定。阈值 15、25、5 分钟来自历史 Zeek v6.0.9 脚本。[历史脚本](https://raw.githubusercontent.com/zeek/zeek/v6.0.9/scripts/policy/misc/scan.zeek)

这份 Zeek 脚本在 v6.0.9 已标为弃用，并注明 v6.1 移除、推荐 NCSA 的 `bro-simple-scan`。原生实现接收 connection_attempt、connection_rejected、connection_reset、connection_pending 事件，可以把带重置回应的连接及反向连接识别为失败。它使用 SumStats 分段累计、包含当前触发事件，并发出带抑制的源级 notice。本代理只有已完成 conn 记录，采用严格历史滚动窗口及逐流映射。本轮将它登记为 `no_reply_scan_proxy` 敏感性对照，不能将其成绩当作当前 Zeek 或 NCSA 原生检测器成绩。[弃用及事件逻辑](https://raw.githubusercontent.com/zeek/zeek/v6.0.9/scripts/policy/misc/scan.zeek) · [SumStats 阈值与累计周期](https://raw.githubusercontent.com/zeek/zeek/v6.0.9/scripts/base/frameworks/sumstats/main.zeek)

合成检查覆盖同分边界、三分量额度、首小时未结束时回退、追加未来记录后前缀不变、不同源和协议的独立状态、5 分钟窗口左端、同钟排除、未知回应、重复端口/目标与当前流映射。两个扫描方向可以并发计算，外层按来源并发时可传入 `workers=1` 控制总线程数。

GPU 批大小探针只重复早期 C 的 1,826 条记录到 65,536 行。4096、16384、65536 三个候选分别预热两次、重复三次；候选必须在绝对与相对容差各 $10^{-5}$ 内复现 4096 批的三视图分数，并保持七种旧判定一致，才按三视图中位耗时之和选择。报告同时记录重复输入与原始 C 存档的判定差异、实际设备及显存峰值。本地首小时和后续测试记录均不参与批大小选择。

历史构建探针在每个数据提供方已成功准备且无标签行数最多的来源，取最前 50,000 条盲记录，依次以一个线程和登记的多线程预算各构建一次。全部输入、历史列与行序须相同。报告包含实际墙钟、CPU 时间、RSS、磁盘中间产物字节和加速比；固定先串后并的单次测量可能受到文件缓存影响。

同一前缀还使用现有 `OnlineHistory(arm="history")` 逐条重放，核对流数、不同目标、不同目的端口和无回应比例四列与批量输出一致。单线程计时覆盖当前记录入窗、过期状态更新、两条按旧 C 各分配 0.5% 的计数阈值及其并集，记录 P50/P95、保留状态键数和每 1024 行采样的进程 RSS。内存数字包含输入表和已形成的批量历史表；本项没有调用质量模型，也未构建其完整历史状态。
