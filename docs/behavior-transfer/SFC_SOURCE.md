# R25 IoT-SFC 单传感器来源与准备

本批固定使用原先已打开的 `192.168.0.106` 传感器，收齐最新官方 ZIP 中该传感器的全部 25 份 `conn.log`。不按攻击标签、模型分数或扫描检出挑选流。备份去重后按登记时钟的 UTC 日期分成 14 个来源，每日独立冷启动历史。

## 事件证据和采集覆盖

官方时间表共有 302 个事件，其中 16 个为 `scanning`。已核验其原始编号、UTC 时间、发起端、目标列表及原标签。该单传感器原文在事件 `90、104、118、132、160、173、187` 的时间区间内有流记录；其余 9 个区间没有记录。因此本批不能称为覆盖 16 个扫描事件。

4/10 的事件 160 已用于开发。4/13 的事件 173 与 4/14 的事件 187 时间区间内，原生流 UID 均未出现在旧两快照。这里核验的是数据身份与时间交集；扫描流数和实际覆盖由实验室读取原生 v7 标签后统计，不能把窗口内所有流直接算成攻击。

作者 v7 标签按传感器、UID、微秒时间与五元组逐行附回原生记录。相同 UID 的时间或五元组冲突、同一流标签冲突均失败；找不到标签的流保留为 `Unresolved`。`scan_heuristic` 与作者 `ambiguous*` 标签继续列入 `Unresolved`。扫描事件只有 `label_source=window` 的原生标签才能记为扫描。`background` 代表作者标注的正常流，不是另有独立操作日志证明的正常行为。

IoT-SFC 的攻击类型和事件编号原样保留。它不提供本课题所需的纯 C&C、FileDownload 两类独立真值；其他攻击名称不转换成这两类。

## 时钟、字段与执行

每行从原生微秒 `ts + max(duration, 0)` 得到向上取整的毫秒流结束时间，再在首次出现的物理顺序中取累计最大值。没有按真实时间重排原文。整个传感器构造该登记时钟后按 UTC 日切分；每日历史冷启动，前一日状态不传入。源原始时间另存 `original_start_ms`、`original_end_ms`。本批最大登记滞后 3,599,150 毫秒，真实结束时间相邻逆序 535,429 次；这些是原生日志顺序的实测属性。

`prepare_sources(cache_dir, output_dir, workers)` 返回逐日 `name/features/truth/audit/role/source_id/status`。features 与 R23 盲输入相同并保留 UID；truth 独立保存类别、UID、事件、证据级别、原生时间、暴露身份与首次来源备份。历史特征和前一小时阈值由主入口另行构造。

原生下载最多 8 个线程，备份解码最多 8 个独立 CPU 进程，逐日数值转换最多 4 个线程；全部日期共享一次 v7 标签扫描。真实本机原文解码已经观察到 4 个不同工作进程，合计解析 5,839,132 行、CPU 时间 21.59375 秒。每个成员的解码时间与 PID 存入缓存收据。这里没有运行模型，GPU 使用由主实验入口的模型推理阶段记录。

每个原始成员、解码结果、标签投影和日期结果都有收据。完整的每日收据可直接返回；某日转换失败会保存 `status=failed`，其他完成日期保留。公共原始对象下载或校验失败会使 SFC provider 失败，主入口继续其他 provider；不返回伪造的空数据成功状态。

## 已完成的准备验证

`SFC_SOURCE_PROBE.json` 保存旧 4/10 的真实准备结果：274,871 行，其中 Scanning 83,936、Benign 38,189、OtherAttack 143,368、Unresolved 9,378。与旧已开 CSV 的 15 个原生字段、UID 物理顺序及登记时钟逐行完全相同。该探针没有读取新日前向标签，没有运行模型。

11 项合成检查覆盖备份去重、相同 UID 冲突、物理结束时钟、分块续传与摘要、原生标签连接、truth 分离、失败状态、空备份 schema 和完整逐日准备路径。

```powershell
python -m ids.behavior_transfer.sfc --cache data/raw/behavior-transfer-20261114/sfc --report artifacts/behavior-transfer-20261114/evidence/sfc-identity.json --workers 8
```
