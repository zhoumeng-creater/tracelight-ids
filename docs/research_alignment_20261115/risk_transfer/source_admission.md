# 独立事件与同服务正常业务：实件准入

2026-11-15。来源核查已从数据集介绍推进到实际日志；网络会话对应尚未完成。当前只发布一次抓包取证任务，不启动新模型训练或独立效果评价。

## 选定来源及已取得的原件

[AIT-LDS v2.1](https://zenodo.org/records/19483937) 于 2026 年发布，所选 `russellmitchell` 场景实际有效区间为 **2022-01-21 00:00 至 2022-01-25 00:00 UTC**，右端不含。它提供不同于已有 Merlin 的 HTTP WebShell 攻击实现，可作外部历史来源；八个同模板场景不等于八种独立机制。

已经定向取得并核验 **18 个小原件、16,386,926 字节**，包含场景配置、Apache 请求、作者标签、攻击动作与两名正常员工的动作日志。每个成员的长度、CRC32 与 ZIP 目录一致，另记录 SHA-256。原件集中在项目 `data/raw/ait-lds/source-audit-20261115`，不在 Git 中重复上传。机器可读证据：[实件核验](source/ait-small-evidence.json)、[成员校验清单](source/ait-members.json)。

受害网站为 `10.143.2.4`。内部正常员工为 `10.143.2.91`；远程正常员工经 VPN 后，与控制请求共享服务器观察到的 `172.19.131.174`。不能用该地址独占划分正常与攻击。

## 正常流、时间和字段的缺口

四份 Apache 日志有 11,184 条有效期请求。作者按未标注视为正常的请求为 3,489 条，其中 2,262 条带同网站 HTTPS referer。但 80 与 443 写入同一个 combined log，日志不含目标端口和客户端临时端口，不能将它们记成 2,262 条正常 TCP/443 流。68 次有生成器回执的正常动作提供了更强的业务证据。

两个已核员工日志中没有名为 download 的动作。正常页面资源传输不能直接充当与工具包/口令表可比的正常文件下载；本次全背景连接清单用于继续核查传输候选，未匹配连接不自动标正常。

首日存在 **4,956 次 DNS 外传接收事件**，第一次为 00:00:09.631596 UTC。因此整个首 24 小时不能当作无攻击校准前缀。若限制到网站 TCP 服务，仍须单独核定正常业务范围和确认方式。

正常任务的发起、成功时间已知；检测器实际取得成功回执、日志送达或人工正常确认的时刻未知。取证输出分别保存这些字段，未知保持空值。后续允许明确假设反馈延迟的回顾模拟，但不能声称已证明当时在线可得，更不能用评价期真值反选正常池。

全 ZIP 的 14,911 个成员没有原生 `conn.log`。现成 AIT-NDS 使用 tstat，不能把相似列改名代入既有 Zeek 八字段。此次轻量解析器输出的捕获 TCP payload 字节、包计数用于连接定位，**不是模型输入**；需要评分时再以兼容 Zeek 流语义统一提取，并核对截断、方向、重传和连接边界。

## 取证后的决策

先判断 AIT 的独立事件、同服务正常和八字段提取是否能成立；成立才冻结来源角色、正常反馈假设与评价时段。正常文件下载若仍无证据，不把下载列计为已确认，也不将同一攻击链的多个请求拆成独立重复。

混合 HGB 的固定保旧规则已在已有分数审计中失败。新来源只补研究证据，不能替代这个失败。下一项方法设计必须说明如何减少高分正常流与补漏攻击的混淆，并给出相对强基线逐条保留与丢失的检验；不从调 alpha、delta、换模型或追加特征开始。
