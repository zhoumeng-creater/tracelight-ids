# 保留既有检出与限制增量告警：R29 后续模型设计

日期：2026-11-17。状态：`zero_fit_candidate_specified_not_evaluated`。公式、模型来源、输入、训练处置、比较、验收与退出已经明确；尚未计算本候选的新判决，尚无效果结论。配套[静态规格](../configs/retained-increment-design-20261117/design.json)不是运行注册。

## 1. 本次作出的设计决定

**下一步只检验一个无需训练的系统设计：冻结旧 HGB∪规则保留通道，复用 R29 三个 PLE 最终模型，以原生零分界限制增量报警。** 不再把新增 A、四组加权、扩大 TabM 或换 pAUC 损失列为默认下一次训练。V2 的七轨迹方案保留为历史候选，不执行。

本候选回答一个有限而具体的问题：在不丢弃旧系统任何告警的条件下，现成神经模型在其原生分类边界上，是否还保留足够增量，补齐 B 的 6 条漏检并改善完整 D，同时不超出任何单元的误报预算。它首先是既有能力的组合与判决设计，不是新的网络训练算法。

这项取舍来自[已确认的两类错误](R29_FAILURE_MECHANISM_RESOLUTION_20261117.md)：旧检出损失不能靠继续抬高同一神经模型阈值修复；低至负十余的正常分位阈值，又释放了零分界原本不报警的正常记录。保留通道承担前一项，增量判界限制后一项。新方案的作用可以由集合关系证明，效果仍需逐行验证。

## 2. 为什么现在不启动另一套训练

| 已核对的修改方向 | 具体证据 | 决定 |

| 更大网络、更多集成成员或轮次 | 既有训练已严格分离，不能由失败推出容量不足 | 不增加 |
| 新增 A/TCP 监督 | A 正例约1秒，主要 D 旧损失约31秒；A 正常没有 UDP/443；不是已覆盖错误的直接对照 | 不作为已证修复进入七轨迹训练 |
| 协议内成对 pAUC | 原 P 最弱 UDP 正例与最高 UDP 正常的分数间隔为22.436/14.048/14.835；普通 logistic pair loss 上界约1.80e-10/7.93e-7/3.61e-7 | 旧支持的排序已饱和，不立即换损失 |
| 正常 CVaR-BCE、更大 margin | 严格分离时正比例放大 logits 可继续降低这些损失，却不改变同池分位校准判决 | 不能把降 loss 当修复机制 |
| 分协议头、平均包长等派生输入 | 派生量不增加观测信息；共享主干仍有跨协议梯度，分头又不固定跨头分数尺度 | 不新增 |
| 原阈值直接 OR | 旧通道 OR PLE17/29/43 的 D 合规单元仅4/5/4个；B仅1/2/2个 | 已有缓存集合统计否定直接采用 |
| 冻结保留通道＋零分界增量 | 可以保证旧告警身份保留，增量集合又是直接 OR 的子集 | 唯一下一步候选 |

前三种方向不是被证明永远无效；当前证据不足以把它们当作已经对准错误的修复。具体原文、公式、作者函数、优化器差异和成本见[目标审查](retained_increment_design_20261117/author_objective_review.md)。

## 3. 模型与判决的完整定义

### 3.1 保留通道

令 $b(x)$ 为已封存的 `legacy_hgb_or_rule`：

$$b(x)=[h_{old}(x)>0.969384090147706]\lor r_{old}(x).$$

旧 HGB 工件 SHA-256 为 `e2b3100860b2c05b0957865a7faf57f6d9e03a7fc15f5d4cf2f88c1977b8e0e8`；阈值来自旧 R23 校准，不在 B/C 上重建。规则仍是 UDP、任一端口443、完整流 duration≥30秒。只引用原实现，不加入根据 D 新造的端口、时长或包长规则。

该通道既有 B 66/72 TP、12 FP，D 1694/1964 TP、15 FP，全部15单元合规。它同时会保留这些旧 FP，不能只说保留 TP 而忽略风险占用。它含源数据训练的 raw8 HGB 和端口规则，所以完整系统不是无端口、同信息的 TabM 架构对照。

### 3.2 增量通道

只复用 R29 的 `tabm_ple_s17`、`tabm_ple_s29`、`tabm_ple_s43` **final** 工件与其冻结 CPU 分数。不得改用 trajectory 最佳工件、重新选择 epoch 或把 V2 的 F-only 交付规则追溯套到 R29。

保留其五连续量、协议和五缺失标记、P 上已拟合的预处理及 PLE、两个512宽隐藏块、32成员、各成员 BCE 训练和概率均值推理。具体数值及版本以 R29 冻结工件、源码快照和协议为准，不用新模型重建旧分数。

对种子 $s$，已有分数定义为

$$p_s(x)=\frac1{32}\sum_{k=1}^{32}\sigma(z_{sk}(x)),\qquad s_s(x)=\log\frac{p_s(x)}{1-p_s(x)}.$$

这里使用原稳定 FP64 log-odds 缓存。不是平均成员 logits；不重新 sigmoid 再截断，不加温度、平移或重新标准化。

三个原 C 阈值分别为 −15.029755070856966、−10.643443729727716、−10.90311970257591。新候选的增量判界定义为

$$\tau_s=\max(0,t_{C,s}),\qquad i_s(x)=\neg b(x)\land[s_s(x)>\tau_s],$$

$$a_s(x)=b(x)\lor i_s(x).$$

三个现存阈值都小于0，因此本候选实际使用同一个原生常数0。**这是新候选的判决规则，不是对 R29 原阈值、原结果的更正。** 原 C 数值只读引用，不重新取分位点；0附近不扫描，不为任何cell另设阈值。

0来自这个已冻结分数的 $p_s>0.5$ 定义，并非从 E 的 TP/FP曲线挑出。它不表示真实攻击后验已校准，也不是低FPR最优点或高置信保证。单个 sigmoid 输出二分类与双类 softmax 的等价语义支持这种原生判界；作者 TabM 示例采用成员概率均值后分类，但没有提出本项目的保留通道或零下限组合。[固定作者示例：loss_fn/evaluate](https://github.com/yandex-research/tabm/blob/28e47ae301c92ec37787dde1ce923a0793f405b4/example.ipynb)

### 3.3 可以证明的性质

令 $A_0=\{b=1\}$、$A_{C,s}=\{s_s>t_{C,s}\}$、$A_{+,s}=\{s_s>\max(0,t_{C,s})\}$，则

$$A_0\subseteq A_0\cup A_{+,s}\subseteq A_0\cup A_{C,s}.$$

因此旧通道全部 TP 身份保留；与原阈值直接 OR 相比，最终 FP 不会增加。增量 TP 同样可能减少到零。相对旧通道自身，FP只能不变或增加，不能写成“修复旧系统误报”。三者分别报告。

这不违背前次单阈值反证：该反证针对固定神经评分函数。本设计加入一个冻结的旧检测函数保留其告警，已经改变最终判决函数；并未证明原神经网络的排序被修好。

## 4. 训练与数据处置

本候选新增拟合数、优化器更新、checkpoint选择、预处理拟合、PLE边界重算均为 **0**。不存在待填写的学习率、轮数、采样或新损失超参。保留原 R29 自然权重、F/V 选轮和 P 重训的历史，不将它们解释成新设计已经验证的训练配方。

V2 的 A/B监督、四组等权、同PLE普通MLP及Q_dev→V_eval拆分只留作先前设计记录。当前公式不使用 A 训练，也不偷偷建立 A/B 残差训练集。R23 已找到 A/B旧HGB缓存并核对同一工件，但这不是完整 HGB∪规则残差标签集，不用其漏检数充当残差训练规模。

评价身份全部沿用 R29：B后三单元＋完整D十二单元，共17059行，15023正常、2036控制。C仍是原5511正常。已开数据用于开发核查，不能重新称为独立盲测。原结果、模型、标签、阈值和困难样本全部保留。

## 5. 误报预算与统计主张

对每个单元c，必须明确分解

$$FP_c(a_s)=FP_c(b)+FP_c(i_s),\qquad TP_c(a_s)=TP_c(b)+TP_c(i_s),$$

因为增量只在 $b=0$ 区域报警。整数验收为 $FP_c(a_s)\le\lfloor0.01n_{0c}\rfloor$。该式只用于验收，**不从 E 计算可用额度后反调增量阈值**。

总体风险也必须计算整个系统：

$$R_c(a_s)=P_c(b=1\mid Y=0)+P_c(b=0,s_s>\tau_s\mid Y=0).$$

不能将第二项写成残差域条件FPR后直接与第一项相加；残差域条件FPR还需乘 $P_c(b=0\mid Y=0)$。C中旧通道0FP不等于真实风险为0。现有C只为增量评分函数提供历史正常分位，不能给最终OR系统签发1%保证。

[统计设计审查](retained_increment_design_20261117/calibration_design_review.md)将“名义校准水平”“真实正常风险”“有限单元经验预算”“联合置信度”分开。若额外采用联合失败概率5%的设计建议，分配校准2.5%与有限评价抽样2.5%，三个固定模型×15单元的充分共同真实FPR上限为0.221558%；独立代表性正常5511条可支持未来序位5507，Q1569不足，至少需2159条。这里的5%是研究设计建议，不是用户原有硬要求。

**本候选不采用5507、不改变旧alpha，也不据该算术宣称95%成功。** 当前C/E已参与设计，B-only C无支配D正常尾风险的依据，流级独立性也未成立。未来若给组合系统作概率保证，必须针对最终组合函数的整体正常风险设计独立校准或风险分配，不能把单一神经分数的序位结果直接套给两个通道。更严格校准也不保证TP。

## 6. 下一步固定缓存核查：输入、比较与通过标准

这一节是待执行合同，本轮未计算新候选判决。无需模型加载或前向；只连接已存在的分数、身份与原判决。所需文件及SHA在静态规格中绑定。

1. 按 `(source_id,row_id)` 一对一连接 `inputs/ED.parquet`、旧通道原判决和三个 `ED-scores.parquet`；核查真值、完整15单元、17059行、无重复、无遗漏及冻结CPU分数来源。不能按隐含行位置拼接。
2. 先复核缓存分数与各原阈值能还原原PLE判决，确保没有误接同名工件；再逐一计算本次固定公式。分数非有限、阈值缺失、身份不符均报工件错误，不能静默零告警。
3. 三个固定种子全部核查，不平均、投票或挑冠军；不产生第四个种子或新增模型组合。
4. 每个种子必须同时满足：全部15单元原1%整数预算；B72/72；旧通道每条TP身份保留；相对每个已有参照的合规单元不减少TP数。参照包括旧HGB∪规则、R26三份target-ports_zero MLP、R26 target HGB、R29 HGB及同种子原PLE。
5. 在以上条件全部成立后，还需相对旧通道严格增加D检出。保留 R26 MLP29 等强能力，不能只以B从66到72或赢R29弱树就宣布整体改善。合规单元计数不减少并不等于TP身份不交换，逐条增失仍完整报告。
6. 报告每cell的旧通道、仅增量与总TP/FP、余量、对全部参照的新增/丢失身份；另列UDP正常尾部、旧TCP损失的身份归属。后者只作解释，不改变通过门槛。

上述是固定开发可用性门槛，不是独立科学结论。此时还没有可运行入口，`execution_enabled=false`；本文写清后，后续实现范围首先限于这个缓存核查，不能调用旧R29训练脚本。

## 7. 预先固定的结果分支

| 缓存核查结果 | 决定 |
|---|---|
| 三种子全部满足第6节 | 形成已开开发上的组合候选；才进入组合预测器的冷加载等价与实验室成本验证，仍不重训 |
| 只有部分种子通过 | 不挑最好种子，不增加seed，结束该三种子稳定增量主张 |
| 误报合规但B72、强参照保护或D严格增益失败 | 固定增量通道未满足所需检出；只有与原阈值OR的身份差分才能判断是否由零下限移除。不把floor向下扫描，不恢复负阈值网格，结束候选 |
| 检出改善但任何cell超预算 | 说明组合仍没有实现所需误报余量；不借E改floor、按协议校准或删除cell，结束候选 |
| 身份/分数/工件校验失败 | 修复缓存连接或来源错误，再复核同一公式；不将工程错误算成模型负结果 |

候选失败只否定这个固定结构，不证明模型永远不能成功。失败后不自动回到V2七轨迹，不自动转入pAUC、残差训练或数据扩充；需要新的、能够改变判别信息或有明确训练作用的证据，才重新立项。这里没有隐藏的后备矩阵。
