# 第二十六轮：历史监督、源数据增量与端口依赖的开发诊断

本批回答：在同一个控制通信任务、同一历史正常校准下，加入目标环境历史标签是否有效，旧来源数据是否额外有益，以及增益是否依赖端口。**这是已开材料上的现成学习方法诊断，不是新算法、盲测或扫描/恶意下载能力确认。**

前序路线重审发现，旧模型只用两次IoT-23采集的8192条记录，其中扫描4040、纯控制56、下载0，正常校准也来自不同早期设备。不能用其跨来源失败直接判断充分监督后现成方法仍然无效。本轮固定算法和实际预处理，改变监督条件；没有KD、新骨干、历史构建或阈值搜索。

## 为什么选B，为什么不扩成四个profile训练矩阵

TQH完整48单元均已打开。作者明确提醒目的端口等采集身份关联可能影响泛化。元数据和标签核对发现：A/C/D控制通信的目标服务缺少同服务正常，而B有匹配的正常业务，因此以B为主任务。

已有缺口也已核实：B后续3单元中，原八字段HGB误报12/5459，控制检出0/72，固定评分的逐单元1%事后上界也是0；三个MLP同样全漏且均超预算。它们不能仅靠同分数上阈值调整恢复这些控制。D则已有HGB检出1694/1964、误报15/9564，12单元各自达标，必须保留这项强参照。

| 角色 | 按真实时间排序的完整单元 | 正常/C2记录 | 同C2服务正常 |
|---|---|---|---:|
| 目标训练T | B_i30_j0/j30/j70；B_i300_j0/j30/j70 | 10502 / 180 | 1081 |
| 正常校准C | B_i1800_j0/j30/j70 | 5511正常；72攻击不用于拟合或定阈值 | 662 |
| 后续开发评价 | B_i3600_j0/j30/j70 | 5459 / 72 | 651 |
| 跨传输外评 | D全部12单元 | 按单元原生真值核算 | C2同服务正常为0 |

T始于2026-07-20，C结束于2026-07-21 01:54 UTC附近，B后续单元随后开始；D采集在B之后。精确时间使用已绑定的日志完成时间，见[角色登记](../configs/support-diagnostic-20261115/registration.json)及[TQH原始登记](../configs/response-evidence-20261112/tqh.json)。单元不能拆到不同角色，不能按单元名称代替实际时间排序。

标签条件为离线回顾：假设历史B标签与正常确认在C结束时已取得，原采集时的实际标签取得时间未知。因此结果是该条件下的前向模拟，不冒称无人工标签的在线适配。D不提供任何训练、校准或选模标签；使用冻结B阈值。B/D使用同一Merlin攻击实现，D不是新攻击机制确认。

## 一次运行的全部对照

3种训练支持×2种输入视图×4组学习器，共24个评分方案：

| 支持 | 使用的训练记录 | 监督权重与解释 |
|---|---|---|
| source | 原8192条，身份SHA精确复原 | 原4096正常/4096攻击，均匀权重；raw8复用旧权重 |
| target | 完整T的10682条 | 二分类总权重各1/2；不任意丢弃正常以凑小样本 |
| mixed | 原8192＋同一T的10682条，共18874 | 来源×类别四组总权重各1/4；与target使用完全相同目标标签UID |

视图为raw8和ports_zero8。后者只将两个端口槽置零，仍保留八槽、相同网络宽度和其他六项输入。HGB参数沿用原设置；MLP沿用128/64隐藏层、80 epochs、batch512、AdamW及17/29/43三个种子，不按本轮结果选种子或选轮。

MLP原实现的NF字段名名单不匹配这八个Zeek字段，**实际对八列全部使用signed log1p**。本轮保留这一实际路径并明确记录，不根据旧注释静默改编码。每个方案的均值、标准差仅从自身允许的训练行拟合。

新增拟合20次：HGB5次、GPU MLP15次。source/raw8的HGB和三个MLP共4份权重按原SHA复用。**TabM、TabICL、TabPFN、旧完整训练批次均不重跑。** source与target训练数据量不同，优化更新次数也不同；本批不把差异解释为纯样本量、容量或收敛因果。

另保留四项零拟合参照：已开诊断提出的`UDP、任一端口为443、持续时间≥30秒`规则；原HGB沿用原冻结阈值；原HGB与规则的并集；改用B正常校准的HGB与规则的并集。原后3个B单元中，该规则可补66/72且不新增原HGB误报。因此全部新学习器必须与原HGB、纯规则和原HGB并集分别逐行配对，主强参照为原HGB并集；不能只赢原本零检出的模型就称有方法价值。本轮固定30秒，不搜索规则参数。总计24个学习方案与4项固定参照；四项固定参照中的HGB判决复用source/raw8/hgb连续分数，无额外模型拟合或前向。

原HGB阈值为`0.969384090147706`，来自1826条原正常校准。已校验原包与成员SHA，记录在[冻结旧校准](../configs/support-diagnostic-20261115/legacy-hgb-calibration.json)。保留它是为了完整报告D原有1694条检出是否丢失；不能先改变旧阈值、削弱基线后再宣称保留旧能力。

## 阈值、判读与停止条件

全部24个学习方案使用同一5511条历史正常记录，各自按原严格序位规则登记1%阈值，评分严格大于阈值才告警。模型和阈值在进入B后续3单元前固定；D全12单元直接沿用。source/raw8也重新用同一B正常池校准，用于同校准下的训练机制比较；另外完整保留原阈值HGB及其规则并集作为部署能力参照，两种用途分列。

每单元及其UTC日分别报告正常分母、FP与整数预算、控制TP/FN、逐类新增/丢失、双方是否合规、同服务正常误报和实际成本。无扫描/下载正例标为没有支持，不计成功。失效或无有限阈值不能用零告警取得资格。事后正常排序上界单独标诊断，不生成部署阈值。

- target在合规单元优于source：说明在这项任务上目标历史监督有价值；不能据此声称新算法或全来源普遍可训练。
- mixed不优于同标签的target，或引入额外误报/漏检：不继续声称这项加权方案有源知识增量，也不据此启动教师蒸馏。
- raw8收益在双端口置零后消失：保留端口依赖解释；不能称已学到可迁移的控制语义。置零后仍有效，也不等于其他来源代理全部排除。
- 三种支持都失败：先用固定分数上界区分排序与校准问题；没有新机制证据，不追加宽度、轮数、种子或历史特征。
- 本地B有效而D失败：分别报告有历史监督的同profile能力和冻结迁移失败，不用B成功抵销D失败。

本批不预设必须获胜的方案。结果需按全部种子、全部单元报告；不以总体平均掩盖超标单元，不用净增覆盖新增漏检。

## 实验室运行

在独立checkout使用发布标签`support-diagnostic-lab-v1`，继续使用已有route-core环境，无新增基础模型权重或许可准备。

```powershell
git fetch origin --tags
git worktree add ..\tracelight-support-diagnostic support-diagnostic-lab-v1
Set-Location ..\tracelight-support-diagnostic
.\scripts\RUN_SUPPORT_DIAGNOSTIC.ps1
```

脚本在同级项目中寻找并校验4份旧raw模型；找不到时显式指定保留的R22/R23运行目录。只有已验证的同SHA模型会被复用：

```powershell
.\scripts\RUN_SUPPORT_DIAGNOSTIC.ps1 -ReferenceRun 'D:\实际旧项目\local\response-r23'
```

既有原始文件可离线复用：`CTU-IoT-Malware-Capture-1-1.conn.log.labeled.gz`、`CTU-IoT-Malware-Capture-8-1.conn.log.labeled.gz`、`TQH-C2_labels_v110.zip`、`TQH-C2_labels_D.zip`。传入它们所在的同一目录：

```powershell
.\scripts\RUN_SUPPORT_DIAGNOSTIC.ps1 -ReferenceRun 'D:\实际旧项目\local\response-r23' -RawDir 'D:\实际原始缓存目录'
```

不指定RawDir时先寻找同级项目保留的完整缓存；未找到才准备上述固定输入，不下载SFC/DEDALE大包。四个原始文件全部校验通过后才启动正式任务。可分别执行`-PlanOnly`、`-CheckOnly`、`-PreflightOnly`；正式运行自身也先核环境、旧权重和输入。预检没有拟合。`-Python`可指向已有环境，勿在系统Python上另装一套库。

CPU独立拟合与GPU拟合分池并发，默认两CPU作业、两GPU作业；原始解析采用多进程。线程受逻辑核预算约束，实际设备前向探针、CPU线程、GPU显存、阶段时间和利用率写入回传。共享资源下的训练吞吐不是独占部署时延，不据此宣称最终提速。

默认输出为`local/support-diagnostic-r26`。逐阶段保存回执；中断后执行同一命令复用完成项，失败保留记录并封包。不得在同一输出目录更换协议或参数后覆盖旧结果。

完成后回传本轮ZIP及SHA文件。包中包含模型、逐单元效果、配对、仅诊断的上界、完整连续分数与紧凑八字段复核数据、校准分数、训练身份和资源记录；不重复打包原始日志。不要删除该输出的本地分数和回执，直到结果复核结束。

## 独立确认仍缺什么

IoT-23未发现项目评分记录的9个恶意采集均没有FileDownload；含下载的7场均已打开。SFC换传感器没有增加独立攻击事件；DEDALE D15之后延续同一攻击链。需要另一个有明确作者动作/网络证据的下载或控制链、同环境正常下载/控制业务、部署前可用的监督以及独立后续评价。当前不为凑齐三类目标使用同链随机切分。
