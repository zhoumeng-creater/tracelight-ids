**真实可观察的量是什么**

固定一个共同查询截止时刻 τ，所有表示只能使用此前已捕获的记录。每条 TCP 记录至少保留：连接方向、时间戳、SEQ、ACK、SYN/FIN/ACK 标志、IP 声明长度、TCP 头长度、实际捕获长度。方向由连接证据确定，不能用攻击标签反推。端点身份可用于关联和分组，不能变成特征捷径。

SEQ 按每方向独立展开；SYN/FIN 消耗序列号但不算应用负载。令第 i 个包声明的负载区间为 `I_i=[seq_i, seq_i+payload_len_i)`，此前已见同方向区间并集为 `U_d`。它带来的新字节是 `J_i=I_i\U_d`。后续相同区间重传不重新增加字节；部分重叠只计新增部分。记录这些新字节首次被观察时，该数据包携带的对向 ACK 前沿 `a_i`。

`ACK=a_i` 表示该发送端声明已连续收到对向序号小于 `a_i` 的字节。它不证明应用读过这些字节，不证明执行了命令，也不能从两个 TCP 连接之间推出控制—下载触发关系。丢失首次发送时，首次观察可能实际是重传；此时保留的 ACK 是本次观察的属性，不是这些字节最初生成时的状态。

同一时刻双方都有数据时，不按抓包先后强行配成请求—响应。只有明确覆盖相关字节的 ACK 支持一条传输层确认关系。UDP/QUIC 没有这里定义的 TCP 确认关系，应单列可用性；不能仿照相邻反向包给它补上“确认”语义。

缺 SYN、SEQ 回绕无法消歧、捕获孔洞、声明长度与捕获长度不一致、卸载聚合，以及重复区间，都属于输入事实。捕获文件记录完整不等于网络无丢包。必须保留这些条件，不能用补零把未知变成无数据。元数据可完整读取而负载被 snaplen 截断时，声明序列区间与实际捕获负载要分别统计。

**一个不需要拟合的判别依据核对**

在截止 τ 的双向已见字节并集 `U_+、U_-` 中，对每段新字节 `J_i` 计算：

```
w_i = |J_i|
c_i = |U_opposite ∩ (-∞, a_i)|
K = (Σ_i w_i c_i) / (|U_+| |U_-|)
```

分母为零时 K 未定义。`c_i` 只对截止 τ 已见的对向字节求交，不能用 τ 以后才出现的字节补齐。在线仅对当时已见集合计算的版本与此回看截止版本不是同一个量，结果表中必须区分。

K 度量双向字节对中有多少得到数据包携带 ACK 的支持。它只是机制筛查量，不是恶意分数，也不是新算法。在完整首次传输可识别的理想条件下，每个双向字节对至多有一个方向的接收先后关系；首见为重传或序列参考不明时，这个解释可以失效。出现 K>1 时应检查这类观察条件，不能截成 1 后宣布识别了并发关系。

本轮已经取得真实反例：普通下载和恶意下载共享两阶段确认拓扑，控制与同期正常业务的 K 均接近饱和。它足以停止“确认充分说明恶意”或“ACK 拓扑本身识别下载意图”的主张。它没有检验所有时间、字节量、头字段表示，不能扩展成“所有包方法失败”。

只有流标签而无命令标签时，不能把每个方向切换当成一条控制命令；一个正常下载动作也不能把整条持久连接变为正常。OpTC 若只有连接与 HTTP/FUID 日志，无法构造 TCP 包内确认关系，不应通过插值补造包序。

**哪些不变性成立，哪些不成立**

| 变换 | 唯一字节区间及 ACK 关系能保证什么 | 不能保证什么 |
|---|---|---|
| 同 ACK、同方向、连续区间被拆成多个包或合成一个包 | 区间并集和按字节质量计算的关系不变 | 按包个数、包均值、每包 softmax 归一化通常改变；不能据此声称恢复应用写调用 |
| 在首见以后加入完全重复的重传 | 不新增唯一字节，不覆盖首见 ACK 属性 | 丢失原包、只看到后续重传不属于这项不变性 |
| 插入纯 ACK | 它不产生负载区间，不凭空新增数据交互 | ACK 调度改变后续数据包的 ACK 值时，表示仍可能改变 |
| 调整未形成相互确认的数据包的捕获排列 | 以区间及 ACK 定义的关系不必跟随这个排列改变 | 时间特征、原始包序模型会改变；传输延迟并非总是无关噪声 |
| 同 ACK 连续区间按长度加权聚合 | 可避免把一个大包拆成多个小包后重复投票 | 普通加权池化是已有操作，不足以构成算法创新 |
| 删除包、改变 ACK 策略、HTTP/2 多路复用或改变抓包点 | 可记录观察差异与缺失 | 不能保证所见字节或确认前沿仍相同，更不能保证应用交互不变 |

这些性质只对给定变换成立。不能用随机打乱真实包或任意改时间构造一个“正常业务不变”的大范围增强规则。

**已提出但未建立需求的压缩问题**

按字节加权的 ACK 前缀消息，可以写成“同 ACK 合段 + 对向前缀加权聚合”；普通可加统计还可用前缀和计算。若提出的层只做这件事，它与强简单实现等价。唯一字节去重也是正常的 TCP 处理工作。两者都可改善输入质量，但不应再命名为一个原创神经机制。

本轮曾提出“固定状态预算下，保留未来 ACK 查询所需关系”的候选问题。真实段数和项目要求不支持把它列为后续主线：用户没有给出硬预算，目标控制连接只有 3—11 段，普通合段已经完整保留其中大部分连接的首见数据字节 ACK 前缀映射。把预算人为压到更少段，再让新模型击败受限摘要，会制造一个当前任务并未要求的问题。

累计确认字节量、确认前沿所在区间、对向条件表示是不同查询。前两项可用简单数据结构回答；关于第三项的表达与误差推导可以作为数学研究记录，不能凭推导存在就声称当前真实数据需要学习式压缩。本轮不登记压缩训练、不确定新的小状态上限，也不扫描合并策略。

**同信息、同预算的最小对照应如何解释**

下面只保留解释未来包方法时所需的比较口径；本轮结果不支持据此安排新实验矩阵。

| 对照 | 所回答的问题 | 公平性要求 |
|---|---|---|
| 既定 HGB 强简单基线，增加同一包前缀可计算的统计 | 新信息本身能提供多少价值 | 先明确这是信息升级；它不证明新机制 |
| 唯一字节/ACK/方向段统计或固定前缀摘要 + 相同分类头 | 学习式关系是否胜过同信息简单摘要 | 同去重规则、缺失标记、查询时刻、特征缩放与模型选择依据 |
| 按原始包构造的 FG-SAT 机制，以及规范化后同类型编码器 | 收益来自构图、去重，还是提出的压缩机制 | 相同允许字段；若屏蔽原论文头字段，称任务适配版，不冒充完整作者复现 |
| 若未来另有真实成本瓶颈，才考虑均匀合并/固定桶等压缩参照 | 压缩是否解决已经观察到的成本问题 | 当前 3—11 段控制材料不构成这个瓶颈；不得人为制造硬预算 |

不必同时训练所有论文。FastFlow 的等待决策、C2Detector 的完整相邻块网络和 FSG-NID 的头字节网络只在它们对应的问题进入主张时才成为必要模型对照。来源正文或代码缺失的模型，不宜先用近似实现填满实验表。

方法间公平口径是**共同原始包集合、共同截止时刻**，再完整报告计算与状态成本。在每条连接上，各方法均读取相同前 20 条记录时，比较仍然公平；AIT 与 Unraveled 的字节覆盖比例不同是该观察条件的特性。若候选按字节或 ACK 段等到更晚、读取更多包，而对照停在原始第 20 包，就不能称同信息比较。自适应停止是另一个已有近邻的问题，必须同时报告等待时间与误报，不能用覆盖比例单独证明新算法价值。

精确区间并集在一般情况下需要随区间数量增长的状态；排序集合实现通常涉及插入与求交成本。没有上界证明时，不宣称常数内存。模型成本之外要计 TCP 解析、去重、SEQ 展开、连接表、未确认区间、图构造或压缩、查询耗时以及实际等待时间。正式资源测量仍在实验室 RTX4090D 完成。
