# 第二阶段：字段预算的受控开发比较

日期：2026-11-01。状态：本轮运行前的比较约定；本文未执行训练、校准或最终测试。

**已接收的基线结果可以作为开发基线使用。** 12 次真实数据基线及其工件已核验，现有结果不需要被判定为失败。这一轮用于回答新的研究问题：在训练规则保持一致时，减少输入字段能否保留检测能力，并带来可测量的存储或 CPU 推理收益。

本文依据实验归档中的《接收核验说明.txt》，以及当前 `models.py`、`runner.py`、`evaluation.py`、`benchmark.py`、[数据协议](DATA.md)和[评估协议](PROTOCOL.md)编写。既有初筛已被查看，因此不能称为盲选、预注册或独立确认研究；只能说明本轮规则在本轮运行前落盘。未来修改规则须保留版本、时间和原因，不得倒写成事前约定。

## 1. 本轮回答什么

研究问题：在 UNSW-NB15 当前固定分区上，RF、HGB、MLP 各自在 42、24、16、8 个原始字段预算下，验证集检测效果与 CPU 部署代价如何变化？

主要比较单位是“同模型、同 seed、精简字段”对“同模型、同 seed、42 字段”。不同模型的绝对结果可以并列展示，但不把算法差异归因于字段数量。当前仅支持从既有 CSV 特征开始的处理和推理，字段减少不等于已经降低了抓包或流特征提取成本。

若精简方案没有满足筛选条件，保留 42 字段基线就是有效结果。体积减半、Fuzzers 保护条件及任何精简方案胜出，都不是毕业设计必须通过的指标。本轮完成也不能单独证明整个毕业设计已经完成。

## 2. 固定实验矩阵

模型 3 种 × 字段方案 4 种 × seeds 3 个，共 **36 个训练工件**。

| 项目 | 本轮固定值 |
|---|---|
| 模型 | RF、HGB、MLP |
| 字段方案 | `all`（42 个）、`mutual_info` 的 k=8、16、24 |
| seeds | 17、29、43；必须全部报告，不挑最好 seed |
| 数据 | 同一 prepared 清单及相同四分区哈希；不重新划分 |
| RF | 200 棵树、max_depth=16、min_samples_leaf=2；class_weight=balanced；其余有效参数固定 |
| HGB | max_iter=200、max_leaf_nodes=31、learning_rate=0.1、early_stopping=False；固定训练内 balanced sample weights |
| MLP | hidden_sizes=[64,32]；epochs 上限 60；patience=8；batch_size=1024；learning_rate=0.001；weight_decay=0.0001；min_delta=0.00001；固定现有二分类损失与训练内权重算法 |
| 训练资源 | 全部候选训练 threads=4；RF/HGB 用 CPU，MLP 使用所指定的同一设备；记录实际设备 |
| 效果操作点 | validation 正常记录上的经验 FPR 预算 0.01；每个工件独立产生开发阈值 |
| 效率条件 | 所有 36 个工件在同一机器 CPU、threads=1 下重测 |

先写入并保存完整配置、源码指纹、依赖版本、数据清单、协议副本及其 SHA-256，再开始这一轮。保存 estimator 的有效参数或足以重建其默认值的锁定版本；配置里未写出的默认值仍属于方法的一部分。已有全字段工件只有在源码、数据、有效参数、种子与环境完全匹配并明确记录复用时才可复用；默认按本轮完整矩阵执行，避免混入旧 RF100 或 MLP40 的初筛结果。

已实现的统一入口使用 `configs/controlled-features.yaml`。按 [STAGE2_LAB.md](STAGE2_LAB.md) 设置 `prepared` 和 `stage2` 目录后执行：

```powershell
python scripts/run_lab.py --data-dir $prepared --work-dir $stage2 --config configs/controlled-features.yaml --with-study --device cuda
```

入口依次完成 doctor、suite、report、benchmark-suite、study；目前自动执行 **1 个完整 CPU 测量轮次**，并不自动执行后文建议的额外轮次。`--device cuda` 指定本次实际机器的 GPU，不能把本机结果标成此前实验室 RTX 4090D 的测量。

MLP 固定的是早停规则和 epoch 上限，实际训练轮数可以不同；逐 run 保存 best_epoch、实际 epochs 和历史。RF 的 `max_features='sqrt'` 是固定规则，但编码维度减少时每次分裂的候选字段数也随之变化；MLP 首层参数量也会变化。因此本轮结论是“固定训练规则下的字段预算效果”，不声称完全固定有效模型容量。

## 3. 特征选择与数据边界

MI 排名、缺失值填补、编码词表、标准化及模型拟合只使用 train。validation 用于早停、开发阈值和候选选择，不能再称为独立确认集。calibration 与 test 保持封存，本轮命令不得执行 `freeze` 后的最终 `evaluate` 流程。

MI 的 k 指原始字段数，不是独热编码后的列数。每个 run 同时报原始字段数、encoded_dim、所选字段清单；同一 seed 的三种模型应得到相同 MI 排名和字段集合，且 MI8 ⊆ MI16 ⊆ MI24。当前实现对三种类别字段使用离散 MI，对其余数值字段使用连续估计；包括计数和二值数值字段在内都按这个固定实现处理。它是可复现的筛选器，不是因果重要性判断。本轮不临时切换估计方式或挑选“更好看”的排名。

保存三个 seed 间的集合交集、Jaccard 相似度或逐字段入选频次，用于描述选择稳定性。现有 seed 同时影响 MI 的随机扰动和模型训练；三个 seed 的变化不能全部解释为纯粹的模型初始化差异。不得在看过 validation 后更换 MI seed。

完整 42 字段的精确重复组在 train/validation/calibration 之间已经隔离。减少字段可能让原本不同的记录映射为相同输入，这属于信息压缩后的表示冲突；如做诊断，应保持现有分区并报告冲突，不能为每个字段预算重新划分或静默删行。

## 4. 阈值和效果指标

每个 run 使用 validation 中的正常样本选择阈值。允许的误报数为 `floor(0.01 × n_normal)`，沿用现有 `float64(score) >= threshold` 及并列分数处理规则。保存实际 FP、正常分母、阈值与实际 FPR；并列分数可能使实际 FPR 小于 1%，不能偷偷放宽阈值补齐预算。

这只说明开发集上满足经验预算；不是对未来流量或最终 test 的误报保证。攻击分数也不自动具有经过概率校准的含义。

每个 run 输出 TN、FP、FN、TP、attack recall、normal FPR、precision、二分类 Macro-F1、AP、ROC-AUC，以及每个攻击家族的样本数与“被检测为任意攻击”的比例。家族召回不是正确识别攻击家族的分类准确率。

三种子汇总给出每个 seed 的原值、均值、样本标准差、最小值和最大值。精简方案的主要差值先在同 seed 内计算，再跨三个 seed 求均值；不能用两个不相同 seed 集合的均值相减。三个 seed 是随机性描述，不是三份独立测试数据，更不能仅凭均值差小于 2 个百分点就宣称统计学非劣效。

## 5. 候选筛选的操作定义

以下数值是本项目本轮运行前选择的实用筛选尺度，不来自论文中的普遍标准。它们用于给候选分层，不用于倒推已有结果“合格或失败”。

令 R(m,k,s) 为模型 m、字段数 k、seed s 在各自开发阈值下的攻击召回；令 F 为相同条件下的 Fuzzers 召回。每个精简配置的三个 seed 作为一个整体评审。

| 层级 | 运行前约定 |
|---|---|
| 工件可用 | 三个 seed 均成功且可校验；数据/参数符合矩阵；阈值规则正确；效果与 CPU 数据齐全 |
| 检测保留候选 | 平均配对差 `mean_s[R(m,k,s)-R(m,42,s)] >= -0.02`，且每个 run 的 validation FPR 满足上述经验预算 |
| 家族保护标记 | 平均配对差 `mean_s[F(m,k,s)-F(m,42,s)] >= -0.03`；不满足者仍报告，可称总体召回保留但 Fuzzers 退化，不优先作为默认演示模型 |
| 体积挑战目标 | 平均配对 `model.joblib` 字节数比值 <= 0.50；没有达到就如实写未达到，不改成“字段减半”等替代指标 |

Fuzzers 是已有验证结果发现的重点，所以家族保护条件属于有依据的开发关注点，不能伪装成没有看过数据的研究假设。还必须公开全部家族结果，避免只改善 Fuzzers 却隐藏其他家族损失。小样本家族给出检出数/总数，不能按一两条记录的变化下稳定结论。

候选选择顺序固定如下：

1. 先保留工件可用且满足检测保留条件的配置；家族保护标记作为默认推荐条件。每个不通过的配置仍留在完整表格中。
2. 在每种模型内部，把这些精简配置与 42 字段基线共同放入 recall、部署包字节数、CPU 单条 p95 的 Pareto 图。当前只有一轮效率测量，图用于描述本机本轮取舍，时间不作为硬筛选条件，也不因很小的计时差异淘汰候选。
3. 每种模型最多保留一个满足两项效果条件的精简候选：先选三种子平均部署包字节数最小者；相差不超过 1% 时，选平均 recall 较高者；仍相同则按 k 从小到大确定。该顺序服务于本轮存储优先的候选缩减，不宣称具有唯一最优意义。CPU 结果随候选一并展示，不参与此轮硬筛选。
4. 同时保留对应模型的 42 字段基线作为对照。若某模型没有入围精简配置，保留其基线，不继续为了“必须胜出”而增加 k、seed 或阈值搜索。
5. 只有实际体积或效率体现出优势，才称其在相应维度更轻或更快；仅减少字段可称输入预算更低。延迟优势若与重复测量波动相当，则写“本轮未区分出稳定速度差异”。50% 体积挑战是否达成单独打标，不充当其他证据的替代。

至多形成 3 个精简配置及其配对基线。该列表仍是开发候选，不自动触发最终测试。若需要一个开发演示实例，使用选定配置的 seed 17，展示时说明这是固定实例；论文汇总保留全部三个 seed。最终冻结前应把配置和 seed 列表一次性写明，不能以后根据 test 再挑幸运 seed。

## 6. Fuzzers 与模型互补诊断

归档核验指出：旧 seed 17 的四个模型共同漏检 1695 条，其中 Fuzzers 为 1489/2727。这个事实值得分析，但不等于每个模型的 Fuzzers 召回都是同一个数，也不证明必须增加复杂模型。

本轮用稳定 sample_id 对齐各 run，报告 Fuzzers 的检出数、召回、阈值附近分数和字段预算变化后的错对转移。原始类别标签只作监督信息或诊断，不能进入推理输入。若抽取案例，按固定规则抽取：每种错误类型按 sample_id 排序取前若干条，并提供完整可检索列表；不把精选案例当作分布结论。

若报告某模型“唯一检出”，集合定义必须是“该模型检出，其他参照模型全部漏检”，不能使用“该模型检出数减去所有模型共同检出数”。多个模型告警取并集属于新的决策系统，会改变正常误报率；不能因为组成模型各自为 1% 就把并集也写成 1%。本轮不自动增加集成或路由器。

## 7. CPU 效率重测

36 个已训练工件全部在同一台机器重测，而不只测胜出候选。先停止训练和其他竞争任务，保持相同电源模式、软件环境、CPU 线程设置和输入行；记录机器、操作系统、CPU、库版本、运行时间、run_id、模型哈希和测量顺序。不要将旧实验室机器、当前本机或不同线程数的绝对延迟混为一张排名表。

本轮统一 CPU threads=1，RF n_jobs=1，MLP torch 线程数=1，BLAS/OpenMP 同样限制为 1。GPU 可参与训练，但本轮部署性能比较在 CPU 上完成。线程配置在计时区间之外设置。

沿用现有 benchmark：每种模式预热 5 次；单条模式使用同一 validation 上均匀抽取的 100 个固定行，各测 30 轮，共 3000 次计时；另以固定的 256 行 batch 测 30 次。所有候选使用相同 row_indices 和批次，保留原始延迟、分块中位数、单条 p50/p95、批量吞吐。吞吐不能换算为真实单请求延迟；3000 次计时也不是 3000 条独立流量样本。

当前执行 **1 个完整测量轮次**，用调度 seed 20261101 产生并保存 36 个工件的测量顺序，避免永远先测全字段、最后测最小模型。结果称为本机本轮的探索测量，报告三个训练 seed 的单条 p95 与批量吞吐，不把全部计时观察值当成大量独立模型，也不据此宣称稳定或显著速度优势。

只有需要主张稳定速度优势时，才预先约定并补足 3 个完整测量轮次，每轮包含全部 36 个工件、分别保存顺序和结果目录；以每个工件三轮 p95 的中位数及范围描述重复性，再汇总训练 seed。当前 study 入口并未自动汇总多个测量轮次，届时需单独完成这一分析。补测适用于整组，不能只重测较慢的一方直到满意。这是后续可选强化，不是本轮完成的附加门槛。

范围严格标为“预处理 + 模型预测”：不含 CSV 解析、DataFrame 切片、模型载入、特征提取、网络传输或界面渲染。`model.joblib` 大小包含模型、预处理器及随包元数据，是部署工件大小，不是纯权重内存。RSS 前后快照不是峰值内存。字段预算、编码维度、工件字节数、单条延迟和批量吞吐分别报告，不用其中一项替代其他项。

## 8. 重复、时间与泛化限制

目前源文件训练/测试之间有 1302 个相同完整特征组，涉及训练源 10279 条、测试源 8541 条。当前内部按精确特征组隔离有效，但不能消除官方兼容测试源的重叠。数据来自固定公开镜像，尚未与独立官方副本逐字节核对；继续保留这一来源说明。

本轮不需要为排除重复而重做基线。未来最终评估前可约定同时报告完整 test，以及“与整个原训练源无完整特征重叠”的 test 子集；子集规则只依赖特征哈希，不依赖 test 标签或分数。先冻结规则再开 test，完整结果与敏感性子集均保留，不把后者包装成新的无偏独立数据集。

精确重复组不等于会话组，去除精确重叠也不消除近重复或采集环境线索。没有可靠会话和时间元数据时，不把 CSV 行号、sample_id 或随机拆分称为时间外推；不为了使用 LSTM/Transformer 而把无时间依据的相邻行拼成序列。另一个数据集上独立重训验证属于复现或跨数据集重复实验，只有保持模型与特征语义一致的跨域测试才能支持相应迁移主张。

## 9. 有必要时才做的一条后续改进

**可选方向：现有全字段 HGB 向小 MLP 蒸馏。** 只有在本轮表明精简后有明确资源收益但检测能力损失需要恢复，或课程/论文需要一个有清晰消融的压缩研究问题时才开展。现有候选已满足实际需求时，可以直接推进独立评估和展示，无需为创新感堆叠大模型。

限定一个字段预算与一种学生结构：预算由本轮 validation 规则确定，学生固定为 [32,16]。仅比较同结构、同字段、同训练规则的“硬标签学生”和“硬标签 + 教师软标签学生”，均使用 seeds 17/29/43；全字段 HGB 作为教师参考。不要把学生结构缩小与蒸馏同时改变却缺少同结构硬标签对照。

教师只用 train。更稳妥的软目标生成方式是在 train 内按完整 feature_hash 做 3 折分组交叉拟合，每折重新拟合该折预处理器，给该折未参与拟合的记录生成教师分数；validation 不生成训练软标签，calibration/test 不参与。折划分与权重在新增实验前固定。可以先固定软目标混合权重 0.5、温度 1，不搜索大量温度或教师组合；这是本项目的简化设计，不声称复现了下述论文的 Kronecker 结构。记录教师训练与软目标生成成本，部署时仅加载学生。

继续使用本轮低误报、Fuzzers、工件大小与 CPU 条件评审。若蒸馏不优于同结构硬标签学生，保留负结果并停止这一支线；不能打开 test 决定是否继续优化。该建议尚未实现，也不是本轮 36 个 run 的组成部分。

## 11. 阶段完成与下一步边界

本阶段完成条件是：36 个 run 及其失败/重试记录完整；36 个工件的一轮 CPU 测量覆盖齐全；一张包含全部配置和种子的配对比较表；字段清单与稳定性分析；Fuzzers 和全部家族结果；候选选择记录；数据、源码、配置与报告可追溯。速度比较明确标为本机本轮探索性测量，不提升为稳定优势结论。

只有在开发选择结束后，才单独冻结最终候选、全部 seed、阈值校准算法、评价指标及重叠敏感性规则。calibration 只确定每个已选模型实例的操作阈值；test 的 FPR 即使超过 1% 也须按原值报告，不能回头改阈值或挑模型。本协议没有启动这些操作。

可视化可以采用“字段预算—recall—单条 p95—部署体积”联动图、Fuzzers 错误迁移图和逐样本证据页，全部由真实工件生成并标为 development validation。视觉表现可以强化成果，但模型效果、部署成本、验证边界和最终完成状态仍由证据决定。
