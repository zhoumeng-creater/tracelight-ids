## 唯一主候选及必要对照

**当前采用成熟的确定性网络历史摘要加 HGB，作为唯一可落实的方法候选；尚不立关系监督的新算法。** 最小问题是：在同一动作标签、相同当前流字段、相同完整链划分与操作点规则下，历史中当时已经可用的网络记录，能否在单流 HGB 之外增加攻击动作识别，同时守住预先声明正常业务单元的1%误报预算？

只需要两个学习臂：单流 HGB；同一 HGB 加固定历史摘要。R30 已冻结的8维分数仅作旧任务参照，不新训练一个 R30，也不把赢过旧窄输入当作算法创新。IP只用作关联键，PID、进程名、路径、域名、来源名与攻击时间只进真值表，不进模型。

本轮把非训练导出规格固定为 `prefix_context_v1`，详见 [prefix_context_spec.json](<E:/OneDrive - Coventry University/中传/毕业论文/工作/统一事件与方法落实_20261119/split_method/prefix_context_spec.json>)：每个完整采集组的内网主机，只保存最近一条已可用流与8字段在线均值；输出上一流8值、均值8值、距上一流可用时刻的 `log1p` 间隔、相同对端布尔和空历史标记，共19个历史值，连同当前8字段为27维。数值先 `log1p`，缺失仍为空。没有时间窗参数，不按攻击间隔选窗。

当前8字段统一为 `ip_protocol, orig_port, resp_port, duration_seconds, orig_pkts, resp_pkts, orig_ip_bytes, resp_ip_bytes`，不使用原草案中的应用载荷字节和 `missed_bytes`，不从动作/主机真值补输入。空历史固定填0并置 `empty_history=1`；已有历史中的缺测仍为空。`flow_id` 是唯一主机视角 ID；同组内不同主机可观察同一 `physical_flow_id`，同一主机不能重复更新，物理流数与视角数分别报告。

该规格必须消费完整声明区间内的所有观测连接，不能只用已标攻击和正常的子集。相同可用时刻的记录全部先查询、后更新，跨完整采集组清空；双观测视角和多动作引用不重复更新同一模型流。每主机为固定数值状态，总内存仍随主机数增长，实际成本由导出审计记录。当前只确定摘要导出与“历史严格早于当前可用时刻”检查，不预设它能提高识别率。

纯 Python 实现见 [prefix_context.py](<E:/OneDrive - Coventry University/中传/毕业论文/工作/统一事件与方法落实_20261119/split_method/prefix_context.py>)。输入为 JSONL / JSONL.gz，至少包含 `group, host, peer, flow_id, available_at, raw8`；`host` 必须是明确受监控主机，不能一律取源 IP。实际可用时间为空时，显式选择 `--time-mode offline_flow_end_replay`，并为每条记录提供 `flow_end_at`；该模式统一使用结束时间，输出不声称实际在线可用。示例 CLI：`python prefix_context.py context_inputs.jsonl.gz context_rows.jsonl.gz --audit context_audit.json --time-mode offline_flow_end_replay`。批量实现需要排序和保存输出，整体内存为 O(N)，只有上下文状态是每主机常数规模。

缺少所需时钟时默认报错。显式加 `--unavailable-policy block-group` 可阻断整个受影响组，同时继续处理其他完整组；审计保留整组全部视角 ID、排除数量、原因及缺时钟原行，不会删去少数行后冒称完整。无效的非空时钟仍报错，不自动修补。

若以后比较另一种窗口/容量，必须另给资源或成熟方法依据，不能在这次导出中扫描。已有 OpTC 开发链的最后已证控制与下载约隔16分钟；这说明随手取5分钟没有覆盖依据，但不能反向据攻击间隔挑一个能覆盖的窗口。若只有完整流统计，历史须在实际导出后进入缓存。只有 `ts+duration` 下界而没有输出时刻时，最多评价明确写出的离线完成流重放；不能宣称真实在线早检。

当前数据支持动作/业务对象标签，并不支持“哪条命令连接导致哪次下载”的关系标签。同进程、同主机、同攻击链、相邻时间都不足以生成该监督。已明确下载后的证据只能支持该时刻之后的新判断，不能倒填为先前控制已被识别。缺少可观测差异时保留未知，不能让标签要求模型猜意图。

**当前尚未具备新的两臂训练登记。** 统一主表与声明正常分母已经完成，缺口不再笼统称为“数据还在装配”。具体限制是两次 AIT 下载的完整流输入损坏、部分动作仍多对多；TQH没有下载动作标签，DEDALE的确认等级不同；新的拟合/验证/正常校准身份尚未确定。把 OpTC 正常业务保留为不拟合、不调阈值的外源开发持出，是此前方案的选择，不是用户禁止重新分配。后续可以改分配，但必须显式替换旧角色，不能同时将同一记录用于拟合并保留原持出评价身份。

1. **按已落实的共同网络合同导出完整背景历史摘要。** 消费完整声明区间的全部观测，验证每个历史记录严格早于当前可用时刻；四条长度损坏的 AIT 候选不进入完整流特征。Meterpreter 已以0351的完整片段取得事件资格，0051控制缺口保留，不借另一台填齐。AIT 下载保留对象级事件证据，不用损坏 raw8 启动逐流训练。没有关系因果真值，不追加同 PID 伪标签。
